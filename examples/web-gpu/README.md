# Web GPU showcase

Run Bijou example apps in a browser, on a `<canvas>`, through
`mountBijouCanvas()` and Geordi's WebGPU, WebGL2 and Canvas 2D presenters.
The page has a HUD that reports what the mount and each presenter's receipt
say, and controls that switch the backend, lose the WebGL2 context, and reset
the glyph atlas.

The reference for what the page mounts, what the HUD reports and what is
verified is [the showcase topic](../../docs/topics/web-gpu-showcase/README.md).

## Run the page

From the repository root, after `npm ci --ignore-scripts` (the browser suite
is the one lane outside the sealed runner, so a plain `npm ci` would run every
dependency's lifecycle scripts on this machine; the CI job installs the same way):

```sh
npm run web-gpu
```

This starts the Vite development server on `http://127.0.0.1:5173`. Click the
Surface, then type: `+` or `k` increments the counter, `-` or `j` decrements it.
See [Keys](#keys) for the page's own keys, which never take a key from the app.

To serve the production bundle instead:

```sh
npm run web-gpu:build
npx vite preview --config examples/web-gpu/vite.config.ts --port 41797
```

`/dom.html` is the page the browser suite checks `mountBijouDom()` on.

The first mount is chosen in the address: `?app=counter`, `?app=components`,
`?app=hero` or `?app=showcase`,
and `&backend=auto` (the default), `webgpu`, `webgl2` or `canvas2d`.

## The page chrome

Everything around the two Bijou mounts is a Vite + React app built only from
shadcn components, installed with the shadcn CLI from the `@flyingrobots`
registry and the stock shadcn registry it builds on, and styled only with
shadcn's tokens. `components.json` configures the CLI.

| Where | What | Items |
| --- | --- | --- |
| `src/components/` | `@flyingrobots` registry items | `@flyingrobots/theme-provider`, `@flyingrobots/theme-switch` |
| `src/vendor/components/ui/` | stock shadcn items (radix-nova style) | `alert`, `badge`, `button`, `card`, `command`, `dialog`, `dropdown-menu`, `field`, `input`, `input-group`, `item`, `kbd`, `label`, `separator`, `skeleton`, `spinner`, `table`, `textarea`, `toggle`, `toggle-group`, `tooltip` |
| `src/chrome/`, `src/dom/dom-page.tsx` | this page's composition of those components | |

### Installed registry files

`src/vendor/` and `src/components/` hold only files the shadcn CLI installed,
unedited. They are registry code, not this repository's: Code Dojo's 150-line
file limit exempts `vendor/` directories as vendored third-party source, which
is why six stock files over 150 lines (`dropdown-menu`, `field`, `item`,
`command`, `dialog`, `input-group`) live there without baseline entries, and
ESLint lints the chrome's own `.tsx` but not these files.

`registry-files.json` records each installed file, its registry item and its
SHA-256. The sealed test
`keeps every CLI-installed file byte for byte as registry-files.json records it, and records nothing else`
fails if a file is edited, added or removed without the record. The seal is
offline, so it cannot compare against the registry itself; what ties the
record to the registry is reinstalling. To add, update or check items:

1. Serve the registry: `bun run serve` in its checkout (`http://127.0.0.1:4173`).
2. In a scratch Vite project with React, Tailwind, a `@/*` path to `./src/*`
   and a copy of this `components.json`, run
   `npx shadcn@4.23.0 add <items> -y` (the full list is in `registry-files.json`).
3. Compare the scratch project's `src/vendor/` and `src/components/` with
   these (`diff -r`), copy changed files here, update `registry-files.json`'s
   digests, and add any new npm dependency to the root `package.json`: the
   CLI's own install does not apply to this repository.

`src/index.css` is shadcn's stylesheet for this style. Its light and dark
colours were generated by theme-book, and audited at WCAG AAA, with:

```sh
theme-book theme --seed "#2171cc" --preset shadcn --mood editorial --generator oklch --standard wcag-aaa --audit
```

The seed is Bijou's sapphire brand hue (OKLCH 255). The audit reports APCA
advisories for the dark theme's muted text and primary buttons (Lc 54 to 58);
they are kept as secondary text and large controls. The theme switch offers
light, dark and system; the choice is kept in `localStorage` under
`bijou-web-gpu-theme`, and a blocked storage keeps it for the visit.

Type is one step larger at the root (`text-lg` on `html`). The layout is one
column on a phone; from `lg` the Surface takes two of three columns beside the
controls, with the HUD below; from `2xl` the Surface, the controls and the HUD
sit side by side. Skeletons stand in for the HUD and the status until the first
state is read, and a Spinner shows while an operation or a backend negotiation
runs. One GSAP timeline brings in the cards; the Surface card does not move,
and with reduced motion nothing does.

### The Bijou mounts are not chrome

`#surface` and `#dom-root` are `src/chrome/mount-host.tsx`: an empty element
React never renders into, marked `data-bijou-mount`. The canvas and textarea
`mountBijouCanvas()` adds, and the elements `mountBijouDom()` adds, are the
library's output and are not restyled: `[data-bijou-mount] * { all: revert; }`
in `src/index.css` takes back every chrome rule, Tailwind's preflight included,
so they keep their inline styles and the browser's defaults. The host itself
only takes layout classes (its size).

### Keys

The focus rule: **while focus is inside a Bijou mount, every key goes to the
mounted app, and the page does nothing with it.** That is the Surface's hidden
textarea after a click on the canvas, or any element `mountBijouDom()` made.
The page's keys work only while focus is in the chrome, and not while the
palette or a menu is open. `src/chrome/keys.ts` holds the rule.

| Keys | Effect |
| --- | --- |
| `Esc`, or `Space` `Space` | Open the command palette: every control, both pages and the three themes. |
| `j` `k`, `↓` `↑` | Move focus through the controls. |
| `h` `l`, `←` `→` | Move focus to the previous or next region. Inside a toggle group the arrows move between its items. |
| `Space` `s` | Focus the Surface, so the next keys go to the app. |
| `Space` `g`, `Space` `d` | Open the GPU showcase or the DOM check page. |
| `Space` `t` | Open the theme menu. |

The Keys card on each page shows them with `Kbd`.

This key layer, the header and the palette live in the showcase rather than in
the registry's `@flyingrobots/app-shell` block. That is a recorded departure
from the web style, which puts new behaviour in the registry: `app-shell`
cannot yet host an embedded app (its 700-line sidebar dependency, its Space
leader taking Space from a focused Bijou button, no palette on `Esc`, and a
palette that cannot be opened from outside). flyingrobots/shadcn-registry#18
proposes an option for each, and flyingrobots/bijou#817 switches the showcase
to `app-shell` once they land.

### What does not apply here

The page has no server, no data store and no login: it is a static bundle that
the browser suite serves on `127.0.0.1`. Postgres functions, PGlite, GraphQL
SDL and Zod at a server boundary have nothing to hold, so the page has none.

### Bundle size

`npm run web-gpu:build` writes 1,125,245 bytes of JavaScript, CSS and HTML
(344,538 bytes at gzip level 9) and 76,420 bytes of Geist font files. The
canvas page's first paint loads 851,537 bytes of it (256,456 gzip); the
command palette, its dialog and cmdk (23,684 bytes) load on first use, and each
example app loads when it is mounted. React, Radix and the shadcn components
share one chunk with the Bijou packages, and Vite warns that it is over 500 kB;
flyingrobots/bijou#818 tracks splitting it.

## Run the browser suite

The suite needs Google Chrome installed. It builds the bundle, serves it on
port 41797, and drives it with Playwright:

```sh
npm run test:browser:web-gpu
```

| Variable | Default | Effect |
| --- | --- | --- |
| `BIJOU_WEB_GPU_PORT` | `41797` | The port the bundle is served on. Use a free one when another worktree runs the suite. |
| `BIJOU_WEB_GPU_BROWSER_CHANNEL` | `chrome` | `chromium` uses the browser that `npx playwright install chromium` downloads. |

Each test prints a `web-gpu-evidence` line naming the backend, the adapter and
the receipt's evidence level. Failures leave traces in `test-results/web-gpu/`.

This suite is the one test lane that runs outside the
[sealed runner](../../docs/guides/sealed-tests.md): the sealed workers have no
browser and no GPU. The sealed gate (`npm run code-dojo:ci`) still builds and
typechecks the page (`npm run web-gpu:build`, `npm run web-gpu:typecheck`) and
runs the tests in `tests/web-gpu/`.

## Refresh the pinned Geordi packages

`@flyingrobots/geordi-core` and `@flyingrobots/geordi-bijou-gpu` are not on
npm. The page uses tarballs packed from one Geordi commit, in `vendor/`, and
records the commit and every SHA-256 in `geordi-pin.json`. The tarballs are the
only vendored files. To move the pin, in a clean Geordi checkout at the new
commit (`<bijou>` stands for this repository's root; the commands are
illustrative):

```sh
pnpm install --frozen-lockfile
pnpm --filter @flyingrobots/geordi-core build
pnpm --filter @flyingrobots/geordi-bijou-gpu build
pnpm --filter @flyingrobots/geordi-core pack --pack-destination <bijou>/examples/web-gpu/vendor
pnpm --filter @flyingrobots/geordi-bijou-gpu pack --pack-destination <bijou>/examples/web-gpu/vendor
```

Pack twice, to two directories, and compare `shasum -a 256`: the digests must
match. `pnpm pack` names each tarball after the package version, so a new
version gives new file names; an unchanged version overwrites the old file
under the same name. Then, in Bijou:

1. Delete any old tarball whose name changed from `vendor/`.
2. In `geordi-pin.json`, set the commit, and each package's `version`,
   `tarball` and `sha256` (from `shasum -a 256`).
3. In the root `package.json`, point the `@flyingrobots/geordi-core` and
   `@flyingrobots/geordi-bijou-gpu` development dependencies at the new
   `file:examples/web-gpu/vendor/<name>-<version>.tgz` paths.
4. In `package-lock.json`, set each package's `version`, `resolved` and
   `integrity`. Run `npm install --package-lock-only --ignore-scripts` to
   update `version`, `resolved` and the package's `dependencies` after a
   version change. It does **not** refresh `integrity` for a `file:` tarball,
   and it leaves the old value when the file name is unchanged, so set
   `integrity` yourself to `sha512-` plus the base64 of
   `openssl dgst -sha512 -binary <tarball>`.
5. Run `npm ci --ignore-scripts`, which fails on an integrity mismatch, then
   `npm run web-gpu:typecheck` and the browser suite.

`tests/web-gpu/geordi-pin.test.ts` recomputes every digest, checks that the
manifest, the lockfile and the pin agree, and that `vendor/` holds nothing but
the two tarballs. `.gitattributes` keeps the tarballs byte-exact on a checkout
that converts line endings.
