# Philosophie et architecture

Bijou n’est pas seulement un catalogue de composants. Le dépôt adopte un parti
pris de conception explicite sur la vérité du runtime, l’honnêteté du shell, la
portabilité et le rôle de la documentation comme surface de mise à l’épreuve.

## Thèmes centraux

- la vérité du runtime l’emporte sur les contrats disparus
- les API propres à un hôte doivent se trouver derrière des adaptateurs
- la documentation doit mettre en œuvre le vrai framework
- l’habillage du shell doit enseigner plutôt qu’obscurcir

## Références de conception préservées

- `System-Style JavaScript`
- `Architecture`
- `Bijou UX Doctrine`
- `Invariants`
- `Design System Overview`

Ces articles sont des sources d’archive historiques, signalées comme telles dans le lecteur. La
politique d’ingénierie en vigueur se trouve dans `AGENTS.md` et `docs/typescript-code-standards.editors-edition.md`.
Consultez **Latest Features** et les README des paquets pour le comportement actuel ; l’accès aux archives
préserve des preuves plutôt que de mettre à jour chaque ancienne affirmation de conception.

## Comment utiliser cette section

- commencez par cette vue d’ensemble si vous voulez le cadre global
- ouvrez `System-Style JavaScript` pour la posture d’ingénierie fondée sur la vérité du runtime
- ouvrez `Architecture` pour la structure des paquets et des frontières
- ouvrez `Bijou UX Doctrine` et `Design System Overview` pour la posture produit
  et interface
- ouvrez `Invariants` lorsque vous devez voir les vérités du dépôt que les légendes
  protègent
