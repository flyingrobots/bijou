# Filosofía y arquitectura

Bijou no es solo un catálogo de componentes. El repositorio tiene una postura
de diseño explícita sobre la verdad del runtime, la honestidad del shell, la
portabilidad y el papel de la documentación como superficie de prueba.

## Temas centrales

- la verdad del runtime prevalece sobre los contratos desaparecidos
- las API específicas del host van detrás de adaptadores
- la documentación debe ejercitar el framework real
- el chrome del shell debe enseñar en lugar de ocultar

## Referencias de diseño preservadas

- `System-Style JavaScript`
- `Architecture`
- `Bijou UX Doctrine`
- `Invariants`
- `Design System Overview`

Estos artículos son fuentes de archivo histórico, marcadas como tales en el lector. La
política de ingeniería vigente está en `AGENTS.md` y `docs/typescript-code-standards.editors-edition.md`.
Consulta **Latest Features** y los README de los paquetes para el comportamiento actual; el acceso
al archivo preserva evidencias en lugar de actualizar cada afirmación de diseño antigua.

## Cómo usar esta sección

- empieza por esta visión general si quieres el marco global
- abre `System-Style JavaScript` para la postura de ingeniería basada en la verdad del runtime
- abre `Architecture` para la estructura de paquetes y límites
- abre `Bijou UX Doctrine` y `Design System Overview` para la postura de producto
  e interfaz
- abre `Invariants` cuando necesites ver las verdades del repositorio que protegen
  las leyendas
