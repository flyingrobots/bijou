# Bijou Workflow

GitHub [issues](https://github.com/flyingrobots/bijou/issues) and
[milestones](https://github.com/flyingrobots/bijou/milestones) own the roadmap
and release scope. The next release is
[stable v8.0.0](https://github.com/flyingrobots/bijou/milestone/6), following
`v8.0.0-rc.1`.

Linear is the chosen execution tracker. Connection and workspace/team selection
are still pending. Existing GitHub issues remain live until their Linear
counterparts are created, linked, and verified. Do not duplicate execution state
in repository backlog files or invent a completed migration.

## Working Loop

1. Inspect the work item, linked PRs, and current Git state.
2. Sync the merge target and create a descriptive branch without disturbing
   unrelated local work.
3. Define one observable outcome, scope, acceptance checks, and real prerequisites.
4. Implement with relevant regression evidence. Use a design record when the
   change needs a durable technical decision.
5. Update affected documentation and the changelog, run the relevant checks,
   and review the diff.
6. Link the work item and PR. Request review when the change is ready.
7. After merge, retain the integration link and update the external tracker.

Use focused conventional commits. Do not amend, rebase, force-push, or push to
`main` without explicit authorization. There is no mandatory cycle ceremony,
advance shaping commit, sponsor taxonomy, or retrospective template.

## GitHub Comment Safety

Structured review comments often contain Markdown tables, code spans, shell
examples, `$()` text, and copied command output. Post those comments through
`--body-file` with a quoted heredoc or a real body file so the shell cannot
evaluate the body before GitHub receives it. Do not use inline `--body "..."`
for self-review findings, Code Lawyer reports, activity summaries, or any other
Markdown-heavy comment.

Safe PR comment pattern:

```sh
gh pr comment "$PR_NUMBER" --body-file - <<'EOF'
# Self-Code Review

| Severity | Count |
| :--- | ---: |
| P0 | 0 |

Commands stay literal: `npm test`, `gh pr checks`, and $().
EOF
```

Safe issue comment pattern:

```sh
gh issue comment "$ISSUE_NUMBER" --body-file - <<'EOF'
Linked artifacts:
- Design: `docs/design/WF-128-safe-gh-comments-and-milestone-items.md`
- Tests: `tests/cycles/WF-128/safe-comments-and-milestone-items.test.ts`
EOF
```

Use a temporary file with `--body-file "$COMMENT_BODY_FILE"` when the comment
is generated by a script. Delete the temporary file after the command succeeds.

## Evidence And Release Mechanics

- [release.md](./release.md) owns release validation and publishing mechanics.
- [Documentation Standards](./DOCUMENTATION_STANDARDS.md) owns documentation upkeep.
- [CHANGELOG.md](./CHANGELOG.md) records merged behavior.
- `docs/design/`, `tests/cycles/`, and release packets preserve technical proof.
- `docs/method/` is historical material, not an active workflow or backlog.

## Context Recovery

Start with GitHub issues, milestones, open and recently merged PRs, then the
linked Linear items once connected. Read relevant design/release evidence and
verify local Git history, status, and worktrees. Repository planning mirrors
are retired; tracker state must be read from the tracker.
