\chapter{What's New in Bijou 8.0.0-rc.1}\label{record-284}

\noindent{\footnotesize\color{BookMuted}\path{docs/releases/8.0.0/whats-new.md}\par}\smallskip

A release candidate, published so the breaking changes below can be validated against real applications before \texttt{8\allowbreak{}.\allowbreak{}0\allowbreak{}.\allowbreak{}0} is cut. Pin the exact version; the dist-tag is \texttt{n\allowbreak{}e\allowbreak{}x\allowbreak{}t}, not \texttt{l\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}s\allowbreak{}t}.

\section{The headline is a deletion}\label{record-284-the-headline-is-a-deletion}

\texttt{d\allowbreak{}e\allowbreak{}t\allowbreak{}e\allowbreak{}c\allowbreak{}t\allowbreak{}O\allowbreak{}u\allowbreak{}t\allowbreak{}p\allowbreak{}u\allowbreak{}t\allowbreak{}M\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{}(\allowbreak{})} no longer looks at \texttt{N\allowbreak{}O\allowbreak{}\_\allowbreak{}C\allowbreak{}O\allowbreak{}L\allowbreak{}O\allowbreak{}R}.

That variable means one thing: do not send me colour. It has never meant ``do not draw a user interface''. Bijou read it as a capability signal, so a developer who had \texttt{N\allowbreak{}O\allowbreak{}\_\allowbreak{}C\allowbreak{}O\allowbreak{}L\allowbreak{}O\allowbreak{}R\allowbreak{}=\allowbreak{}1} in their shell profile did not get a monochrome TUI --- they got no TUI. Every component dropped to its single-frame form, and the quit confirmation stopped asking.

The tell was that two first-party consumers had each independently written their own detector to route around it. \texttt{g\allowbreak{}i\allowbreak{}t\allowbreak{}-\allowbreak{}c\allowbreak{}a\allowbreak{}s} ships a \texttt{d\allowbreak{}e\allowbreak{}t\allowbreak{}e\allowbreak{}c\allowbreak{}t\allowbreak{}C\allowbreak{}l\allowbreak{}i\allowbreak{}T\allowbreak{}u\allowbreak{}i\allowbreak{}M\allowbreak{}o\allowbreak{}d\allowbreak{}e} with a comment explaining the problem; \texttt{m\allowbreak{}u\allowbreak{}n\allowbreak{}i\allowbreak{}m\allowbreak{}e\allowbreak{}n\allowbreak{}t} wrote the same override for the same reason. When consumers reimplement your detector, the detector is answering a question they did not ask.

Colour is unaffected --- it was never coupled to the mode in the implementation, only in the detector. \texttt{N\allowbreak{}O\allowbreak{}\_\allowbreak{}C\allowbreak{}O\allowbreak{}L\allowbreak{}O\allowbreak{}R} is read independently in three places, none of which consult \texttt{c\allowbreak{}t\allowbreak{}x\allowbreak{}.\allowbreak{}m\allowbreak{}o\allowbreak{}d\allowbreak{}e}, so with it set you still get \texttt{t\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e\allowbreak{}.\allowbreak{}n\allowbreak{}o\allowbreak{}C\allowbreak{}o\allowbreak{}l\allowbreak{}o\allowbreak{}r\allowbreak{} \allowbreak{}=\allowbreak{}=\allowbreak{}=\allowbreak{} \allowbreak{}t\allowbreak{}r\allowbreak{}u\allowbreak{}e} and unstyled output. What you also get now is a working TUI.

The test for this is the shape worth stealing. Rather than assert which mode \texttt{N\allowbreak{}O\allowbreak{}\_\allowbreak{}C\allowbreak{}O\allowbreak{}L\allowbreak{}O\allowbreak{}R} produces, the property asserts that adding \texttt{N\allowbreak{}O\allowbreak{}\_\allowbreak{}C\allowbreak{}O\allowbreak{}L\allowbreak{}O\allowbreak{}R} to \emph{any} environment leaves that environment's mode unchanged --- the contract stated directly, over 200 generated combinations of value, TTY state, \texttt{C\allowbreak{}I}, and \texttt{T\allowbreak{}E\allowbreak{}R\allowbreak{}M}.

\section{An unknown status key no longer looks cancelled}\label{record-284-an-unknown-status-key-no-longer-looks-cancelled}

\texttt{c\allowbreak{}t\allowbreak{}x\allowbreak{}.\allowbreak{}s\allowbreak{}t\allowbreak{}a\allowbreak{}t\allowbreak{}u\allowbreak{}s\allowbreak{}(\allowbreak{}'\allowbreak{}t\allowbreak{}y\allowbreak{}p\allowbreak{}o\allowbreak{}'\allowbreak{})} used to fall back to \texttt{s\allowbreak{}t\allowbreak{}a\allowbreak{}t\allowbreak{}u\allowbreak{}s\allowbreak{}.\allowbreak{}m\allowbreak{}u\allowbreak{}t\allowbreak{}e\allowbreak{}d}, and \texttt{s\allowbreak{}t\allowbreak{}a\allowbreak{}t\allowbreak{}u\allowbreak{}s\allowbreak{}.\allowbreak{}m\allowbreak{}u\allowbreak{}t\allowbreak{}e\allowbreak{}d} carries \texttt{s\allowbreak{}t\allowbreak{}r\allowbreak{}i\allowbreak{}k\allowbreak{}e\allowbreak{}t\allowbreak{}h\allowbreak{}r\allowbreak{}o\allowbreak{}u\allowbreak{}g\allowbreak{}h} in every shipped preset. So a mistyped key --- or a key an application meant to define and didn't --- rendered text with a line through it. The reader sees ``cancelled''. The application never said that.

It now falls back to \texttt{s\allowbreak{}e\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}c\allowbreak{}.\allowbreak{}m\allowbreak{}u\allowbreak{}t\allowbreak{}e\allowbreak{}d}, which is dim and nothing else, matching what the sibling \texttt{u\allowbreak{}i\allowbreak{}(\allowbreak{})} accessor already did with \texttt{s\allowbreak{}e\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}c\allowbreak{}.\allowbreak{}p\allowbreak{}r\allowbreak{}i\allowbreak{}m\allowbreak{}a\allowbreak{}r\allowbreak{}y}.

This one came out of a real application shipping the bug: a painter was declared, its status key was later dropped from the theme as a duplicate, and the painter kept resolving to the fallback. Nothing caught it --- not the type checker, not a palette audit, not review --- because no view had called it yet. \href{https://github.com/flyingrobots/bijou/issues/521}{\#521} tracks typing the accessors so that becomes a compile error.

\section{\texorpdfstring{\texttt{e\allowbreak{}x\allowbreak{}t\allowbreak{}e\allowbreak{}n\allowbreak{}d\allowbreak{}T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e\allowbreak{}(\allowbreak{})} can finally reach every group}{ can finally reach every group}}\label{record-284-extendtheme-can-finally-reach-every-group}

\texttt{T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e} has six token groups. \texttt{e\allowbreak{}x\allowbreak{}t\allowbreak{}e\allowbreak{}n\allowbreak{}d\allowbreak{}T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e\allowbreak{}(\allowbreak{})} accepted extensions for four, which sounds like an oversight and behaves like a trap, because the shipped presets alias one colour across the groups you could not reach.

\texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}d\allowbreak{}a\allowbreak{}r\allowbreak{}k} paints \texttt{s\allowbreak{}t\allowbreak{}a\allowbreak{}t\allowbreak{}u\allowbreak{}s\allowbreak{}.\allowbreak{}w\allowbreak{}a\allowbreak{}r\allowbreak{}n\allowbreak{}i\allowbreak{}n\allowbreak{}g}, \texttt{s\allowbreak{}t\allowbreak{}a\allowbreak{}t\allowbreak{}u\allowbreak{}s\allowbreak{}.\allowbreak{}a\allowbreak{}c\allowbreak{}t\allowbreak{}i\allowbreak{}v\allowbreak{}e}, \texttt{s\allowbreak{}e\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}c\allowbreak{}.\allowbreak{}w\allowbreak{}a\allowbreak{}r\allowbreak{}n\allowbreak{}i\allowbreak{}n\allowbreak{}g}, \texttt{s\allowbreak{}e\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}c\allowbreak{}.\allowbreak{}a\allowbreak{}c\allowbreak{}c\allowbreak{}e\allowbreak{}n\allowbreak{}t}, \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}c\allowbreak{}u\allowbreak{}r\allowbreak{}s\allowbreak{}o\allowbreak{}r}, \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}f\allowbreak{}o\allowbreak{}c\allowbreak{}u\allowbreak{}s\allowbreak{}G\allowbreak{}u\allowbreak{}t\allowbreak{}t\allowbreak{}e\allowbreak{}r}, \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}s\allowbreak{}e\allowbreak{}c\allowbreak{}t\allowbreak{}i\allowbreak{}o\allowbreak{}n\allowbreak{}H\allowbreak{}e\allowbreak{}a\allowbreak{}d\allowbreak{}e\allowbreak{}r}, \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}l\allowbreak{}o\allowbreak{}g\allowbreak{}o}, \texttt{b\allowbreak{}o\allowbreak{}r\allowbreak{}d\allowbreak{}e\allowbreak{}r\allowbreak{}.\allowbreak{}s\allowbreak{}e\allowbreak{}c\allowbreak{}o\allowbreak{}n\allowbreak{}d\allowbreak{}a\allowbreak{}r\allowbreak{}y} and \texttt{b\allowbreak{}o\allowbreak{}r\allowbreak{}d\allowbreak{}e\allowbreak{}r\allowbreak{}.\allowbreak{}w\allowbreak{}a\allowbreak{}r\allowbreak{}n\allowbreak{}i\allowbreak{}n\allowbreak{}g} in a single amber. Ten tokens. So \texttt{e\allowbreak{}x\allowbreak{}t\allowbreak{}e\allowbreak{}n\allowbreak{}d\allowbreak{}T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e\allowbreak{}(\allowbreak{}B\allowbreak{}I\allowbreak{}J\allowbreak{}O\allowbreak{}U\allowbreak{}\_\allowbreak{}D\allowbreak{}A\allowbreak{}R\allowbreak{}K\allowbreak{},\allowbreak{} \allowbreak{}\{\allowbreak{} \allowbreak{}s\allowbreak{}t\allowbreak{}a\allowbreak{}t\allowbreak{}u\allowbreak{}s\allowbreak{} \allowbreak{}\}\allowbreak{})} gave you your statuses and left that amber running every heading, cursor and border --- and if one of your new statuses was also amber-ish, your headings became indistinguishable from your warnings. That is how this was found, at ΔE 0.023 in OKLab.

\texttt{b\allowbreak{}o\allowbreak{}r\allowbreak{}d\allowbreak{}e\allowbreak{}r} and \texttt{s\allowbreak{}e\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}c} are now reachable. They are overridable rather than extensible, since \texttt{T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e} fixes their key sets.

The alias itself is still there. \texttt{e\allowbreak{}x\allowbreak{}t\allowbreak{}e\allowbreak{}n\allowbreak{}d\allowbreak{}T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e\allowbreak{}(\allowbreak{})} makes it escapable, not fixed --- see \href{https://github.com/flyingrobots/bijou/issues/519}{\#519}, which also records that \texttt{e\allowbreak{}r\allowbreak{}r\allowbreak{}o\allowbreak{}r} and \texttt{s\allowbreak{}u\allowbreak{}c\allowbreak{}c\allowbreak{}e\allowbreak{}s\allowbreak{}s} collapse to ΔE 0.059 under protanopia in the dark preset and 0.064 in the light one, and that \texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}l\allowbreak{}i\allowbreak{}g\allowbreak{}h\allowbreak{}t}'s severity ladder is inverted in lightness. If you rely on the shipped presets to distinguish severities, read that issue.

\section{What this candidate is for}\label{record-284-what-this-candidate-is-for}

Two behaviour changes that are correct in principle and unproven in the field. If \texttt{N\allowbreak{}O\allowbreak{}\_\allowbreak{}C\allowbreak{}O\allowbreak{}L\allowbreak{}O\allowbreak{}R} or a custom theme matters to your application, this is the version to try before \texttt{8\allowbreak{}.\allowbreak{}0\allowbreak{}.\allowbreak{}0} exists.

Read the \href{https://github.com/flyingrobots/bijou/blob/cbd70612140e7a450d764b3c7be1c6af878b99bc/docs/releases/8.0.0/migration-guide.md}{migration guide} for the specific things to check, and the \href{https://github.com/flyingrobots/bijou/blob/cbd70612140e7a450d764b3c7be1c6af878b99bc/docs/releases/8.0.0/README.md}{release evidence packet} --- which is explicit about which evidence was replayed for this candidate and which was inherited, because nine of eleven release-law review gates are still unreviewed. That is exactly why this is an rc and not a release.
