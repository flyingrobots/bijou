\section{MCP Rendering Server}\label{record-276-mcp-rendering-server}

Bijou now ships \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}m\allowbreak{}c\allowbreak{}p}, an MCP (Model Context Protocol) server that exposes Bijou's terminal components as rendering tools over stdio.

Any MCP client --- Claude Code, Cursor, or a custom integration --- can call 22 tools to get Unicode box-drawing output that renders correctly in monospace chat contexts. Tables, trees, DAGs, alert boxes, progress bars, timelines, and more --- all produced without ANSI escape codes.

\subsection{Why this matters}\label{record-276-why-this-matters}

LLM-powered coding tools talk in plain text. Structured terminal output (tables, graphs, trees) is useful in that context, but the rendering usually lives on the other side of a TTY. bijou-mcp bridges that gap: the AI calls a tool, Bijou renders the component, and the result drops into the conversation as clean Unicode text.

\subsection{Highlights}\label{record-276-highlights}

\begin{itemize}
\tightlist
\item
  \textbf{22 rendering tools} covering data/structure, containers/layout, feedback/status, navigation, rich panels, and utility categories
\item
  \textbf{No ANSI} --- uses \texttt{c\allowbreak{}r\allowbreak{}e\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}T\allowbreak{}e\allowbreak{}s\allowbreak{}t\allowbreak{}C\allowbreak{}o\allowbreak{}n\allowbreak{}t\allowbreak{}e\allowbreak{}x\allowbreak{}t} with \texttt{p\allowbreak{}l\allowbreak{}a\allowbreak{}i\allowbreak{}n\allowbreak{}S\allowbreak{}t\allowbreak{}y\allowbreak{}l\allowbreak{}e\allowbreak{}(\allowbreak{})} for terminal-free rendering
\item
  \textbf{Zero config} --- point your MCP client at the bin entrypoint and go
\end{itemize}

See the \href{https://github.com/flyingrobots/bijou/blob/cbd70612140e7a450d764b3c7be1c6af878b99bc/docs/packages/bijou-mcp/README.md}{bijou-mcp README} for the full tool inventory and configuration instructions.

\section{Runtime Engine: Framed Shell Migration (RE-007)}\label{record-276-runtime-engine-framed-shell-migration-re-007}

The framed shell now routes all input through the runtime engine's \texttt{r\allowbreak{}o\allowbreak{}u\allowbreak{}t\allowbreak{}e\allowbreak{}R\allowbreak{}u\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}m\allowbreak{}e\allowbreak{}I\allowbreak{}n\allowbreak{}p\allowbreak{}u\allowbreak{}t} infrastructure instead of ad-hoc key/mouse branches.

\subsection{What changed}\label{record-276-what-changed}

\begin{itemize}
\tightlist
\item
  Key routing flows through \texttt{r\allowbreak{}o\allowbreak{}u\allowbreak{}t\allowbreak{}e\allowbreak{}R\allowbreak{}u\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}m\allowbreak{}e\allowbreak{}I\allowbreak{}n\allowbreak{}p\allowbreak{}u\allowbreak{}t} producing \texttt{F\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e\allowbreak{}S\allowbreak{}h\allowbreak{}e\allowbreak{}l\allowbreak{}l\allowbreak{}C\allowbreak{}o\allowbreak{}m\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}d} facts
\item
  Mouse hit-testing uses retained layout trees with explicit layout nodes (\texttt{t\allowbreak{}a\allowbreak{}b\allowbreak{}:\allowbreak{}\{\allowbreak{}p\allowbreak{}a\allowbreak{}g\allowbreak{}e\allowbreak{}I\allowbreak{}d\allowbreak{}\}}, \texttt{p\allowbreak{}a\allowbreak{}n\allowbreak{}e\allowbreak{}:\allowbreak{}\{\allowbreak{}p\allowbreak{}a\allowbreak{}n\allowbreak{}e\allowbreak{}I\allowbreak{}d\allowbreak{}\}}, \texttt{s\allowbreak{}e\allowbreak{}t\allowbreak{}t\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}s\allowbreak{}-\allowbreak{}r\allowbreak{}o\allowbreak{}w\allowbreak{}:\allowbreak{}\{\allowbreak{}i\allowbreak{}n\allowbreak{}d\allowbreak{}e\allowbreak{}x\allowbreak{}\}})
\item
  Commands are buffered via \texttt{b\allowbreak{}u\allowbreak{}f\allowbreak{}f\allowbreak{}e\allowbreak{}r\allowbreak{}R\allowbreak{}u\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}m\allowbreak{}e\allowbreak{}R\allowbreak{}o\allowbreak{}u\allowbreak{}t\allowbreak{}e\allowbreak{}R\allowbreak{}e\allowbreak{}s\allowbreak{}u\allowbreak{}l\allowbreak{}t} and applied via \texttt{a\allowbreak{}p\allowbreak{}p\allowbreak{}l\allowbreak{}y\allowbreak{}R\allowbreak{}u\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}m\allowbreak{}e\allowbreak{}C\allowbreak{}o\allowbreak{}m\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}d\allowbreak{}B\allowbreak{}u\allowbreak{}f\allowbreak{}f\allowbreak{}e\allowbreak{}r}
\item
  Shell commands are a plain discriminated union interpreted by a handler table, not classes with behavior
\item
  The \texttt{u\allowbreak{}p\allowbreak{}d\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}(\allowbreak{})} key and mouse branches are reduced to single-line buffer drains
\end{itemize}
