\section{Hill}\label{record-253-hill}

Project Big Extraction starts by killing a hard-limit monolith instead of preserving legacy-large files as permanent habitat.

\texttt{e\allowbreak{}x\allowbreak{}a\allowbreak{}m\allowbreak{}p\allowbreak{}l\allowbreak{}e\allowbreak{}s\allowbreak{}/\allowbreak{}d\allowbreak{}o\allowbreak{}c\allowbreak{}s\allowbreak{}/\allowbreak{}d\allowbreak{}o\allowbreak{}g\allowbreak{}f\allowbreak{}o\allowbreak{}o\allowbreak{}d\allowbreak{}-\allowbreak{}b\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}s\allowbreak{}.\allowbreak{}t\allowbreak{}s} is currently a \texttt{2\allowbreak{},\allowbreak{}6\allowbreak{}3\allowbreak{}7} line / \texttt{9\allowbreak{}2\allowbreak{},\allowbreak{}0\allowbreak{}2\allowbreak{}0} byte DOGFOOD block registry monolith with \texttt{1\allowbreak{}5\allowbreak{}1} exports. The cycle turns it into a small compatibility facade backed by focused modules, preserving existing consumers while removing the hard-limit file from the active monolith list.

\section{Implementation Result}\label{record-253-implementation-result}

BE-001 turns \texttt{e\allowbreak{}x\allowbreak{}a\allowbreak{}m\allowbreak{}p\allowbreak{}l\allowbreak{}e\allowbreak{}s\allowbreak{}/\allowbreak{}d\allowbreak{}o\allowbreak{}c\allowbreak{}s\allowbreak{}/\allowbreak{}d\allowbreak{}o\allowbreak{}g\allowbreak{}f\allowbreak{}o\allowbreak{}o\allowbreak{}d\allowbreak{}-\allowbreak{}b\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}s\allowbreak{}.\allowbreak{}t\allowbreak{}s} into a \texttt{9\allowbreak{}7} line / \texttt{3\allowbreak{},\allowbreak{}7\allowbreak{}4\allowbreak{}0} byte facade and moves the registry, schema parsing, renderers, block definitions, and registry entries into focused modules. The largest extracted module is \texttt{e\allowbreak{}x\allowbreak{}a\allowbreak{}m\allowbreak{}p\allowbreak{}l\allowbreak{}e\allowbreak{}s\allowbreak{}/\allowbreak{}d\allowbreak{}o\allowbreak{}c\allowbreak{}s\allowbreak{}/\allowbreak{}d\allowbreak{}o\allowbreak{}g\allowbreak{}f\allowbreak{}o\allowbreak{}o\allowbreak{}d\allowbreak{}-\allowbreak{}b\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}-\allowbreak{}d\allowbreak{}o\allowbreak{}c\allowbreak{}s\allowbreak{}-\allowbreak{}s\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}-\allowbreak{}r\allowbreak{}e\allowbreak{}n\allowbreak{}d\allowbreak{}e\allowbreak{}r\allowbreak{}.\allowbreak{}t\allowbreak{}s} at \texttt{1\allowbreak{}4\allowbreak{}3} lines / \texttt{5\allowbreak{},\allowbreak{}5\allowbreak{}9\allowbreak{}7} bytes, so every new module stays below the Code Dojo file/context threshold.

\begin{itemize}
\tightlist
\item
  aggregate Code Dojo debt: \texttt{3\allowbreak{}6\allowbreak{}2}
\item
  file/context baseline: \texttt{3\allowbreak{}0\allowbreak{}8}
\item
  mock-ban baseline: \texttt{0}
\item

\item

\item
  DOGFOOD raw-string debt: \texttt{2\allowbreak{},\allowbreak{}3\allowbreak{}6\allowbreak{}5}, down from the stored \texttt{2\allowbreak{},\allowbreak{}4\allowbreak{}1\allowbreak{}5} baseline
\item
  next aggregate target from the live count: \texttt{3\allowbreak{}1\allowbreak{}2} or lower
\end{itemize}

The extraction removes \texttt{d\allowbreak{}o\allowbreak{}g\allowbreak{}f\allowbreak{}o\allowbreak{}o\allowbreak{}d\allowbreak{}-\allowbreak{}b\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}s\allowbreak{}.\allowbreak{}t\allowbreak{}s} from both debt ledgers but only removes two aggregate violations. It is an honest structural reduction, not a 50-violation goalpost by itself.

The DOGFOOD raw-string baseline is also transferred from the old \texttt{d\allowbreak{}o\allowbreak{}g\allowbreak{}f\allowbreak{}o\allowbreak{}o\allowbreak{}d\allowbreak{}-\allowbreak{}b\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}s} surface to the extracted module surfaces at exact measured counts, while stale slack in the docs, counter, and Storybook surfaces is removed.

\section{Scope}\label{record-253-scope}

\begin{itemize}
\tightlist
\item
  Split DOGFOOD block registry, block definitions, renderers, schema helpers, and registry assembly out of \texttt{e\allowbreak{}x\allowbreak{}a\allowbreak{}m\allowbreak{}p\allowbreak{}l\allowbreak{}e\allowbreak{}s\allowbreak{}/\allowbreak{}d\allowbreak{}o\allowbreak{}c\allowbreak{}s\allowbreak{}/\allowbreak{}d\allowbreak{}o\allowbreak{}g\allowbreak{}f\allowbreak{}o\allowbreak{}o\allowbreak{}d\allowbreak{}-\allowbreak{}b\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}s\allowbreak{}.\allowbreak{}t\allowbreak{}s}.
\item
  Preserve the current public import path and named exports through the facade.
\item
  Keep every new module below Code Dojo file/context and code-size thresholds.
\item
  Do not add new file/context or code-size baseline entries.
\item
  Update the Code Dojo ledgers after live counts prove the monolith is gone.
\item
  Update changelog and exception documentation with the Big Extraction result.
\end{itemize}
