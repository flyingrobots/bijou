\section{Framing}\label{record-257-framing}

Focus behavior in complex shells and multi-pane workstations is difficult to reason about from runtime output alone. The humane terminal story is stronger when focus ownership is inspectable and explainable.

HT-007 adds a pure focus map report and surface helper. The first slice accepts focus facts from an app or shell, detects basic focus-health issues, and renders plain text or a bounded \texttt{S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e}.

\section{Sponsored Users}\label{record-257-sponsored-users}

\begin{itemize}
\tightlist
\item
  App authors debugging tab order and focus ownership.
\item
  Maintainers investigating multi-pane focus regressions.
\item
  Agent workflows that need focus facts as deterministic text.
\end{itemize}

\section{Hills}\label{record-257-hills}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A developer can render the current focus map with focused node, owner, region, tab order, and disabled state.
\item
  A maintainer can detect multiple focused nodes, missing focused node, focused-disabled nodes, and duplicate tab indexes.
\item
  A test can render the report as a \texttt{S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e} for docs or debug panes.
\end{enumerate}

\section{Drift Check}\label{record-257-drift-check}

\begin{itemize}
\tightlist
\item
  Scope stayed pure and report-only; the helper consumes focus facts supplied by an app or shell instead of creating a competing focus manager.
\item
  The first issue set covers foundational focus invariants. Richer trap and dead-island detection remains a follow-up because it needs parent/edge facts that are not part of this slice.
\item
  Ordering is deterministic: tab index first, then node id.
\end{itemize}

\section{Retrospective}\label{record-257-retrospective}

\begin{itemize}
\tightlist
\item
  This pairs cleanly with the layout and input-routing inspectors: layout shows where regions are, input routing shows how events moved, and the focus map shows who currently owns focus.
\item
  App-provided focus facts are the right boundary for the first slice. Inferring focus from rendered text would create brittle diagnostics and hide the runtime truth the helper is meant to expose.
\end{itemize}
