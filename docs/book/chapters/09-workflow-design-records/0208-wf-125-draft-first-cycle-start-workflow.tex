\section{Framing}\label{record-208-framing}

Issue \href{https://github.com/flyingrobots/bijou/issues/279}{\#279} changes the Bijou cycle loop from ``open the pull request at ship time'' to ``open a draft pull request at cycle start.'' The intent is to make issue, branch, design doc, and PR state visible before implementation expands, while keeping the final ready-for-review and merge gates strict.

The work follows a Design Thinking loop:

\begin{itemize}
\tightlist
\item
  observe that cycle work can stay invisible until late implementation
\item
  frame draft PRs as early coordination artifacts rather than merge-ready review artifacts
\item
  prototype the new loop in Method, Workflow, Contributor, Agent, and issue template docs
\item
  prove the policy with a workflow regression that reads those docs
\end{itemize}

\section{Sponsored Users}\label{record-208-sponsored-users}

\begin{itemize}
\tightlist
\item
  Maintainers who need early visibility into the branch and linked artifacts.
\item
  Contributors who need one explicit start-of-cycle checklist.
\item
  Agents that need a deterministic order for sync, branch, shape, push, draft PR, and work-in-progress labeling.
\item
  Reviewers who should see draft context early without treating it as ready.
\end{itemize}

\section{Hills}\label{record-208-hills}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A contributor can start a cycle by syncing the merge target, creating a \texttt{c\allowbreak{}y\allowbreak{}c\allowbreak{}l\allowbreak{}e\allowbreak{}/\allowbreak{}<\allowbreak{}c\allowbreak{}y\allowbreak{}c\allowbreak{}l\allowbreak{}e\allowbreak{}\_\allowbreak{}n\allowbreak{}a\allowbreak{}m\allowbreak{}e\allowbreak{}>} branch, shaping the issue and design doc, committing and pushing that shape, opening a draft PR, and applying \texttt{w\allowbreak{}o\allowbreak{}r\allowbreak{}k\allowbreak{}-\allowbreak{}i\allowbreak{}n\allowbreak{}-\allowbreak{}p\allowbreak{}r\allowbreak{}o\allowbreak{}g\allowbreak{}r\allowbreak{}e\allowbreak{}s\allowbreak{}s}.
\item
  A reviewer can distinguish an early draft coordination PR from a ready PR that has passed implementation, validation, and self-review.
\item
  A maintainer can run one workflow regression that prevents the docs and issue template from drifting back to the old ``PR only at ship'' loop.
\end{enumerate}

\section{Playback Questions}\label{record-208-playback-questions}

\begin{itemize}
\tightlist
\item
  Does every workflow surface say to run \texttt{g\allowbreak{}i\allowbreak{}t\allowbreak{} \allowbreak{}f\allowbreak{}e\allowbreak{}t\allowbreak{}c\allowbreak{}h} and sync the merge target before branching?
\item
  Does the cycle branch start from the synced target instead of stale local state?
\item
  Does the shaping commit include the GitHub Issue and design doc before implementation work begins?
\item
  Does a draft PR to \texttt{m\allowbreak{}a\allowbreak{}i\allowbreak{}n} exist before implementation starts?
\item
  Does the issue carry \texttt{w\allowbreak{}o\allowbreak{}r\allowbreak{}k\allowbreak{}-\allowbreak{}i\allowbreak{}n\allowbreak{}-\allowbreak{}p\allowbreak{}r\allowbreak{}o\allowbreak{}g\allowbreak{}r\allowbreak{}e\allowbreak{}s\allowbreak{}s} while the branch or draft PR is actively carrying it?
\item
  Does the draft PR move to ready only after implementation, validation, and self-review?
\end{itemize}

\section{Workflow Contract}\label{record-208-workflow-contract}

\begin{CodeBlock}
git fetch
sync merge target branch
checkout cycle/<cycle_name>
write or update GitHub Issue
write docs/design/<cycle>.md
stage + commit + push shaping artifact
open draft PR to main
link issue + design doc + draft PR
apply work-in-progress to issue
do RED/GREEN cycle work
validate + self-review
mark PR ready for review
\end{CodeBlock}

\section{Closeout}\label{record-208-closeout}

The cycle is landed when:

\begin{itemize}
\tightlist
\item
  the workflow docs require merge-target sync before branching
\item
  the workflow docs require a draft PR to \texttt{m\allowbreak{}a\allowbreak{}i\allowbreak{}n} at cycle start
\item
  the issue template requires issue, design doc, and draft PR links
\item
  the draft PR is marked ready only after implementation, validation, and self-review
\item
  the WF-001 regression, docs inventory, lint, and whitespace checks pass
\item
  the pull request closes \#279
\end{itemize}
