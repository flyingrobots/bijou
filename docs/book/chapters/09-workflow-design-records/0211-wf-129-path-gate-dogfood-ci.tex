\section{Framing}\label{record-211-framing}

The CI loop is intentionally conservative, but ordinary workflow/documentation PRs currently run DOGFOOD-heavy gates even when they do not touch DOGFOOD, runtime components, localization, or CI scripts. That makes rapid-fire cycles pay duplicate install/build/smoke costs before review can close.

This cycle adds a CI change classifier so DOGFOOD-specific checks run when they are relevant and skip when a PR is unrelated to DOGFOOD. Pushes to \texttt{m\allowbreak{}a\allowbreak{}i\allowbreak{}n} and tag workflows remain full-strength.

\section{Sponsored Users}\label{record-211-sponsored-users}

\begin{itemize}
\tightlist
\item
  A maintainer iterating on workflow documentation needs PR CI to avoid DOGFOOD smoke work when the branch cannot affect DOGFOOD.
\item
  A release maintainer needs \texttt{m\allowbreak{}a\allowbreak{}i\allowbreak{}n} pushes and tags to continue running the full DOGFOOD proof path.
\item
  A review agent needs the path-gating contract to be visible in the workflow file and covered by a regression test.
\end{itemize}

\section{Hill}\label{record-211-hill}

A contributor can open a PR that only changes non-DOGFOOD docs or workflow bookkeeping and see DOGFOOD-heavy CI lanes skipped, while any PR touching DOGFOOD, packages, localization, DOGFOOD scripts/tests, or CI workflows still runs DOGFOOD proof.

\section{Product Shape}\label{record-211-product-shape}

\subsection{CI Classifier}\label{record-211-ci-classifier}

\begin{CodeBlock}
CI
  changes
    dogfood = true on main pushes and tags
    dogfood = true on PRs touching:
      .github/workflows/**
      package.json
      package-lock.json
      packages/**
      examples/docs/**
      scripts/dogfood-*
      scripts/smoke-dogfood*
      tests/cycles/DF-*
      tests/cycles/*dogfood*
      docs/DOGFOOD.md
      docs/design/DF-*
      docs/legends/DF-*
      docs/method/legends/DF-*
\end{CodeBlock}

\subsection{Gated DOGFOOD Proof}\label{record-211-gated-dogfood-proof}

\begin{CodeBlock}
test (22)
  always: build, lint, npm test
  when dogfood-relevant: DOGFOOD coverage + DOGFOOD i18n policy

Smoke DOGFOOD (landing/docs)
  when dogfood-relevant: run checkout, install, build, and smoke command
  otherwise: keep check names present and skip expensive smoke steps
\end{CodeBlock}

\section{Runtime And API Contract}\label{record-211-runtime-and-api-contract}

This cycle changes CI workflow behavior only. It does not change package APIs, runtime behavior, DOGFOOD rendering, localization catalogs, or release workflows.

\section{Acceptance Criteria}\label{record-211-acceptance-criteria}

\begin{itemize}
\tightlist
\item
  Issue \#293 is closed by the PR.
\item
  PR CI has an explicit \texttt{c\allowbreak{}h\allowbreak{}a\allowbreak{}n\allowbreak{}g\allowbreak{}e\allowbreak{}s} job.
\item
  DOGFOOD coverage/i18n policy steps run only when the classifier says DOGFOOD proof is needed.

  DOGFOOD landing/docs smoke commands run only when the classifier says DOGFOOD proof is needed, while the check names remain present.
\item

\item

\section{Risks And Guardrails}\label{record-211-risks-and-guardrails}

\begin{itemize}
\tightlist
\item
  Do not path-gate release dry-run or publish workflows in this cycle.
\item
  Do not skip full \texttt{n\allowbreak{}p\allowbreak{}m\allowbreak{} \allowbreak{}t\allowbreak{}e\allowbreak{}s\allowbreak{}t} in the core Ubuntu matrix yet.
\item
  Do not weaken DOGFOOD proof when \texttt{p\allowbreak{}a\allowbreak{}c\allowbreak{}k\allowbreak{}a\allowbreak{}g\allowbreak{}e\allowbreak{}s\allowbreak{}/\allowbreak{}*\allowbreak{}*}, \texttt{e\allowbreak{}x\allowbreak{}a\allowbreak{}m\allowbreak{}p\allowbreak{}l\allowbreak{}e\allowbreak{}s\allowbreak{}/\allowbreak{}d\allowbreak{}o\allowbreak{}c\allowbreak{}s\allowbreak{}/\allowbreak{}*\allowbreak{}*}, or DOGFOOD-specific scripts/tests change.
\item
  Keep the classifier readable enough to audit in review.
\end{itemize}
