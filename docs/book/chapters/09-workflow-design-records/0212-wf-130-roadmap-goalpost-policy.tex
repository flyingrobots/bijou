\section{Linked Legend}\label{record-212-linked-legend}

WF - Workflow and Delivery

\section{Decision Summary}\label{record-212-decision-summary}

Adopt a Bijou roadmap planning system that maps GitHub milestone items into versioned releases, candidate goalposts, umbrella issues, user-story issues, slice budgets, release gates, and proof requirements.

\section{Sponsor Human}\label{record-212-sponsor-human}

A maintainer wants to see the current release path and backlog shape without reconstructing it from memory, stale Markdown, and raw GitHub lists, so that release planning can stay issue-backed and inspectable.

\section{Sponsor Agent}\label{record-212-sponsor-agent}

An agent needs a documented roadmap hierarchy and issue-template fields so it can classify work as ordinary issues, goalpost umbrellas, or user stories without inventing planning structure in each turn.

\section{Hill}\label{record-212-hill}

By the end of this cycle, Bijou has a release-packet policy, a GitHub-backed roadmap snapshot, issue-template fields for roadmap roles and slice budgets, and tests that prevent the docs from drifting back to draft-first cycle language.

\section{Problem}\label{record-212-problem}

Bijou has strong issue intake and cycle docs, but it lacks the intermediate roadmap structure that explains how individual issues become release-scale goalposts. The docs also contain stale draft-first language that conflicts with current repo instructions.

\section{Scope}\label{record-212-scope}

This cycle includes:

\begin{itemize}
\tightlist
\item
  defining the release-packet contract under \texttt{d\allowbreak{}o\allowbreak{}c\allowbreak{}s\allowbreak{}/\allowbreak{}m\allowbreak{}e\allowbreak{}t\allowbreak{}h\allowbreak{}o\allowbreak{}d\allowbreak{}/\allowbreak{}r\allowbreak{}e\allowbreak{}l\allowbreak{}e\allowbreak{}a\allowbreak{}s\allowbreak{}e\allowbreak{}s\allowbreak{}/}

\item
  grouping the open Beyond backlog into candidate goalposts
\item
  adding roadmap role, linkage, slice budget, and release-gate fields to the Method work-item issue form
\item
  aligning operator docs to non-draft PRs at cycle start
\item
  adding tests that prove the policy and the non-draft alignment
\end{itemize}
