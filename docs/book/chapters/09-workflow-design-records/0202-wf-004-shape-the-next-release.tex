\section{Hill}\label{record-202-hill}

The next Bijou release is a deliberate, inspectable decision rather than an accretion of unreleased work.

\section{Why this cycle exists}\label{record-202-why-this-cycle-exists}

Since \texttt{v\allowbreak{}4\allowbreak{}.\allowbreak{}0\allowbreak{}.\allowbreak{}0}, Bijou has accumulated a large and mixed wave of work:

\begin{itemize}
\tightlist
\item
  runtime engine architecture and implementation slices
\item
  humane shell behavior and shell introspection
\item
  DOGFOOD growth into a real proving surface
\item
  new localization packages and workflow tooling
\item
  design-language doctrine and reusable review surfaces
\item
  release, workflow, and repo-signpost hardening
\end{itemize}

That progress is real, but it created release ambiguity:

\begin{itemize}
\tightlist
\item
  \texttt{[\allowbreak{}U\allowbreak{}n\allowbreak{}r\allowbreak{}e\allowbreak{}l\allowbreak{}e\allowbreak{}a\allowbreak{}s\allowbreak{}e\allowbreak{}d\allowbreak{}]} in \texttt{C\allowbreak{}H\allowbreak{}A\allowbreak{}N\allowbreak{}G\allowbreak{}E\allowbreak{}L\allowbreak{}O\allowbreak{}G\allowbreak{}.\allowbreak{}m\allowbreak{}d} is not yet a clean \texttt{v\allowbreak{}4\allowbreak{}.\allowbreak{}0\allowbreak{}.\allowbreak{}0\allowbreak{}.\allowbreak{}.\allowbreak{}H\allowbreak{}E\allowbreak{}A\allowbreak{}D} release boundary
\item
  the repo had long-form release docs, but they still lived under \texttt{d\allowbreak{}o\allowbreak{}c\allowbreak{}s\allowbreak{}/\allowbreak{}r\allowbreak{}e\allowbreak{}l\allowbreak{}e\allowbreak{}a\allowbreak{}s\allowbreak{}e\allowbreak{}s\allowbreak{}/\allowbreak{}n\allowbreak{}e\allowbreak{}x\allowbreak{}t\allowbreak{}/}
\item
  the workspace contains new i18n packages, but the automated npm publish matrix still only covers the older five published packages
\item
  \href{https://github.com/flyingrobots/bijou/blob/cbd70612140e7a450d764b3c7be1c6af878b99bc/docs/method/graveyard/legacy-backlog/up-next/RE-007-migrate-framed-shell-onto-runtime-engine-seams.md}{RE-007} is important follow-on architecture work, but the repo had not yet answered whether it is a release blocker
\end{itemize}

This cycle exists to make those choices explicit.

\section{Accessibility / assistive reading posture}\label{record-202-accessibility-assistive-reading-posture}

This cycle is documentation-first. The important requirement is that the release shape remains legible in plain markdown and does not depend on tables, screenshots, or GitHub-specific UI to understand the decision.

\section{Localization / directionality posture}\label{record-202-localization-directionality-posture}

The release includes localization work, so the docs must not pretend that the repo is still English-only by design. The prose remains English for now, but the release shape must explicitly acknowledge the new i18n packages and the publish-matrix gap around them.

\section{Decision}\label{record-202-decision}

\subsection{Target version}\label{record-202-target-version}

The next release should be \textbf{\texttt{4\allowbreak{}.\allowbreak{}1\allowbreak{}.\allowbreak{}0}}, stable.

\subsection{\texorpdfstring{Why \texttt{4\allowbreak{}.\allowbreak{}1\allowbreak{}.\allowbreak{}0}}{Why }}\label{record-202-why-4.1.0}

\begin{itemize}
\tightlist
\item
  the release has a strong additive feature story across multiple public surfaces
\item
  it is much larger than a patch release
\item
  it does not present a clear enough breaking boundary to justify \texttt{5\allowbreak{}.\allowbreak{}0\allowbreak{}.\allowbreak{}0}
\item
  it is the first release after \texttt{v\allowbreak{}4\allowbreak{}.\allowbreak{}0\allowbreak{}.\allowbreak{}0} that turns Bijou from ``surface toolkit with a framed shell'' into a more coherent application/runtime platform
\end{itemize}

\subsection{\texorpdfstring{\texttt{R\allowbreak{}E\allowbreak{}-\allowbreak{}0\allowbreak{}0\allowbreak{}7} decision}{ decision}}\label{record-202-re-007-decision}

\texttt{R\allowbreak{}E\allowbreak{}-\allowbreak{}0\allowbreak{}0\allowbreak{}7} is \textbf{not} a blocker for \texttt{4\allowbreak{}.\allowbreak{}1\allowbreak{}.\allowbreak{}0}.

It remains an important architectural follow-on, but waiting for it would blur a coherent and already substantial release behind one more runtime slice. \texttt{4\allowbreak{}.\allowbreak{}1\allowbreak{}.\allowbreak{}0} should ship the runtime-engine story through \texttt{R\allowbreak{}E\allowbreak{}-\allowbreak{}0\allowbreak{}0\allowbreak{}6} and then let \texttt{R\allowbreak{}E\allowbreak{}-\allowbreak{}0\allowbreak{}0\allowbreak{}7} become follow-on work for the next line.
