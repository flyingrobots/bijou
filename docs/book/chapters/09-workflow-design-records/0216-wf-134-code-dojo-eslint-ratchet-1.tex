\section{Decision Summary}\label{record-216-decision-summary}

\texttt{R\allowbreak{}e\allowbreak{}s\allowbreak{}p\allowbreak{}e\allowbreak{}c\allowbreak{}t\allowbreak{}f\allowbreak{}u\allowbreak{}l\allowbreak{} \allowbreak{}R\allowbreak{}e\allowbreak{}p\allowbreak{}o\allowbreak{}:\allowbreak{} \allowbreak{}E\allowbreak{}n\allowbreak{}t\allowbreak{}e\allowbreak{}r\allowbreak{} \allowbreak{}t\allowbreak{}h\allowbreak{}e\allowbreak{} \allowbreak{}C\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{} \allowbreak{}D\allowbreak{}o\allowbreak{}j\allowbreak{}o} made the standards debt visible and ratcheted, but the ESLint debt is still the dominant exception class. The stored ESLint ceiling is \texttt{5\allowbreak{},\allowbreak{}3\allowbreak{}4\allowbreak{}5}, while a live type-aware ESLint run on \texttt{m\allowbreak{}a\allowbreak{}i\allowbreak{}n} reports \texttt{5\allowbreak{},\allowbreak{}1\allowbreak{}2\allowbreak{}1} findings. The first cleanup pass should convert that already observed shrink plus targeted high-yield fixes into a lower enforceable ceiling.

This cycle deliberately starts with bounded test and tooling clusters instead of broad DOGFOOD example rewrites. The DOGFOOD files also carry localization and code-size tripwires, so they need their own carefully shaped pass.

\section{Sponsored Human}\label{record-216-sponsored-human}

A maintainer wants the new standards posture to burn down real lint debt now, not merely document it as a future aspiration.

\section{Sponsored Agent}\label{record-216-sponsored-agent}

An agent needs a concrete first ratchet target with inspectable before/after counts, so later cycles can keep reducing the ceiling without guessing which violations are already paid down.

\section{Hill}\label{record-216-hill}

Reduce live type-aware ESLint findings from \texttt{5\allowbreak{},\allowbreak{}1\allowbreak{}2\allowbreak{}1} to at most \texttt{4\allowbreak{},\allowbreak{}9\allowbreak{}0\allowbreak{}0}, then continue the same bounded cleanup pass to at most \texttt{4\allowbreak{},\allowbreak{}6\allowbreak{}0\allowbreak{}0} when the first target is comfortably met. Lower the official ESLint and aggregate Code Dojo debt ceilings so future work cannot regain the cleaned-up violations.

\section{Non-Goals}\label{record-216-non-goals}

\begin{itemize}
\tightlist
\item
  Do not soften, disable, or narrow ESLint rules.
\item
  Do not raise any Code Dojo ceiling.
\item
  Do not mix unrelated product behavior changes into the cleanup.
\item
  Do not tackle DOGFOOD mega-file refactors in this first pass unless a touched file's policy requires it.
\item
  Do not try to clear all ESLint debt in one oversized branch.
\end{itemize}

\section{Tests To Write First}\label{record-216-tests-to-write-first}

This cycle mostly pays down static-analysis debt in already covered surfaces. When a cleanup changes runtime behavior or helper contracts, add a focused regression test before the fix. For purely type-safety rewrites, the RED signal is the existing ESLint finding and the GREEN signal is the lowered live ESLint count plus the relevant existing focused suite.
