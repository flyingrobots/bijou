\section{Sponsor Human}\label{record-206-sponsor-human}

A TypeScript contributor on macOS, Linux, or Windows who wants the core Bijou build and test path to work without first installing a Unix shell.

\section{Sponsor Agent}\label{record-206-sponsor-agent}

A workflow verification agent that can inspect CI, package scripts, and local commands to prove which parts of the repo are portable and which are intentionally platform-hosted.

\section{Hill}\label{record-206-hill}

Bijou's contributor-facing scripts are Node-first, and CI proves the core build and focused unit-test path on at least one non-Linux platform.

\section{Scope}\label{record-206-scope}

\begin{itemize}
\tightlist
\item
  Replace avoidable Bash and POSIX shell usage in root contributor scripts.
\item
  Add a non-Linux CI lane for build, typecheck, and focused unit tests.
\item
  Document which workflows remain Linux/Bash-hosted because they are release, benchmark, or terminal-capture lanes rather than the first contributor path.
\end{itemize}

\section{Playback Questions}\label{record-206-playback-questions}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Can a Windows contributor run the core root scripts without WSL-only shell behavior?
\item
  Does CI prove at least one non-Linux build/typecheck/unit lane?
\item
  Can a reviewer tell which remaining Bash paths are intentional workflow infrastructure?
\end{enumerate}

\section{Accessibility / Assistive Reading Posture}\label{record-206-accessibility-assistive-reading-posture}

The docs must name the platform support posture plainly in README and CONTRIBUTING without hiding it in workflow YAML.

\section{Localization / Directionality Posture}\label{record-206-localization-directionality-posture}

No runtime localization changes.

\begin{itemize}
\tightlist

  Contributor-facing commands should be portable when Node can provide the same behavior.

\begin{itemize}
\tightlist
\item
  \texttt{n\allowbreak{}p\allowbreak{}m\allowbreak{} \allowbreak{}r\allowbreak{}u\allowbreak{}n\allowbreak{} \allowbreak{}c\allowbreak{}l\allowbreak{}e\allowbreak{}a\allowbreak{}n} becomes \texttt{n\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{} \allowbreak{}s\allowbreak{}c\allowbreak{}r\allowbreak{}i\allowbreak{}p\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}c\allowbreak{}l\allowbreak{}e\allowbreak{}a\allowbreak{}n\allowbreak{}.\allowbreak{}m\allowbreak{}j\allowbreak{}s} and removes workspace \texttt{d\allowbreak{}i\allowbreak{}s\allowbreak{}t\allowbreak{}/} directories plus workspace \texttt{.\allowbreak{}t\allowbreak{}s\allowbreak{}b\allowbreak{}u\allowbreak{}i\allowbreak{}l\allowbreak{}d\allowbreak{}i\allowbreak{}n\allowbreak{}f\allowbreak{}o} files without shell globs.
\item
  \texttt{n\allowbreak{}p\allowbreak{}m\allowbreak{} \allowbreak{}r\allowbreak{}u\allowbreak{}n\allowbreak{} \allowbreak{}v\allowbreak{}e\allowbreak{}r\allowbreak{}s\allowbreak{}i\allowbreak{}o\allowbreak{}n} becomes \texttt{n\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{} \allowbreak{}s\allowbreak{}c\allowbreak{}r\allowbreak{}i\allowbreak{}p\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}v\allowbreak{}e\allowbreak{}r\allowbreak{}s\allowbreak{}i\allowbreak{}o\allowbreak{}n\allowbreak{}.\allowbreak{}m\allowbreak{}j\allowbreak{}s}, preserving the existing workspace version bump and internal dependency pinning behavior.
\item
  CI keeps the full supported Node 20/22 lane on Ubuntu and adds Node 22 focused unit coverage on macOS and Windows.
\item
  The repository development floor is \texttt{\textasciicircum{}\allowbreak{}2\allowbreak{}0\allowbreak{}.\allowbreak{}1\allowbreak{}9\allowbreak{}.\allowbreak{}0\allowbreak{} \allowbreak{}|\allowbreak{}|\allowbreak{} \allowbreak{}>\allowbreak{}=\allowbreak{}2\allowbreak{}2\allowbreak{}.\allowbreak{}1\allowbreak{}2\allowbreak{}.\allowbreak{}0} after the Vitest 4.1 toolchain moved through Vite 8/Rolldown APIs that cannot start on Node 18 or earlier 20/22 minors.
\item
  Existing release, publish, benchmark, retry, and hook shell scripts remain explicit shell-owned infrastructure. They are not the Day 0 contributor path.
\end{itemize}
