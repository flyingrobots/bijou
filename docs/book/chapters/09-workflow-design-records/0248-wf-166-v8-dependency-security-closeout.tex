\section{Tests To Write First}\label{record-248-tests-to-write-first}

The deterministic RED proof reads the lockfile and rejects the vulnerable resolved versions named above. It must fail on the merge-base lockfile before the update and pass afterward.

The external advisory proof is:

\begin{CodeBlock}
npm audit --audit-level=low
\end{CodeBlock}

The clean-install compatibility and product proof is executed in this order:

\begin{CodeBlock}
npm ci
npm audit --audit-level=low
npm run build
npm run typecheck:test
npm run lint
npm run lint:eslint
npm run code:size
npm run test:run
npm run code-dojo:ci
npm run smoke:dogfood
npm run docs:inventory
npm run docs:design-system:preflight
npm run verify:interactive-examples
\end{CodeBlock}

That sequence proves that a clean install from the committed lockfile preserves the repository's supported execution surface. Hosted CI repeats \texttt{n\allowbreak{}p\allowbreak{}m\allowbreak{} \allowbreak{}c\allowbreak{}i} and the full repository test lane on both supported runtimes as the \href{https://github.com/flyingrobots/bijou/blob/cbd70612140e7a450d764b3c7be1c6af878b99bc/.github/workflows/ci.yml}{\texttt{t\allowbreak{}e\allowbreak{}s\allowbreak{}t\allowbreak{} \allowbreak{}(\allowbreak{}2\allowbreak{}0\allowbreak{})} and \texttt{t\allowbreak{}e\allowbreak{}s\allowbreak{}t\allowbreak{} \allowbreak{}(\allowbreak{}2\allowbreak{}2\allowbreak{})} matrix jobs}, and runs the two DOGFOOD smoke jobs independently.

\section{Retrospective}\label{record-248-retrospective}

The security pass had to be refreshed against live advisory truth rather than the original shaping snapshot. The first carried lock attempt still admitted newer \texttt{f\allowbreak{}a\allowbreak{}s\allowbreak{}t\allowbreak{}-\allowbreak{}u\allowbreak{}r\allowbreak{}i}, Hono, and \texttt{i\allowbreak{}p\allowbreak{}-\allowbreak{}a\allowbreak{}d\allowbreak{}d\allowbreak{}r\allowbreak{}e\allowbreak{}s\allowbreak{}s} advisories and predated the \texttt{n\allowbreak{}a\allowbreak{}n\allowbreak{}o\allowbreak{}i\allowbreak{}d} advisory. Its regression could therefore false-green. Raising the executable floors and binding the root Hono override made the clean-install promise real.

\texttt{n\allowbreak{}p\allowbreak{}m\allowbreak{} \allowbreak{}a\allowbreak{}u\allowbreak{}d\allowbreak{}i\allowbreak{}t\allowbreak{} \allowbreak{}f\allowbreak{}i\allowbreak{}x\allowbreak{} \allowbreak{}-\allowbreak{}-\allowbreak{}p\allowbreak{}a\allowbreak{}c\allowbreak{}k\allowbreak{}a\allowbreak{}g\allowbreak{}e\allowbreak{}-\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}-\allowbreak{}o\allowbreak{}n\allowbreak{}l\allowbreak{}y} also demonstrated why audit success is not the complete proof: it temporarily pruned the manifest-required SheetJS entry and reported zero vulnerabilities, while \texttt{n\allowbreak{}p\allowbreak{}m\allowbreak{} \allowbreak{}c\allowbreak{}i} correctly rejected the inconsistent lock. Regenerating through \texttt{n\allowbreak{}p\allowbreak{}m\allowbreak{} \allowbreak{}i\allowbreak{}n\allowbreak{}s\allowbreak{}t\allowbreak{}a\allowbreak{}l\allowbreak{}l\allowbreak{} \allowbreak{}-\allowbreak{}-\allowbreak{}p\allowbreak{}a\allowbreak{}c\allowbreak{}k\allowbreak{}a\allowbreak{}g\allowbreak{}e\allowbreak{}-\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}-\allowbreak{}o\allowbreak{}n\allowbreak{}l\allowbreak{}y} restored that entry; the repeated clean install, audit, full \texttt{9\allowbreak{}3\allowbreak{}0} file / \texttt{4\allowbreak{},\allowbreak{}1\allowbreak{}0\allowbreak{}4} test suite, DOGFOOD smoke, documentation preflight, and interactive examples then passed. Hosted Node 20/22 evidence, \#467 disposition, and the final \#482 closeout remain merge-bound acceptance steps.
