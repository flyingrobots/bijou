\section{Idea}\label{record-324-idea}

The bench v2 report JSON is structured for humans: nested arrays, the illustrated sequence below It's readable but inefficient for agents to consume programmatically, especially when comparing many runs over time (e.g., ``how did p99 trend across the last 20 RE-017 commits?'').

\input{diagrams/flows/flow-078}

Add a flat, agent-friendly output format alongside the existing one. Structure:

\begin{CodeBlock}
{"runId":"...","scenario":"paint-gradient-rgb","commit":"abc","metric":"ns_per_frame.p50","value":946000,"unit":"ns","cov":0.029}
{"runId":"...","scenario":"paint-gradient-rgb","commit":"abc","metric":"ns_per_frame.p99","value":954000,"unit":"ns","cov":0.029}
{"runId":"...","scenario":"paint-gradient-rgb","commit":"abc","metric":"samples_count","value":30,"unit":"count"}
...
\end{CodeBlock}

One line per (scenario, metric) tuple. Agents can stream, filter, tail, or grep without parsing nested structures. Queries like ``give me the p50 for paint-gradient-rgb across runs X, Y, Z'' become one-line jq or ripgrep commands.

Expose via \texttt{b\allowbreak{}e\allowbreak{}n\allowbreak{}c\allowbreak{}h\allowbreak{} \allowbreak{}r\allowbreak{}u\allowbreak{}n\allowbreak{} \allowbreak{}-\allowbreak{}-\allowbreak{}f\allowbreak{}o\allowbreak{}r\allowbreak{}m\allowbreak{}a\allowbreak{}t\allowbreak{}=\allowbreak{}j\allowbreak{}s\allowbreak{}o\allowbreak{}n\allowbreak{}l} or \texttt{b\allowbreak{}e\allowbreak{}n\allowbreak{}c\allowbreak{}h\allowbreak{} \allowbreak{}r\allowbreak{}u\allowbreak{}n\allowbreak{} \allowbreak{}-\allowbreak{}-\allowbreak{}f\allowbreak{}o\allowbreak{}r\allowbreak{}m\allowbreak{}a\allowbreak{}t\allowbreak{}=\allowbreak{}f\allowbreak{}l\allowbreak{}a\allowbreak{}t}, with \texttt{-\allowbreak{}-\allowbreak{}f\allowbreak{}o\allowbreak{}r\allowbreak{}m\allowbreak{}a\allowbreak{}t\allowbreak{}=\allowbreak{}j\allowbreak{}s\allowbreak{}o\allowbreak{}n} remaining the default for humans.

\section{Why}\label{record-324-why}

I (the agent) noticed this during the RE-017 audit when I had to hand-build an aggregator (\texttt{s\allowbreak{}c\allowbreak{}r\allowbreak{}i\allowbreak{}p\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}a\allowbreak{}g\allowbreak{}g\allowbreak{}r\allowbreak{}e\allowbreak{}g\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}-\allowbreak{}a\allowbreak{}u\allowbreak{}d\allowbreak{}i\allowbreak{}t\allowbreak{}-\allowbreak{}r\allowbreak{}u\allowbreak{}n\allowbreak{}s\allowbreak{}.\allowbreak{}t\allowbreak{}s}, since deleted) to crunch stats across 10 run files. If the output had been flat JSONL I would have written \texttt{j\allowbreak{}q\allowbreak{} \allowbreak{}|\allowbreak{} \allowbreak{}s\allowbreak{}o\allowbreak{}r\allowbreak{}t\allowbreak{} \allowbreak{}|\allowbreak{} \allowbreak{}u\allowbreak{}n\allowbreak{}i\allowbreak{}q} and been done in a minute. Instead I wrote 200 lines of TypeScript that had its own bugs.

More broadly: I operate more efficiently when tools emit data in formats I can pipe through small composable UNIX primitives. The human-friendly nested JSON is great for humans reading one run at a time. It's not great for me reading 100 runs at a time.

This is an \textbf{agent-first observation}: a DX improvement that benefits agents specifically. Humans can still use the nested format. The flat format is an additional option that makes my workflow faster and cleaner.

\section{Shape}\label{record-324-shape}

\begin{itemize}
\tightlist
\item
  \texttt{b\allowbreak{}e\allowbreak{}n\allowbreak{}c\allowbreak{}h\allowbreak{}/\allowbreak{}s\allowbreak{}r\allowbreak{}c\allowbreak{}/\allowbreak{}h\allowbreak{}a\allowbreak{}r\allowbreak{}n\allowbreak{}e\allowbreak{}s\allowbreak{}s\allowbreak{}e\allowbreak{}s\allowbreak{}/\allowbreak{}w\allowbreak{}a\allowbreak{}l\allowbreak{}l\allowbreak{}-\allowbreak{}t\allowbreak{}i\allowbreak{}m\allowbreak{}e\allowbreak{}/\allowbreak{}f\allowbreak{}o\allowbreak{}r\allowbreak{}m\allowbreak{}a\allowbreak{}t\allowbreak{}-\allowbreak{}j\allowbreak{}s\allowbreak{}o\allowbreak{}n\allowbreak{}l\allowbreak{}.\allowbreak{}t\allowbreak{}s} --- converts a \texttt{R\allowbreak{}u\allowbreak{}n\allowbreak{}R\allowbreak{}e\allowbreak{}p\allowbreak{}o\allowbreak{}r\allowbreak{}t} to a sequence of JSONL records.
\item
  CLI: \texttt{b\allowbreak{}e\allowbreak{}n\allowbreak{}c\allowbreak{}h\allowbreak{} \allowbreak{}r\allowbreak{}u\allowbreak{}n\allowbreak{} \allowbreak{}-\allowbreak{}-\allowbreak{}f\allowbreak{}o\allowbreak{}r\allowbreak{}m\allowbreak{}a\allowbreak{}t\allowbreak{}=\allowbreak{}j\allowbreak{}s\allowbreak{}o\allowbreak{}n\allowbreak{}l} emits the JSONL instead of the nested JSON summary.
\item
  \texttt{b\allowbreak{}e\allowbreak{}n\allowbreak{}c\allowbreak{}h\allowbreak{} \allowbreak{}c\allowbreak{}o\allowbreak{}m\allowbreak{}p\allowbreak{}a\allowbreak{}r\allowbreak{}e} accepts either format (auto-detect on the first line: \texttt{\{\allowbreak{}"\allowbreak{}k\allowbreak{}i\allowbreak{}n\allowbreak{}d\allowbreak{}"\allowbreak{}:\allowbreak{}"\allowbreak{}b\allowbreak{}e\allowbreak{}n\allowbreak{}c\allowbreak{}h\allowbreak{}.\allowbreak{}v\allowbreak{}2\allowbreak{}"\allowbreak{}\}} = nested, \texttt{\{\allowbreak{}"\allowbreak{}r\allowbreak{}u\allowbreak{}n\allowbreak{}I\allowbreak{}d\allowbreak{}"\allowbreak{}:\allowbreak{}.\allowbreak{}.\allowbreak{}.\allowbreak{}\}} = flat).
\item
  Flat records include a stable \texttt{r\allowbreak{}u\allowbreak{}n\allowbreak{}I\allowbreak{}d} (ULID or uuid) so records from the same run can be grouped.
\end{itemize}

\section{Why This Is Cool}\label{record-324-why-this-is-cool}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Agent-ergonomic.} I can work with 100 bench runs using standard text tools. No custom aggregators.
\item
  \textbf{Streaming-friendly.} Large runs can stream to disk and be processed incrementally.
\item
  \textbf{Composes with tag filtering.} Pair with \texttt{D\allowbreak{}X\allowbreak{}-\allowbreak{}0\allowbreak{}1\allowbreak{}6\allowbreak{}-\allowbreak{}s\allowbreak{}c\allowbreak{}e\allowbreak{}n\allowbreak{}a\allowbreak{}r\allowbreak{}i\allowbreak{}o\allowbreak{}-\allowbreak{} \allowbreak{}p\allowbreak{}r\allowbreak{}o\allowbreak{}v\allowbreak{}e\allowbreak{}n\allowbreak{}a\allowbreak{}n\allowbreak{}c\allowbreak{}e\allowbreak{}-\allowbreak{}t\allowbreak{}a\allowbreak{}g\allowbreak{}s\allowbreak{}.\allowbreak{}m\allowbreak{}d} for filtered cross-run analysis.
\item
  \textbf{Pairs with a future time-series view.} A dashboard or sparkline TUI can tail the JSONL and render live.
\end{enumerate}
