\section{Disposition}\label{record-333-disposition}

Implemented on \texttt{r\allowbreak{}e\allowbreak{}l\allowbreak{}e\allowbreak{}a\allowbreak{}s\allowbreak{}e\allowbreak{}/\allowbreak{}v\allowbreak{}5\allowbreak{}.\allowbreak{}0\allowbreak{}.\allowbreak{}0}. The interactive TUI runtime now switches into a crash surface when \texttt{u\allowbreak{}p\allowbreak{}d\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}(\allowbreak{})} or \texttt{v\allowbreak{}i\allowbreak{}e\allowbreak{}w\allowbreak{}(\allowbreak{})} fails, renders the error, stack, phase, and last stable model snapshot inside the alt screen, and waits for Enter before tearing the terminal down and rethrowing the failure. That turns a lost alt-screen crash into a readable post-mortem without changing the raw runtime contract.

\section{Idea}\label{record-333-idea}

When a TUI app crashes during \texttt{u\allowbreak{}p\allowbreak{}d\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}(\allowbreak{})} or \texttt{v\allowbreak{}i\allowbreak{}e\allowbreak{}w\allowbreak{}(\allowbreak{})}, the \texttt{r\allowbreak{}u\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}m\allowbreak{}e\allowbreak{}.\allowbreak{}t\allowbreak{}s} currently catches the error, writes the stack trace to stderr, and exits. If the app is in alt-screen mode, this stack trace is often lost or obscured by the terminal's screen restoration.

Implement a dedicated ``Error Surface'' that is rendered using Bijou components \emph{before} the alt-screen is exited. This surface should display:

\begin{itemize}
\tightlist
\item
  The error message and stack trace.
\item
  The last stable model snapshot (if serializable).
\item
  A prompt to ``Press Enter to exit.''
\end{itemize}
