\section{Problem}\label{record-328-problem}

Testing nontrivial apps still leaks internal runtime knowledge. Async commands, emitted messages, and lifecycle ordering can be tested today, but the path often requires understanding \texttt{E\allowbreak{}v\allowbreak{}e\allowbreak{}n\allowbreak{}t\allowbreak{}B\allowbreak{}u\allowbreak{}s} details instead of staying at the app boundary.

The 2026-04-11 code-quality audit called for a \texttt{t\allowbreak{}e\allowbreak{}s\allowbreak{}t\allowbreak{}R\allowbreak{}u\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}m\allowbreak{}e\allowbreak{}(\allowbreak{}a\allowbreak{}p\allowbreak{}p\allowbreak{})}-style helper that behaves like a first-class harness rather than a bag of internal seams.

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Provide a \texttt{t\allowbreak{}e\allowbreak{}s\allowbreak{}t\allowbreak{}R\allowbreak{}u\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}m\allowbreak{}e\allowbreak{}(\allowbreak{}a\allowbreak{}p\allowbreak{}p\allowbreak{},\allowbreak{} \allowbreak{}o\allowbreak{}p\allowbreak{}t\allowbreak{}i\allowbreak{}o\allowbreak{}n\allowbreak{}s\allowbreak{})} helper that returns a \texttt{T\allowbreak{}e\allowbreak{}s\allowbreak{}t\allowbreak{}H\allowbreak{}a\allowbreak{}r\allowbreak{}n\allowbreak{}e\allowbreak{}s\allowbreak{}s}.

\end{enumerate}
