\section{Idea}\label{record-342-idea}

Replace the manual \texttt{m\allowbreak{}o\allowbreak{}u\allowbreak{}n\allowbreak{}t\allowbreak{}(\allowbreak{})} / \texttt{m\allowbreak{}a\allowbreak{}p\allowbreak{}C\allowbreak{}m\allowbreak{}d\allowbreak{}s\allowbreak{}(\allowbreak{})} pattern with a compile-time-checked adapter factory:

\begin{CodeBlock}
const adapter = createSubAppAdapter<ParentMsg, ChildMsg>({
  'child-done': (msg) => ({ type: 'panel-closed' }),
  'child-error': (msg) => ({ type: 'show-alert', text: msg.error }),
});
\end{CodeBlock}

TypeScript enforces that every \texttt{C\allowbreak{}h\allowbreak{}i\allowbreak{}l\allowbreak{}d\allowbreak{}M\allowbreak{}s\allowbreak{}g} variant is covered. A forgotten mapping is a compile error, not a silent message drop.

\section{Why}\label{record-342-why}

The current \texttt{m\allowbreak{}a\allowbreak{}p\allowbreak{}C\allowbreak{}m\allowbreak{}d\allowbreak{}s\allowbreak{}(\allowbreak{})} pattern works but requires manual wiring with no type-level guarantee of completeness. In larger apps with multiple sub-apps, a missing mapping causes a message to vanish silently --- the hardest kind of bug to diagnose in a TEA architecture.
