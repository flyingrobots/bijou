\section{Working Loop}\label{record-013-working-loop}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Inspect the work item, linked PRs, and current Git state.
\item
  Sync the merge target and create a descriptive branch without disturbing unrelated local work.
\item
  Define one observable outcome, scope, acceptance checks, and real prerequisites.
\item
  Implement with relevant regression evidence. Use a design record when the change needs a durable technical decision.
\item
  Update affected documentation and the changelog, run the relevant checks, and review the diff.
\item
  Link the work item and PR. Request review when the change is ready.
\item
  After merge, retain the integration link and update the external tracker.
\end{enumerate}

Use focused conventional commits. Do not amend, rebase, force-push, or push to \texttt{m\allowbreak{}a\allowbreak{}i\allowbreak{}n} without explicit authorization. There is no mandatory cycle ceremony, advance shaping commit, sponsor taxonomy, or retrospective template.

\section{GitHub Comment Safety}\label{record-013-github-comment-safety}

Structured review comments often contain Markdown tables, code spans, shell examples, \texttt{\$\allowbreak{}(\allowbreak{})} text, and copied command output. Post those comments through \texttt{-\allowbreak{}-\allowbreak{}b\allowbreak{}o\allowbreak{}d\allowbreak{}y\allowbreak{}-\allowbreak{}f\allowbreak{}i\allowbreak{}l\allowbreak{}e} with a quoted heredoc or a real body file so the shell cannot evaluate the body before GitHub receives it. Do not use inline \texttt{-\allowbreak{}-\allowbreak{}b\allowbreak{}o\allowbreak{}d\allowbreak{}y\allowbreak{} \allowbreak{}"\allowbreak{}.\allowbreak{}.\allowbreak{}.\allowbreak{}"} for self-review findings, Code Lawyer reports, activity summaries, or any other Markdown-heavy comment.

Safe PR comment pattern:

\begin{CodeBlock}
gh pr comment "$PR_NUMBER" --body-file - <<'EOF'
# Self-Code Review

| Severity | Count |
| :--- | ---: |
| P0 | 0 |

Commands stay literal: `npm test`, `gh pr checks`, and $().
EOF
\end{CodeBlock}

Safe issue comment pattern:

\begin{CodeBlock}
gh issue comment "$ISSUE_NUMBER" --body-file - <<'EOF'
Linked artifacts:
- Design: `docs/design/WF-128-safe-gh-comments-and-milestone-items.md`
- Tests: `tests/cycles/WF-128/safe-comments-and-milestone-items.test.ts`
EOF
\end{CodeBlock}

Use a temporary file with \texttt{-\allowbreak{}-\allowbreak{}b\allowbreak{}o\allowbreak{}d\allowbreak{}y\allowbreak{}-\allowbreak{}f\allowbreak{}i\allowbreak{}l\allowbreak{}e\allowbreak{} \allowbreak{}"\allowbreak{}\$\allowbreak{}C\allowbreak{}O\allowbreak{}M\allowbreak{}M\allowbreak{}E\allowbreak{}N\allowbreak{}T\allowbreak{}\_\allowbreak{}B\allowbreak{}O\allowbreak{}D\allowbreak{}Y\allowbreak{}\_\allowbreak{}F\allowbreak{}I\allowbreak{}L\allowbreak{}E\allowbreak{}"} when the comment is generated by a script. Delete the temporary file after the command succeeds.

\section{Context Recovery}\label{record-013-context-recovery}

Start with GitHub issues, milestones, open and recently merged PRs, then the linked Linear items once connected. Read relevant design/release evidence and verify local Git history, status, and worktrees. Repository planning mirrors are retired; tracker state must be read from the tracker.
