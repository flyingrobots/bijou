\section{Framing}\label{record-123-framing}

Key swallowing and priority mistakes are hard to diagnose from outside the runtime. Frame/page binding warnings already proved this seam needs stronger observability; developers should not have to infer routing truth from visible state changes alone.

DX-023 adds a first-party input-routing inspector. The first slice is a pure history and report helper around existing \texttt{R\allowbreak{}u\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}m\allowbreak{}e\allowbreak{}I\allowbreak{}n\allowbreak{}p\allowbreak{}u\allowbreak{}t\allowbreak{}R\allowbreak{}o\allowbreak{}u\allowbreak{}t\allowbreak{}e\allowbreak{}R\allowbreak{}e\allowbreak{}s\allowbreak{}u\allowbreak{}l\allowbreak{}t} facts. Shell integration can feed it live records later without changing the core router.

\section{Sponsored Users}\label{record-123-sponsored-users}

\begin{itemize}
\tightlist
\item
  App authors debugging key priority, shell/page routing, and swallowed input.
\item
  Maintainers investigating runtime routing regressions.
\item
  Agent workflows that need text output for recent input-routing facts.
\end{itemize}

\section{Hills}\label{record-123-hills}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A developer can append routing records to a bounded history and inspect the last N events.
\item
  A maintainer can read a text report that shows event kind, visited views, handler owner, hit target, commands, effects, swallowed input, and no-op handlers.
\item
  A test can render the same report as a surface for docs or debug panes.
\end{enumerate}

\section{Playback Questions}\label{record-123-playback-questions}

\begin{itemize}

\item
  Does the text report distinguish key and pointer events?
\item
  Does the report expose visited views, handled/stopped owner, and hit target?
\item
  Does the report flag swallowed input when routing stops unhandled?
\item
  Does the report flag no-op handlers when an event is handled without commands or effects?
\item
  Does \texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}t\allowbreak{}u\allowbreak{}i} export the inspector API from the source barrel?

\section{Drift Check}\label{record-123-drift-check}

\begin{itemize}
\tightlist
\item
  Scope stayed on a pure inspector helper. The runtime router and frame shell are unchanged.
\item
  Command and effect meaning remains caller-owned. The helper accepts optional labels and otherwise reports counts instead of guessing object semantics.
\item
  Live shell integration remains follow-on work; the first slice provides the data model, bounded history, text report, and surface rendering.
\end{itemize}

\section{Retrospective}\label{record-123-retrospective}

\begin{itemize}
\tightlist
\item
  This complements the layout inspector without coupling to it. Layout explains geometry; input routing explains priority and ownership.
\item
  Keeping labels explicit prevents the inspector from turning command objects into misleading strings.
\end{itemize}
