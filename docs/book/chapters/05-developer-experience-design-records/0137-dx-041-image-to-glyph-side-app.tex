\section{Framing}\label{record-137-framing}

Issue \#305 adds a small, runnable side app that proves image browsing and image-to-glyph rendering as a real workflow instead of only as DOGFOOD title art. The app should use a sidebar file explorer, render the selected image in a main preview pane, let the user hot-swap between Braille and ASCII output, and expose enough tuning controls to discuss how image-to-text filters behave.

The app stays intentionally small: it reuses \texttt{f\allowbreak{}i\allowbreak{}l\allowbreak{}e\allowbreak{}P\allowbreak{}i\allowbreak{}c\allowbreak{}k\allowbreak{}e\allowbreak{}r\allowbreak{}S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}(\allowbreak{})} for the filesystem browser and \texttt{r\allowbreak{}a\allowbreak{}s\allowbreak{}t\allowbreak{}e\allowbreak{}r\allowbreak{}T\allowbreak{}o\allowbreak{}G\allowbreak{}l\allowbreak{}y\allowbreak{}p\allowbreak{}h\allowbreak{}S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}(\allowbreak{})} for glyph rendering. Codec support is dependency-free and scoped to formats the repo can test deterministically.

\section{Hill}\label{record-137-hill}

A user can launch the image viewer, browse supported image files in a sidebar, select an image, and see the main pane render that image as Braille or ASCII glyphs. Pressing \texttt{m} swaps the render mode immediately. The preview pane also supports pan and zoom so a user can inspect image details without leaving the side app. The same pane lets the user preserve sampled image colors, adjust Braille threshold and contrast, and toggle ordered dithering.

\section{Runtime Contract}\label{record-137-runtime-contract}

The app starts in \texttt{a\allowbreak{}s\allowbreak{}s\allowbreak{}e\allowbreak{}t\allowbreak{}s\allowbreak{}/} by default. If the user passes a directory, that directory becomes the file-picker root. If the user passes an image file, the file's parent directory becomes the root and the file starts selected.

Supported input formats:

\begin{itemize}
\tightlist
\item
  SVG: rasterized into a transparent RGBA frame at preview resolution.
\item
  PNG: 8-bit, non-interlaced RGB/RGBA.
\item
  PPM/PNM: \texttt{P\allowbreak{}3} and \texttt{P\allowbreak{}6} RGB Netpbm data.
\end{itemize}

Navigation contract:

\begin{itemize}
\tightlist
\item
  \texttt{j} / \texttt{k}: move file-picker focus.
\item
  \texttt{E\allowbreak{}n\allowbreak{}t\allowbreak{}e\allowbreak{}r}: select focused image or open focused directory.
\item
  \texttt{B\allowbreak{}a\allowbreak{}c\allowbreak{}k\allowbreak{}s\allowbreak{}p\allowbreak{}a\allowbreak{}c\allowbreak{}e}: move the file picker to its parent directory.
\item
  Arrow keys: pan the image viewport.
\item
  \texttt{+} / \texttt{=}: zoom in.
\item
  \texttt{-}: zoom out.
\item
  \texttt{0}: reset to fit.
\item
  \texttt{m} / \texttt{T\allowbreak{}a\allowbreak{}b}: switch Braille and ASCII rendering.
\item
  \texttt{c}: cycle color mode between monochrome, full color, and foreground-only color.
\item
  \texttt{d}: toggle ordered dithering.
\item
  \texttt{[} / \texttt{]}: lower or raise the Braille threshold.
\item
  \texttt{,} / \texttt{.}: lower or raise contrast.
\end{itemize}

The file picker marks focus with \texttt{>} and the rendered image with \texttt{*}. The preview gutter reports zoom percentage, pan offset, color mode, dithering mode, threshold, and contrast. The initial image and every newly selected image start at \texttt{1\allowbreak{}0\allowbreak{}0\allowbreak{}\%} fit, centered horizontally and vertically.

\section{Lower Modes}\label{record-137-lower-modes}

The app is interactive-first. Pipe/static smoke only needs to prove startup and first-frame rendering; the selected path and mode remain ordinary model state for tests.

\section{Accessibility / Assistive Posture}\label{record-137-accessibility-assistive-posture}

The file picker remains textual. The preview pane names the selected file, render mode, format, dimensions, and tuning state so the image is not only communicated by glyph art.

\section{Tests To Write First}\label{record-137-tests-to-write-first}

\begin{itemize}
\tightlist
\item
  RED: PNG decoder cannot map synthetic RGB/RGBA PNGs into RGBA.
\item
  RED: PPM decoder cannot map \texttt{P\allowbreak{}3} and \texttt{P\allowbreak{}6} RGB data into RGBA.
\item
  RED: image viewer starts with an image selected from the root.
\item
  RED: pressing \texttt{m} does not change Braille mode to ASCII mode.
\item
  RED: pressing \texttt{c} does not preserve sampled light and dark image colors on rendered glyph cells.
\item
  RED: threshold, contrast, and dither controls do not change visible tuning state.
\item
  RED: rendered view does not contain the file picker and preview panes.
\end{itemize}

\section{Follow-On Debt}\label{record-137-follow-on-debt}

\begin{itemize}
\tightlist

  Add JPEG/WebP support behind an explicit codec adapter decision.
\item
  Decide whether this app should become part of DOGFOOD or stay an example.
\item
  Promote a first-class image/file-browser block only after the side-app shape proves stable.
\item
  Add error-diffusion algorithms such as Floyd-Steinberg or Atkinson once the ordered-dither baseline has enough usage feedback.
\item
  Add palette quantization and custom charset editing if the side app graduates into a broader image-to-text workbench.
\end{itemize}
