\section{Sponsored Human}\label{record-135-sponsored-human}

A component author wants BlockLab to feel like a real component development product: searchable, controllable, inspectable, test-aware, and useful for building the next Bijou Block without dropping into the full DOGFOOD docs app.

\section{Sponsored Agent}\label{record-135-sponsored-agent}

An agent needs one stable story surface that can produce docs, fixtures, lower-mode captures, interaction playback, visual evidence, source links, and machine-readable reports without scraping terminal frames.

\section{Hill}\label{record-135-hill}

Evolve BlockLab from ``story catalog plus preview'' into a terminal-native component and Block laboratory that borrows the strongest workflows from the current Storybook product without cloning its browser UI.

\section{Lower Modes}\label{record-135-lower-modes}

Pipe mode should expose stable machine-readable sections:

\begin{CodeBlock}
blocklab story notification-system
variant=live-stack
profile=interactive
globals.mode=interactive
globals.locale=en
globals.width=60
args.severity=success
args.count=2

[preview]
release dashboard
Canaries stable in eu-west

[tests]
interaction=pass
a11y=pass
visual=changed +2 lines
\end{CodeBlock}

Accessible mode should prioritize the selected story and active findings:

\begin{CodeBlock}
BlockLab story notification-system. Variant Live stack.
Controls: severity success, count two, compact off.
Globals: interactive mode, English locale, left to right, sixty columns.
Accessibility report passed. Visual report changed by two lines in static mode.
\end{CodeBlock}

\section{Protocol Sketch}\label{record-135-protocol-sketch}

\texttt{C\allowbreak{}o\allowbreak{}m\allowbreak{}p\allowbreak{}o\allowbreak{}n\allowbreak{}e\allowbreak{}n\allowbreak{}t\allowbreak{}S\allowbreak{}t\allowbreak{}o\allowbreak{}r\allowbreak{}y} can grow without breaking existing records by adding optional fields:

\begin{CodeBlock}
interface BlockLabControl {
  readonly id: string;
  readonly label: string;
  readonly kind: 'boolean' | 'number' | 'text' | 'select' | 'color' | 'json';
  readonly defaultValue: unknown;
  readonly options?: readonly unknown[];
}

interface BlockLabGlobals {
  readonly mode?: OutputMode;
  readonly width?: number;
  readonly locale?: string;
  readonly direction?: 'ltr' | 'rtl';
  readonly theme?: string;
  readonly density?: string;
  readonly reducedMotion?: boolean;
}

interface BlockLabPanelReport {
  readonly panelId: string;
  readonly status: 'pass' | 'warn' | 'fail' | 'info';
  readonly facts: readonly ExplanationFact[];
  readonly output: string;
}
\end{CodeBlock}

The first implementation should keep these fields optional and derive defaults from the current profile presets.

\section{Feature Slices}\label{record-135-feature-slices}

\subsection{1. Args/Controls}\label{record-135-argscontrols}

Add serializable controls to stories and a control pane in BlockLab.

Proof:

\begin{itemize}
\tightlist
\item
  controls render in TUI and lower modes
\item
  control changes feed story render input deterministically
\item
  CLI output includes selected args
\end{itemize}

\subsection{2. Globals/Toolbars}\label{record-135-globalstoolbars}

Add global context for mode, width, locale, direction, theme, density, and reduced motion.

Proof:

\begin{itemize}
\tightlist
\item
  global state affects preview context
\item
  lower modes report globals
\item
  locale/direction changes route through DOGFOOD localization ports
\end{itemize}

\subsection{3. Decorators/Harnesses}\label{record-135-decoratorsharnesses}

Add a story harness chain for common setup: AppFrame, providers, mock IO, binding snapshots, theme, and viewport.

Proof:

\begin{itemize}
\tightlist
\item
  harnesses compose without mutating base context
\item
  a story can declare provider data without bespoke preview code
\end{itemize}

\subsection{4. Docs Blocks}\label{record-135-docs-blocks}

Replace fixed markdown assembly with docs block composition.

Proof:

\begin{itemize}
\tightlist
\item
  docs view can show source, controls, lowerings, story matrix, and related stories as separate inspectable blocks
\item
  pipe mode can emit those blocks in deterministic order
\end{itemize}

\subsection{5. Addon-Like Panels}\label{record-135-addon-like-panels}

Introduce panel slots for actions/events, accessibility facts, visual diffs, performance facts, binding state, and source.

Proof:

\begin{itemize}
\tightlist
\item
  each panel has a stable id and lower-mode report
\item
  disabled panels do not affect preview rendering
\end{itemize}

\subsection{6. Interaction Playback}\label{record-135-interaction-playback}

Let stories declare deterministic play steps that can run in BlockLab, CI, and text-first output.

Proof:

\begin{itemize}
\tightlist
\item
  RED/GREEN tests for one story-local playback
\item
  playback report includes steps, status, elapsed time, and artifacts
\end{itemize}

\subsection{7. Composition}\label{record-135-composition}

Allow BlockLab to import multiple story catalogs.

Proof:

\begin{itemize}
\tightlist
\item
  composed catalogs preserve package/source facts
\item
  duplicate story ids fail loudly
\item
  CLI can filter by package, family, tag, and source
\end{itemize}

\section{Accessibility / Assistive Posture}\label{record-135-accessibility-assistive-posture}

BlockLab parity must improve lower-mode truth, not just add visual panels. Every product feature needs accessible and pipe output:

\begin{itemize}
\tightlist
\item
  controls list active values
\item
  globals list current context
\item
  panels list status and findings
\item
  interactions list steps and outcomes
\item
  visual reports describe line/cell differences
\item
  docs blocks preserve heading order
\end{itemize}

\section{Localization / Directionality Posture}\label{record-135-localization-directionality-posture}

Controls and globals are visible UI. Labels, panel names, and status text must go through DOGFOOD localization when they appear in DOGFOOD-owned surfaces. Story ids, arg ids, and artifact paths remain machine tokens.

Directionality belongs in globals. RTL preview should be a first-class context state, not a separate story variant unless the variant is semantically different.

\section{Tests To Write First}\label{record-135-tests-to-write-first}

\begin{itemize}

\item

\item

\item

\section{Non-Goals}\label{record-135-non-goals}

\begin{itemize}
\tightlist
\item
  No browser Storybook runtime.
\item
  No direct addon API compatibility promise.
\item
  No screenshots-only acceptance criteria.
\item
  No story catalog fork separate from DOGFOOD story truth.
\item
  No hidden global registry.
\end{itemize}

\section{Retrospective Target}\label{record-135-retrospective-target}

BlockLab is product-grade when a maintainer can open one terminal workbench, adjust story inputs, switch global context, read generated docs, run playback, inspect a11y/visual/performance findings, and export deterministic evidence for CI or agents.
