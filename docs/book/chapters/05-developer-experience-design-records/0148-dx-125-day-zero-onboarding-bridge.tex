\section{Sponsor Human}\label{record-148-sponsor-human}

A first-time TypeScript reader who wants to see useful output quickly, then learn the next app shape without reverse-engineering DOGFOOD.

\section{Sponsor Agent}\label{record-148-sponsor-agent}

A code-generation agent that needs public docs to explain package boundaries, Surface/TEA/Cmd concepts, render tradeoffs, and the right next guide without hidden repo memory.

\section{Hill}\label{record-148-hill}

The README moves from first visible output to a small framed app path before asking readers to absorb the full architecture or DOGFOOD implementation.

\section{Scope}\label{record-148-scope}

\begin{itemize}
\tightlist
\item
  Move GUIDE and documentation map discovery near the top of README.
\item
  Explain the first app imports by package boundary.
\item
  Stage Surface, App, Msg, Cmd, and framed-shell concepts.
\item
  Add \texttt{n\allowbreak{}p\allowbreak{}m\allowbreak{} \allowbreak{}r\allowbreak{}u\allowbreak{}n\allowbreak{} \allowbreak{}a\allowbreak{}p\allowbreak{}p\allowbreak{}-\allowbreak{}f\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e} as an intermediate command.
\item
  Add a framed app tutorial that teaches header, status, navigation, detail, overlay, and shell commands with the compact existing example.
\item
  Document package split and render-pipeline tradeoffs where readers encounter those concepts.
\end{itemize}

\section{Playback Questions}\label{record-148-playback-questions}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Can a reader reach visible output from the README without first reading architecture docs?
\item
  Can the same reader find GUIDE and the docs map before scrolling deep into the README?
\item
  Is there a clear path from counter to a framed app before DOGFOOD?
\item
  Do docs explain why package imports are split?
\end{enumerate}

\section{Accessibility / Assistive Reading Posture}\label{record-148-accessibility-assistive-reading-posture}

The bridge uses short sections, tables, and command blocks so readers can scan for the next action. It avoids requiring long prose before the first command.

\section{Localization / Directionality Posture}\label{record-148-localization-directionality-posture}

No runtime localization changes. Documentation text remains English.

\section{Agent Inspectability / Explainability Posture}\label{record-148-agent-inspectability-explainability-posture}

The public README, GUIDE, docs map, package development guide, and render pipeline guide carry the explanation agents need to generate correct examples.

\section{Linked Invariants}\label{record-148-linked-invariants}

\begin{itemize}
\tightlist
\item
  First value should appear before deep architecture.
\item
  DOGFOOD remains the canonical docs app, but it is not the first learning step.
\item
  Package boundaries should be explained at the point of first import.
\end{itemize}

\section{Decisions}\label{record-148-decisions}

\begin{itemize}
\tightlist
\item
  Keep \texttt{n\allowbreak{}p\allowbreak{}m\allowbreak{} \allowbreak{}r\allowbreak{}u\allowbreak{}n\allowbreak{} \allowbreak{}h\allowbreak{}e\allowbreak{}l\allowbreak{}l\allowbreak{}o} as the lowest-friction first visible output.
\item
  Keep \texttt{n\allowbreak{}p\allowbreak{}m\allowbreak{} \allowbreak{}r\allowbreak{}u\allowbreak{}n\allowbreak{} \allowbreak{}c\allowbreak{}o\allowbreak{}u\allowbreak{}n\allowbreak{}t\allowbreak{}e\allowbreak{}r} as the first interactive app.
\item
  Add \texttt{n\allowbreak{}p\allowbreak{}m\allowbreak{} \allowbreak{}r\allowbreak{}u\allowbreak{}n\allowbreak{} \allowbreak{}a\allowbreak{}p\allowbreak{}p\allowbreak{}-\allowbreak{}f\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e} between counter and DOGFOOD.
\item
  Do not make DOGFOOD smaller; teach the bridge before DOGFOOD.
\end{itemize}
