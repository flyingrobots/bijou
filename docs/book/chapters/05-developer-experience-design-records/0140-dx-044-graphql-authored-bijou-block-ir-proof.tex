This cycle is the first implementation proof after the \texttt{u\allowbreak{}i\allowbreak{}-\allowbreak{}s\allowbreak{}c\allowbreak{}e\allowbreak{}n\allowbreak{}e\allowbreak{}-\allowbreak{}i\allowbreak{}r\allowbreak{}/\allowbreak{}1} runtime seed. It should not try to make every Bijou block GraphQL-authored. It should prove one boring, deterministic vertical slice that future Wesley and Geordi work can replace or extend without changing the proof contract.

\section{Decision Summary}\label{record-140-decision-summary}

Bijou should treat GraphQL SDL as an authoring surface for portable block semantics, not as a runtime data store and not as a visual scene graph.

The first flow is:

\begin{CodeBlock}
GraphQL SDL fixture
  -> bijou-block/1 artifact
    -> ui-scene-ir/1
      -> Bijou terminal Surface proof
        -> ui-scene-receipt/1
\end{CodeBlock}

The first slice stays inside Bijou. Geordi remains a named endpoint target, but this cycle does not require Geordi repository changes unless the Bijou proof needs a companion endpoint fixture.

\section{Sponsored Human}\label{record-140-sponsored-human}

A Bijou author wants to define a small UI block in a declarative source format and get a deterministic block artifact, scene IR, terminal output, source map, and receipt without hand-maintaining parallel JSON fixtures.

\section{Sponsored Agent}\label{record-140-sponsored-agent}

An agent wants to inspect the GraphQL source, generated block artifact, \texttt{u\allowbreak{}i\allowbreak{}-\allowbreak{}s\allowbreak{}c\allowbreak{}e\allowbreak{}n\allowbreak{}e\allowbreak{}-\allowbreak{}i\allowbreak{}r\allowbreak{}/\allowbreak{}1}, terminal cell source map, and receipt hashes to understand exactly which source field produced each visible terminal fact.

\section{Hill}\label{record-140-hill}

Given a constrained GraphQL SDL file for one text-first Bijou block, Bijou can produce a stable \texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}b\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}/\allowbreak{}1} artifact, lower it into \texttt{u\allowbreak{}i\allowbreak{}-\allowbreak{}s\allowbreak{}c\allowbreak{}e\allowbreak{}n\allowbreak{}e\allowbreak{}-\allowbreak{}i\allowbreak{}r\allowbreak{}/\allowbreak{}1}, render it to a terminal \texttt{S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e}, and emit a receipt whose source maps, tokens, i18n keys, actions, bindings, and hashes are deterministic.

\section{Playback Questions}\label{record-140-playback-questions}

This design is successful only if the committed proof lets a maintainer or agent answer the following questions from repository facts:

\begin{itemize}
\tightlist
\item
  Can a reader trace one SDL field through \texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}b\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}/\allowbreak{}1}, \texttt{u\allowbreak{}i\allowbreak{}-\allowbreak{}s\allowbreak{}c\allowbreak{}e\allowbreak{}n\allowbreak{}e\allowbreak{}-\allowbreak{}i\allowbreak{}r\allowbreak{}/\allowbreak{}1}, terminal cells, and receipt dependencies?
\item
  Can whitespace-only SDL edits preserve the block artifact hash and scene hash?
\item
  Can unsupported or duplicate identities fail before terminal lowering produces a misleading witness?
\item
  Can an agent inspect source-map, token, i18n, action, and binding facts without scraping a screenshot?
\end{itemize}

\section{First SDL Shape}\label{record-140-first-sdl-shape}

The first SDL subset is intentionally explicit:

\begin{CodeBlock}
type ReleaseTitle
  @bijouBlock(id: "release.title", component: "ReleaseTitleBlock")
  @bijouTarget(kind: "bijou-terminal", cols: 40, rows: 5) {
  heading: String!
    @bijouText(id: "heading", x: 2, y: 1)
    @bijouI18n(key: "release.title.heading", fallback: "Bijou")
    @bijouToken(fg: "semantic.title.fg")

  openNotes: String
    @bijouAction(id: "release.openNotes", command: "release.openNotes", key: "Enter")
    @bijouText(id: "open-notes", x: 2, y: 3)
    @bijouI18n(key: "release.title.openNotes", fallback: "Open release notes")
    @bijouToken(fg: "semantic.action.fg", bg: "semantic.action.bg")
}
\end{CodeBlock}

The subset allows only:

\begin{itemize}
\tightlist
\item
  one \texttt{t\allowbreak{}y\allowbreak{}p\allowbreak{}e}
\item
  type directives on the type declaration or following indented lines before \texttt{\{}
\item
  scalar fields
\item
  field directives on following indented lines
\item
  string and integer directive arguments
\end{itemize}

That is small enough to parse deterministically without pretending to be a general GraphQL compiler.

\section{Binding Directive Shape}\label{record-140-binding-directive-shape}

Bindings use field directives because they attach authoring source to one renderable field:

\begin{CodeBlock}
status: String
  @bijouText(id: "status", x: 2, y: 3)
  @bijouBind(
    id: "release.status.value",
    kind: "state",
    path: "release.status",
    targetProperty: "text",
    when: "release.visible"
  )
\end{CodeBlock}

The first slice treats binding directives as fact records, not live dataflow. \texttt{k\allowbreak{}i\allowbreak{}n\allowbreak{}d} is intentionally constrained to source categories such as \texttt{s\allowbreak{}t\allowbreak{}a\allowbreak{}t\allowbreak{}e}, \texttt{q\allowbreak{}u\allowbreak{}e\allowbreak{}r\allowbreak{}y}, and \texttt{c\allowbreak{}o\allowbreak{}m\allowbreak{}p\allowbreak{}u\allowbreak{}t\allowbreak{}e\allowbreak{}d}. \texttt{p\allowbreak{}a\allowbreak{}t\allowbreak{}h} identifies the external source fact. \texttt{t\allowbreak{}a\allowbreak{}r\allowbreak{}g\allowbreak{}e\allowbreak{}t\allowbreak{}P\allowbreak{}r\allowbreak{}o\allowbreak{}p\allowbreak{}e\allowbreak{}r\allowbreak{}t\allowbreak{}y} defaults to \texttt{t\allowbreak{}e\allowbreak{}x\allowbreak{}t} when omitted. \texttt{w\allowbreak{}h\allowbreak{}e\allowbreak{}n} is optional and records the gating condition that a later runtime or endpoint may evaluate.

\section{Artifact Contract}\label{record-140-artifact-contract}

The first generated artifact is:

\begin{CodeBlock}
bijou-block/1
  id
  component
  sourceHash
  fields[]
    fieldName
    nodeId
    text
    action
    binding
    token refs
    source
  targetProfiles[]
\end{CodeBlock}

\texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}b\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}/\allowbreak{}1} is semantic. It is not the same thing as Geordi IR and it is not the same thing as a final \texttt{S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e}.

\section{Lowering Contract}\label{record-140-lowering-contract}

\texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}b\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}/\allowbreak{}1\allowbreak{} \allowbreak{}-\allowbreak{}>\allowbreak{} \allowbreak{}u\allowbreak{}i\allowbreak{}-\allowbreak{}s\allowbreak{}c\allowbreak{}e\allowbreak{}n\allowbreak{}e\allowbreak{}-\allowbreak{}i\allowbreak{}r\allowbreak{}/\allowbreak{}1} must preserve:

\begin{itemize}
\tightlist
\item
  source hash
\item
  node ids
\item
  component ids
\item
  i18n keys and fallbacks
\item
  token references
\item
  action ids, commands, keybindings, and targets
\item
  binding facts when present
\item
  source-map facts from SDL field anchors to IR nodes
\item
  target profile facts
\end{itemize}

If the source asks for unsupported target facts, the compiler must fail before lowering.

\section{Source Map Posture}\label{record-140-source-map-posture}

Source strings should be stable and local to the input. The first slice uses semantic anchors instead of line and column positions so formatting-only SDL edits do not change the artifact or scene hash:

\begin{CodeBlock}
release-title.graphql#type.ReleaseTitle.field.heading
\end{CodeBlock}

Absolute paths are not allowed in emitted artifacts. The caller may provide a \texttt{s\allowbreak{}o\allowbreak{}u\allowbreak{}r\allowbreak{}c\allowbreak{}e\allowbreak{}N\allowbreak{}a\allowbreak{}m\allowbreak{}e} option, but the default should be a neutral \texttt{i\allowbreak{}n\allowbreak{}l\allowbreak{}i\allowbreak{}n\allowbreak{}e\allowbreak{}.\allowbreak{}g\allowbreak{}r\allowbreak{}a\allowbreak{}p\allowbreak{}h\allowbreak{}q\allowbreak{}l}.

\section{Agent Inspectability}\label{record-140-agent-inspectability}

The useful debug path should be:

\begin{CodeBlock}
SDL field -> bijou-block/1 field -> ui-scene-ir/1 node -> Surface cell -> receipt
\end{CodeBlock}

An agent should not need a screenshot to answer:

\begin{itemize}
\tightlist
\item
  Which SDL field produced this node?
\item
  Which node produced this terminal cell?
\item
  Which i18n key and token refs were used?
\item
  Which action or binding belongs to the rendered text?
\item
  Which hash proves the scene and terminal output?
\end{itemize}

\section{Accessibility And Localization Posture}\label{record-140-accessibility-and-localization-posture}

This first slice preserves localization keys and fallbacks but does not add new runtime translation behavior. The source author must provide fallback text for renderable text nodes. Directionality is deferred until multiline text and localized layout constraints exist in the IR.

\section{Geordi Posture}\label{record-140-geordi-posture}

Geordi is the likely next endpoint after this Bijou-only proof. The first Geordi-facing shape should be a receipt-compatible endpoint facet, not a semantic replacement for \texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}b\allowbreak{}l\allowbreak{}o\allowbreak{}c\allowbreak{}k\allowbreak{}/\allowbreak{}1}.

Expected later flow:

\begin{CodeBlock}
bijou-block/1
  -> ui-scene-ir/1
    -> Geordi endpoint profile
      -> browser/image/packed-cell witness
\end{CodeBlock}
