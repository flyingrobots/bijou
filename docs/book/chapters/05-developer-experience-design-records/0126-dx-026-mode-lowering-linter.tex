\section{Framing}\label{record-126-framing}

Bijou treats \texttt{i\allowbreak{}n\allowbreak{}t\allowbreak{}e\allowbreak{}r\allowbreak{}a\allowbreak{}c\allowbreak{}t\allowbreak{}i\allowbreak{}v\allowbreak{}e}, \texttt{s\allowbreak{}t\allowbreak{}a\allowbreak{}t\allowbreak{}i\allowbreak{}c}, \texttt{p\allowbreak{}i\allowbreak{}p\allowbreak{}e}, and \texttt{a\allowbreak{}c\allowbreak{}c\allowbreak{}e\allowbreak{}s\allowbreak{}s\allowbreak{}i\allowbreak{}b\allowbreak{}l\allowbreak{}e} as real output contracts, not skins. Rich output can use layout, color, borders, animation, and symbols, but lower modes still need to preserve the semantic truth a human or agent needs to understand the component.

DX-026 adds a pure diagnostic helper for mode-lowering fidelity. The first slice does not parse rendered text or own component rendering. Instead, component authors supply the semantic facts each mode promises to preserve, and Bijou reports missing or collapsed facts in a stable format.

\section{Sponsored Users}\label{record-126-sponsored-users}

\begin{itemize}
\tightlist
\item
  Component authors proving a custom component lowers honestly.
\item
  Maintainers reviewing regressions in \texttt{p\allowbreak{}i\allowbreak{}p\allowbreak{}e} and \texttt{a\allowbreak{}c\allowbreak{}c\allowbreak{}e\allowbreak{}s\allowbreak{}s\allowbreak{}i\allowbreak{}b\allowbreak{}l\allowbreak{}e} output.
\item
  Agent workflows that need deterministic diagnostics instead of screenshots.
\end{itemize}

\section{Hills}\label{record-126-hills}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A component author can compare semantic facts across rich, static, pipe, and accessible outputs without matching visual text.
\item
  A maintainer can identify which mode dropped a required entity, count, state, label, edge, or custom fact.
\item
  A test can assert a compact report, then render that report as stable text for docs or review comments.
\end{enumerate}

\section{Playback Questions}\label{record-126-playback-questions}

\begin{itemize}
\tightlist
\item
  Can a caller define a baseline mode and compare every other mode to it?
\item
  Does the helper report missing facts per mode with fact kind and key?
\item
  Does the helper report changed fact values for counts, states, or other value-bearing facts?
\item
  Does the helper report collapsed duplicate facts inside a mode?
\item
  Can callers mark a fact as optional so intentional omissions do not warn?
\item
  Can callers add component-specific assertion results to the same report?
\item
  Does \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u} export the helper and its report types?
\end{itemize}

\section{Requirements}\label{record-126-requirements}

\begin{itemize}
\tightlist
\item
  Add \texttt{l\allowbreak{}i\allowbreak{}n\allowbreak{}t\allowbreak{}M\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{}L\allowbreak{}o\allowbreak{}w\allowbreak{}e\allowbreak{}r\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}(\allowbreak{}o\allowbreak{}p\allowbreak{}t\allowbreak{}i\allowbreak{}o\allowbreak{}n\allowbreak{}s\allowbreak{})} to \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u}.
\item
  Add \texttt{m\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{}L\allowbreak{}o\allowbreak{}w\allowbreak{}e\allowbreak{}r\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}R\allowbreak{}e\allowbreak{}p\allowbreak{}o\allowbreak{}r\allowbreak{}t\allowbreak{}T\allowbreak{}e\allowbreak{}x\allowbreak{}t\allowbreak{}(\allowbreak{}r\allowbreak{}e\allowbreak{}p\allowbreak{}o\allowbreak{}r\allowbreak{}t\allowbreak{})} for deterministic diagnostics.
\item
  Support fact kinds for \texttt{e\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}t\allowbreak{}y}, \texttt{e\allowbreak{}d\allowbreak{}g\allowbreak{}e}, \texttt{c\allowbreak{}o\allowbreak{}u\allowbreak{}n\allowbreak{}t}, \texttt{l\allowbreak{}a\allowbreak{}b\allowbreak{}e\allowbreak{}l}, \texttt{s\allowbreak{}t\allowbreak{}a\allowbreak{}t\allowbreak{}e}, and \texttt{c\allowbreak{}u\allowbreak{}s\allowbreak{}t\allowbreak{}o\allowbreak{}m}.
\item
  Treat baseline facts as required unless \texttt{r\allowbreak{}e\allowbreak{}q\allowbreak{}u\allowbreak{}i\allowbreak{}r\allowbreak{}e\allowbreak{}d\allowbreak{}:\allowbreak{} \allowbreak{}f\allowbreak{}a\allowbreak{}l\allowbreak{}s\allowbreak{}e}.
\item
  Report missing required baseline facts in lower modes.
\item
  Report changed required fact values in lower modes.
\item
  Report duplicate fact keys inside a mode as collapsed semantics.
\item
  Accept custom assertion results so component tests can attach domain-specific failures without a second reporting format.
\end{itemize}

\section{Acceptance Criteria}\label{record-126-acceptance-criteria}

\begin{itemize}
\tightlist
\item
  RED tests fail before implementation and pass after.
\item
  Reports include checked modes, issue severities, fact keys, and messages.
\item
  Optional facts are ignored when absent from a lower mode.
\item
  Duplicate facts are reported deterministically.
\item
  Docs and changelog describe the helper.
\end{itemize}

\item

\section{Drift Check}\label{record-126-drift-check}

\begin{itemize}
\tightlist
\item
  Scope narrowed from a static source-code linter to a pure semantic diagnostic helper. That is the right first slice because components already know their runtime semantic facts, while parsing rendered text or source files would add brittle inference.
\item
  The helper reports missing facts, changed fact values, duplicate facts, and custom assertion failures. It does not try to decide whether a glyph or phrase is visually equivalent.
\item
  \texttt{i\allowbreak{}n\allowbreak{}t\allowbreak{}e\allowbreak{}r\allowbreak{}a\allowbreak{}c\allowbreak{}t\allowbreak{}i\allowbreak{}v\allowbreak{}e} is the default baseline when present; otherwise the first supplied mode becomes the baseline.
\end{itemize}

\section{Playback}\label{record-126-playback}

\begin{itemize}
\tightlist
\item
  \texttt{l\allowbreak{}i\allowbreak{}n\allowbreak{}t\allowbreak{}M\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{}L\allowbreak{}o\allowbreak{}w\allowbreak{}e\allowbreak{}r\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}(\allowbreak{})} compares supplied mode facts against a baseline and returns a structured report with checked modes, issue severities, fact kinds, fact keys, and pass/fail status.
\item
  Optional baseline facts with \texttt{r\allowbreak{}e\allowbreak{}q\allowbreak{}u\allowbreak{}i\allowbreak{}r\allowbreak{}e\allowbreak{}d\allowbreak{}:\allowbreak{} \allowbreak{}f\allowbreak{}a\allowbreak{}l\allowbreak{}s\allowbreak{}e} can be omitted by lower modes without warning.
\item
  Duplicate fact identities inside a mode are reported as collapsed semantics.
\item
  Failed custom assertions are folded into the same report.
\item
  \texttt{m\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{}L\allowbreak{}o\allowbreak{}w\allowbreak{}e\allowbreak{}r\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}R\allowbreak{}e\allowbreak{}p\allowbreak{}o\allowbreak{}r\allowbreak{}t\allowbreak{}T\allowbreak{}e\allowbreak{}x\allowbreak{}t\allowbreak{}(\allowbreak{})} renders deterministic text for tests, docs, and review comments.
\item
  \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u} exports the helper and report types from the root barrel.
\end{itemize}

\section{Retrospective}\label{record-126-retrospective}

\begin{itemize}
\tightlist
\item
  The important boundary is explicit runtime truth. Component authors supply facts like \texttt{e\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}t\allowbreak{}y\allowbreak{}:\allowbreak{}s\allowbreak{}a\allowbreak{}v\allowbreak{}e\allowbreak{}-\allowbreak{}b\allowbreak{}u\allowbreak{}t\allowbreak{}t\allowbreak{}o\allowbreak{}n} or \texttt{c\allowbreak{}o\allowbreak{}u\allowbreak{}n\allowbreak{}t\allowbreak{}:\allowbreak{}r\allowbreak{}o\allowbreak{}w\allowbreak{}s\allowbreak{}=\allowbreak{}3}; the helper checks fidelity without coupling itself to a renderer, AST, or screenshot.
\item
  This composes with DOGFOOD stories and future replay tooling: both can attach semantic facts to rendered variants and use the same report format.
\end{itemize}
