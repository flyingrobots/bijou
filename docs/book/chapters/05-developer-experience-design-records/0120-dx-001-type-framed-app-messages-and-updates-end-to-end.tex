\section{Why this cycle existed}\label{record-120-why-this-cycle-existed}

Remove the \texttt{a\allowbreak{}n\allowbreak{}y} cascade around \texttt{c\allowbreak{}r\allowbreak{}e\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}F\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e\allowbreak{}d\allowbreak{}A\allowbreak{}p\allowbreak{}p\allowbreak{}(\allowbreak{})} and framed-page update flows.

\section{Why}\label{record-120-why}

Current framed-app typing forces consumers into casts and lint debt:

\begin{itemize}
\tightlist
\item
  \texttt{F\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e\allowbreak{}P\allowbreak{}a\allowbreak{}g\allowbreak{}e} effectively types page \texttt{m\allowbreak{}s\allowbreak{}g} as \texttt{a\allowbreak{}n\allowbreak{}y}
\item
  framed update results are difficult to type from the outside
\item
  \texttt{F\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e\allowbreak{}M\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{}l\allowbreak{}<\allowbreak{}M\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{}l\allowbreak{}>} exists, but the consumer-facing API does not make it easy to stay fully typed
\end{itemize}

The result is that a strongly typed app can lose its message-model precision at the shell seam.

\section{Captured feedback}\label{record-120-captured-feedback}

From \texttt{w\allowbreak{}a\allowbreak{}r\allowbreak{}p\allowbreak{}-\allowbreak{}t\allowbreak{}t\allowbreak{}d} TUI development:

\begin{itemize}
\tightlist
\item
  \texttt{c\allowbreak{}r\allowbreak{}e\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}F\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e\allowbreak{}d\allowbreak{}A\allowbreak{}p\allowbreak{}p} page update typed as \texttt{(\allowbreak{}m\allowbreak{}s\allowbreak{}g\allowbreak{}:\allowbreak{} \allowbreak{}a\allowbreak{}n\allowbreak{}y\allowbreak{},\allowbreak{} \allowbreak{}m\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{}l\allowbreak{}:\allowbreak{} \allowbreak{}M\allowbreak{}o\allowbreak{}d\allowbreak{}e\allowbreak{}l\allowbreak{})}
\item
  \texttt{f\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e\allowbreak{}d\allowbreak{}A\allowbreak{}p\allowbreak{}p\allowbreak{}.\allowbreak{}u\allowbreak{}p\allowbreak{}d\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}(\allowbreak{})} returns an effectively untyped tuple
\item
  these two seams were the biggest source of lint violations
\end{itemize}

\section{Likely scope}\label{record-120-likely-scope}

\begin{itemize}
\tightlist
\item
  make framed-page message typing generic and public
\item
  make framed update return types explicit and consumable
\item
  remove or reduce the need for external \texttt{a\allowbreak{}n\allowbreak{}y} casts at the shell seam
\item
  add tests proving end-to-end typed message unions survive framed app composition
\end{itemize}

\section{Outcome}\label{record-120-outcome}

This work landed and is reflected in \href{https://github.com/flyingrobots/bijou/blob/cbd70612140e7a450d764b3c7be1c6af878b99bc/docs/CHANGELOG.md}{CHANGELOG.md}.

The public framed-shell surface now exports explicit typed message and update result helpers, and page updates keep custom message unions typed through the shell seam.
