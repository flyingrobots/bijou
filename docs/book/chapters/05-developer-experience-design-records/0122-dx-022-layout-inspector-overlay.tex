\section{Framing}\label{record-122-framing}

Layout and overlay issues are hard to inspect in situ. Bijou now retains enough runtime geometry that pane bounds, clipping, scroll regions, focus ownership, and z-layer ordering should not stay invisible during development.

DX-022 adds a first-party layout inspector overlay. The first slice is a pure surface helper: apps or framed shells can pass the retained regions they already know about and get a visible overlay plus a plain text report.

\section{Sponsored Users}\label{record-122-sponsored-users}

\begin{itemize}
\tightlist
\item
  App authors debugging split panes, clipped viewports, and mouse hit regions.
\item
  Maintainers investigating shell focus or overlay layering regressions.
\item
  Agent workflows that need a text report of layout truth without screenshot inspection.
\end{itemize}

\section{Hills}\label{record-122-hills}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A developer can composite an inspector over any surface and see region borders, ids, and dimensions without changing the app layout itself.
\item
  A maintainer can mark one region as focused and visually distinguish it from sibling regions.
\item
  A test can ask for a text report that includes rects, clip rects, scroll offsets, focus, and layer ordering.
\end{enumerate}

\section{Playback Questions}\label{record-122-playback-questions}

\section{Acceptance Criteria}\label{record-122-acceptance-criteria}

\begin{itemize}
\tightlist
\item
  Focused tests fail before implementation and pass after.
\item
  The overlay draws borders and labels for visible regions.
\item
  The overlay clips off-screen regions without throwing.
\item
  The text report includes all supplied geometry facts.
\item
  Docs and changelog describe the helper.
\end{itemize}

\section{Drift Check}\label{record-122-drift-check}

\begin{itemize}
\tightlist
\item
  Scope stayed on the first pure helper slice. The runtime did not grow a global toggle, because callers can now compose the inspector over any retained geometry they already own.
\item
  The implementation accepts both debug-friendly \texttt{\{\allowbreak{} \allowbreak{}x\allowbreak{},\allowbreak{} \allowbreak{}y\allowbreak{},\allowbreak{} \allowbreak{}w\allowbreak{}i\allowbreak{}d\allowbreak{}t\allowbreak{}h\allowbreak{},\allowbreak{} \allowbreak{}h\allowbreak{}e\allowbreak{}i\allowbreak{}g\allowbreak{}h\allowbreak{}t\allowbreak{} \allowbreak{}\}} rectangles and Bijou-native \texttt{\{\allowbreak{} \allowbreak{}r\allowbreak{}o\allowbreak{}w\allowbreak{},\allowbreak{} \allowbreak{}c\allowbreak{}o\allowbreak{}l\allowbreak{},\allowbreak{} \allowbreak{}w\allowbreak{}i\allowbreak{}d\allowbreak{}t\allowbreak{}h\allowbreak{},\allowbreak{} \allowbreak{}h\allowbreak{}e\allowbreak{}i\allowbreak{}g\allowbreak{}h\allowbreak{}t\allowbreak{} \allowbreak{}\}} rectangles. That keeps the public helper ergonomic without forcing app-frame internals into the design contract.
\item
  Styling stayed out of the first pass. Plain ASCII borders make the overlay stable in tests, logs, and pipe captures.
\end{itemize}

\section{Retrospective}\label{record-122-retrospective}

\begin{itemize}
\tightlist
\item
  This is useful as a small diagnostic primitive rather than a shell feature. Apps can opt in during tests, demos, or debug modes without changing runtime ownership.
\item
  The native \texttt{L\allowbreak{}a\allowbreak{}y\allowbreak{}o\allowbreak{}u\allowbreak{}t\allowbreak{}R\allowbreak{}e\allowbreak{}c\allowbreak{}t} mismatch was caught by package typecheck after the RED tests went green. Accepting both shapes is the right boundary behavior: app-frame can pass retained layout rects directly, while external tests can use x/y terminology.
\end{itemize}
