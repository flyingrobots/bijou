\section{Why this cycle exists}\label{record-190-why-this-cycle-exists}

LX-002 gave Bijou a real localization tooling core:

\begin{itemize}
\tightlist
\item
  authoring catalogs
\item
  source hashing
\item
  stale detection
\item
  provider-neutral translation rows
\item
  runtime catalog compilation
\item
  pseudo-localization
\end{itemize}

That solved in-memory workflow logic, but not the exchange problem. Real localization work still has to move through:

\begin{itemize}
\tightlist
\item
  spreadsheet-shaped review workflows
\item
  structured handoff bundles
\item
  typed values and references that survive export/import without turning into mush
\end{itemize}

This cycle exists to add a provider-neutral exchange layer to \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}i\allowbreak{}1\allowbreak{}8\allowbreak{}n\allowbreak{}-\allowbreak{}t\allowbreak{}o\allowbreak{}o\allowbreak{}l\allowbreak{}s}.

\section{Scope of this cycle}\label{record-190-scope-of-this-cycle}

This cycle intentionally covers:

\begin{itemize}
\tightlist
\item
  a spreadsheet-friendly workbook model
\item
  typed export/import for translation rows
\item
  a serializable catalog-bundle format for authoring catalogs
\item
  reference-safe encoding/decoding for message/resource/data values
\item
  validation at the exchange boundary
\end{itemize}

It does \textbf{not} include:

\begin{itemize}
\tightlist
\item
  CSV parsing
\item
  XLSX parsing
\item
  Google Sheets integration
\item
  filesystem adapters
\item
  remote services
\item
  runtime i18n changes
\end{itemize}

The goal is to define the exchange seam that those adapters can target later.

\section{Human users}\label{record-190-human-users}

\subsection{Primary human user}\label{record-190-primary-human-user}

A localization maintainer who needs to:

\begin{itemize}
\tightlist
\item
  export translatable work into a spreadsheet-like shape
\item
  import reviewed translations safely
\item
  move full authoring catalogs across tools or repos
\item
  preserve typed values and references without inventing a bespoke format
\end{itemize}

\subsection{Human hill}\label{record-190-human-hill}

A builder can move localization workflow data through spreadsheet-like and bundle-like formats without losing type/reference fidelity or writing their own ad hoc serialization rules.

\section{Agent users}\label{record-190-agent-users}

\subsection{Primary agent user}\label{record-190-primary-agent-user}

An agent helping with localization maintenance and exchange.

It needs to:

\begin{itemize}
\tightlist
\item
  generate workbook-shaped review payloads
\item
  read imported workbook data back into typed translation rows
\item
  exchange full authoring catalogs in a stable serializable form
\item
  validate malformed exchange data before it reaches runtime compilation
\end{itemize}

\subsection{Agent hill}\label{record-190-agent-hill}

An agent can reason about localization exchange through explicit workbook/bundle contracts instead of reverse-engineering spreadsheet columns or raw JSON blobs.

\section{Human playback}\label{record-190-human-playback}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A builder has authoring catalogs in memory.
\item
  They export stale or missing work for \texttt{d\allowbreak{}e} into a workbook-shaped review payload.
\item
  A translator or tool edits the workbook rows.
\item
  The builder imports the workbook back into translation rows and merges it into the authoring catalogs.
\item
  They export the full catalogs as a serializable bundle for storage, transport, or staged review.
\item
  They import the bundle back and compile it into runtime catalogs.
\end{enumerate}

\section{Agent playback}\label{record-190-agent-playback}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  An agent reads authoring catalogs.
\item
  It exports a workbook for a target locale.
\item
  It can inspect typed cells and references explicitly instead of guessing.
\item
  It imports workbook rows back into translation rows.
\item
  It exports/imports full catalog bundles for handoff or normalization.
\item
  It validates malformed references or invalid encoded values before compilation.
\end{enumerate}

\section{Proposed API direction}\label{record-190-proposed-api-direction}

The first slice should be close to:

\begin{CodeBlock}
interface ExchangeWorkbook { ... }
interface ExchangeSheet { ... }
interface ExchangeRow { ... }
interface CatalogBundle { ... }

function exportTranslationWorkbook(
  catalogs: readonly AuthoringCatalog[],
  locale: string,
): ExchangeWorkbook;

function importTranslationWorkbook(
  workbook: ExchangeWorkbook,
): readonly TranslationRow[];

function exportCatalogBundle(
  catalogs: readonly AuthoringCatalog[],
): CatalogBundle;

function importCatalogBundle(
  bundle: CatalogBundle,
): readonly AuthoringCatalog[];
\end{CodeBlock}

Exact names can still move, but the responsibilities should not.

\section{Risks}\label{record-190-risks}

\begin{itemize}
\tightlist
\item
  overfitting the workbook shape to one spreadsheet vendor
\item
  inventing a bundle format that loses reference fidelity
\item
  making the exchange format too magical to validate clearly
\item
  leaking filesystem/provider concerns into the pure tooling package
\end{itemize}

\section{Out of scope}\label{record-190-out-of-scope}

\begin{itemize}

\item
  XLSX readers/writers
\item
  Google Sheets integration
\item
  storage or persistence adapters
\item
  runtime integration beyond proving the roundtripped catalogs still compile cleanly
\end{itemize}
