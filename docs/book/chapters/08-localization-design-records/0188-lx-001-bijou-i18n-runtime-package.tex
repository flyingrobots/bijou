\section{Why this cycle exists}\label{record-188-why-this-cycle-exists}

Bijou now has doctrine for localization and bidirectionality, but no runtime package boundary that applications or shell surfaces can actually consume.

If we want \texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}i\allowbreak{}1\allowbreak{}8\allowbreak{}n} to be a real localization tool, the first step is not spreadsheets.

The first step is a clean, in-memory runtime package.

This cycle intentionally narrows scope to:

\begin{itemize}
\tightlist
\item
  \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}i\allowbreak{}1\allowbreak{}8\allowbreak{}n}
\item
  runtime catalogs
\item
  locale and direction
\item
  runtime-safe lookup and references
\item
  formatting seams
\end{itemize}

It does \textbf{not} try to ship spreadsheet workflows yet.

\section{Human users}\label{record-188-human-users}

\subsection{Primary human user}\label{record-188-primary-human-user}

A builder who wants to localize Bijou shell or app content without inventing their own ad hoc runtime i18n substrate.

They are asking:

\begin{itemize}
\tightlist
\item
  where does locale live?
\item
  where does direction live?
\item
  how do I register catalogs?
\item
  how do I look up a message or resource?
\item
  how do I do this without filesystem or service assumptions?
\end{itemize}

\subsection{Human hill}\label{record-188-human-hill}

A builder can install and use a real \texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}i\allowbreak{}1\allowbreak{}8\allowbreak{}n} runtime package entirely in memory, with a clean catalog model and no spreadsheet baggage.

\section{Agent users}\label{record-188-agent-users}

\subsection{Primary agent user}\label{record-188-primary-agent-user}

An agent that needs to inspect or generate localized UI against explicit runtime contracts instead of hidden string tables.

They are asking:

\begin{itemize}
\tightlist
\item
  what is the active locale?
\item
  what is the active direction?
\item
  what keys and namespaces exist?
\item
  how do references resolve?
\item
  what happens when a translation is missing?
\end{itemize}

\subsection{Agent hill}\label{record-188-agent-hill}

An agent can reason about localized runtime content through explicit catalog, locale, direction, and lookup APIs instead of implicit English defaults.

\section{Human playback}\label{record-188-human-playback}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A builder installs \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}i\allowbreak{}1\allowbreak{}8\allowbreak{}n}.

\item
  They load the catalog into a runtime.
\item
  They resolve messages and resources by key.
\item

\item
  They read direction from the same runtime without inventing a second seam.

\section{Invariants for this cycle}\label{record-188-invariants-for-this-cycle}

\begin{itemize}
\tightlist
\item
  runtime package must work entirely in memory
\item
  runtime package must not assume spreadsheets, files, services, or persistence
\item
  runtime package must expose direction as first-class metadata
\item
  runtime package must be string-first but not string-only
\item
  runtime package must support runtime-safe references without becoming a spreadsheet interpreter
\end{itemize}

\section{Proposed API direction}\label{record-188-proposed-api-direction}

The exact names can still evolve, but the first slice should be close to:

\begin{CodeBlock}
type LocaleDirection = 'ltr' | 'rtl' | 'auto';

interface CatalogKey {
  readonly namespace: string;
  readonly id: string;
}

type CatalogEntryKind = 'message' | 'resource' | 'data';

interface I18nCatalogEntry<T = unknown> {
  readonly key: CatalogKey;
  readonly kind: CatalogEntryKind;
  readonly sourceLocale: string;
  readonly values: Readonly<Record<string, T>>;
  readonly fallbackValue?: T;
}

interface I18nRuntime {
  readonly locale: string;
  readonly direction: LocaleDirection;
  loadCatalog(catalog: I18nCatalog): void;
  unloadCatalog(namespace: string): void;
  t(key: CatalogKey, values?: Record<string, unknown>): string;
  resource<T = unknown>(key: CatalogKey): T | undefined;
}
\end{CodeBlock}

The first slice does not need every possible authoring feature. It does need a clean runtime shape.

\section{Risks}\label{record-188-risks}

\begin{itemize}
\tightlist
\item
  over-designing the runtime around tooling concerns too early
\item
  under-designing the runtime into string-only helpers
\item
  leaking layout or UI overflow policy into the i18n package
\item
  trying to implement tooling and runtime together in one cycle
\end{itemize}

\tightlist
