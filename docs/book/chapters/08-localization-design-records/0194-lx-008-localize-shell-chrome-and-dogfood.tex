\section{Why this cycle exists}\label{record-194-why-this-cycle-exists}

LX-001 through LX-006 built the localization substrate:

\begin{itemize}
\tightlist
\item
  runtime catalogs
\item
  tools and exchange workflows
\item
  filesystem helpers
\item
  XLSX adapters
\end{itemize}

But the humane shell and DOGFOOD still ship mostly hardcoded English copy.

This cycle exists to prove that the i18n work is real in product surfaces:

\begin{itemize}
\tightlist
\item
  shell chrome
\item
  shell overlays and drawers
\item
  DOGFOOD landing and onboarding copy
\end{itemize}

\section{Scope of this cycle}\label{record-194-scope-of-this-cycle}

This cycle intentionally covers:

\begin{itemize}
\tightlist
\item
  a shell-level i18n seam for \texttt{c\allowbreak{}r\allowbreak{}e\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}F\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e\allowbreak{}d\allowbreak{}A\allowbreak{}p\allowbreak{}p\allowbreak{}(\allowbreak{})}
\item
  localized shell-owned defaults such as:

  \begin{itemize}
  \tightlist
  \item
    command palette title
  \item
    default search title
  \item
    settings drawer title
  \item
    quit confirm copy
  \item
    footer notification cue and shell drawer footer hints
  \end{itemize}
\item
  DOGFOOD-localized copy for:

  \begin{itemize}
  \tightlist
  \item
    landing footer and prompt
  \item
    search/settings labels
  \item
    empty-state onboarding copy
  \item
    settings row labels, descriptions, and feedback
  \end{itemize}
\item
  one visible direction-aware shell behavior driven by i18n direction metadata
\end{itemize}

It does \textbf{not} include:

\begin{itemize}
\tightlist
\item
  full generic bidirectional layout support across every shell surface
\item
  localizing every example in the repo
\item
  provider/service adapters
\item
  persistence
\end{itemize}

The point is to prove the localization runtime in the shell and DOGFOOD without pretending RTL support is solved everywhere.

\section{Human users}\label{record-194-human-users}

\subsection{Primary human user}\label{record-194-primary-human-user}

A builder or end user working in a non-English locale.

They need to:

\begin{itemize}
\tightlist
\item
  see shell controls and onboarding copy in their locale
\item
  trust that shell labels, footer hints, and settings copy are not locked to English
\item
  see at least one shell behavior react to logical direction instead of physical left/right assumptions
\end{itemize}

\subsection{Human hill}\label{record-194-human-hill}

A non-English user can enter DOGFOOD and immediately see localized shell/UI copy, while a builder can point to DOGFOOD as proof that Bijou localization is not theoretical.

\section{Agent users}\label{record-194-agent-users}

\subsection{Primary agent user}\label{record-194-primary-agent-user}

An agent integrating or validating localized Bijou surfaces.

It needs to:

\begin{itemize}
\tightlist
\item
  load catalogs into the shell and docs proving surface
\item
  verify localized strings at the rendered shell boundary
\item
  reason about direction-aware shell behavior through explicit runtime metadata
\end{itemize}

\subsection{Agent hill}\label{record-194-agent-hill}

An agent can localize shell chrome and DOGFOOD through explicit i18n contracts instead of editing hardcoded English strings in place.

\section{Human playback}\label{record-194-human-playback}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A builder creates a localized runtime.
\item
  They launch DOGFOOD in that locale.
\item
  The landing footer and prompt use localized copy.
\item
  After entering the docs, the shell drawer titles, search surface, footer hints, and settings copy use localized copy too.
\item
  In an RTL locale, at least one shell drawer placement mirrors logically instead of staying physically fixed.
\end{enumerate}

\section{Agent playback}\label{record-194-agent-playback}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  An agent loads shell and DOGFOOD catalogs into an i18n runtime.
\item
  It passes that runtime into the shell/docs app.
\item
  It verifies localized shell strings in rendered frames.
\item
  It verifies pseudo-localized copy appears in DOGFOOD.
\item
  It verifies direction metadata changes a visible shell behavior.
\end{enumerate}

\section{Invariants for this cycle}\label{record-194-invariants-for-this-cycle}

\begin{itemize}
\tightlist
\item
  \texttt{c\allowbreak{}r\allowbreak{}e\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}F\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e\allowbreak{}d\allowbreak{}A\allowbreak{}p\allowbreak{}p\allowbreak{}(\allowbreak{})} must own shell-localized defaults instead of pushing shell copy responsibility entirely to apps
\item

\section{Deliverable}\label{record-194-deliverable}

Introduce:

\begin{itemize}
\tightlist
\item
  a shell i18n seam in \texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}t\allowbreak{}u\allowbreak{}i}
\item
  a canonical shell catalog for frame-owned copy
\item
  DOGFOOD-localized catalogs and runtime wiring
\end{itemize}

So that shell chrome and DOGFOOD can run against locale/direction metadata instead of hardcoded English strings.

\section{Proposed API direction}\label{record-194-proposed-api-direction}

The first slice should be close to:

\begin{CodeBlock}
interface CreateFramedAppOptions<PageModel, Msg> {
  readonly i18n?: I18nRuntime;
}
\end{CodeBlock}

With:

\begin{itemize}
\tightlist
\item
  a built-in frame-shell catalog exported from \texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}t\allowbreak{}u\allowbreak{}i}
\item
  DOGFOOD creating and using an i18n runtime, loading both shell and docs catalogs
\end{itemize}

Exact names can still move, but the responsibilities should not.

\section{Risks}\label{record-194-risks}

\begin{itemize}
\tightlist
\item
  only partially localizing shell surfaces and leaving confusing English islands
\item
  adding an i18n seam that DOGFOOD does not actually prove
\item
  claiming direction-awareness without any visible shell behavior change
\item
  threading translator functions everywhere instead of defining one shell-localized seam
\end{itemize}

\section{Out of scope}\label{record-194-out-of-scope}

\begin{itemize}

\item

\item
  service-backed localization workflows
\item
  every example app in the repo
\end{itemize}

\subsection{Drift from ideal}\label{record-194-drift-from-ideal}

This cycle proved the shell/runtime seam cleanly, but it did not finish every English island.

Still intentionally incomplete:

\begin{itemize}
\tightlist
\item
  help-overlay keybinding descriptions still mostly fall back to English strings
\item
  notification history/body copy is only partially localized
\item
  direction awareness is real but still narrow; only a subset of shell drawer placement is mirrored so far
\end{itemize}

That drift is acceptable for LX-008 because the point of the cycle was to prove that shell localization and direction metadata are real in product surfaces, not to declare shell localization complete.
