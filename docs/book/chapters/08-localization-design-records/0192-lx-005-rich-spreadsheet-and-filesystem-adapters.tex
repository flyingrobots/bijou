\section{Why this cycle exists}\label{record-192-why-this-cycle-exists}

LX-004 proved the first concrete adapter seam in \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}i\allowbreak{}1\allowbreak{}8\allowbreak{}n\allowbreak{}-\allowbreak{}t\allowbreak{}o\allowbreak{}o\allowbreak{}l\allowbreak{}s}:

\begin{itemize}
\tightlist
\item
  CSV sheet adapters
\item
  TSV sheet adapters
\item
  JSON bundle adapters
\end{itemize}

That still leaves a practical gap for real automation and tooling:

\begin{itemize}
\tightlist
\item
  reading and writing those formats from the filesystem
\item
  handling whole workbooks instead of one sheet string at a time
\end{itemize}

This cycle exists to add the Node-specific filesystem layer on top of the existing exchange seam.

\section{Scope of this cycle}\label{record-192-scope-of-this-cycle}

This cycle intentionally covers:

\begin{itemize}
\tightlist
\item
  a new Node-specific package for filesystem helpers
\item
  reading/writing one \texttt{E\allowbreak{}x\allowbreak{}c\allowbreak{}h\allowbreak{}a\allowbreak{}n\allowbreak{}g\allowbreak{}e\allowbreak{}S\allowbreak{}h\allowbreak{}e\allowbreak{}e\allowbreak{}t} file in CSV or TSV
\item
  reading/writing one \texttt{C\allowbreak{}a\allowbreak{}t\allowbreak{}a\allowbreak{}l\allowbreak{}o\allowbreak{}g\allowbreak{}B\allowbreak{}u\allowbreak{}n\allowbreak{}d\allowbreak{}l\allowbreak{}e} JSON file
\item
  reading/writing a workbook directory made of:

  \begin{itemize}
  \tightlist
  \item
    a manifest file
  \item
    one sheet file per sheet
  \end{itemize}
\end{itemize}

It does \textbf{not} include:

\begin{itemize}
\tightlist
\item
  XLSX
\item
  Google Sheets
\item
  remote services
\item
  zip packaging
\item
  changing the pure \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}i\allowbreak{}1\allowbreak{}8\allowbreak{}n\allowbreak{}-\allowbreak{}t\allowbreak{}o\allowbreak{}o\allowbreak{}l\allowbreak{}s} exchange model
\end{itemize}

The point is to make the current exchange seam practical in Node without dragging platform concerns into the core tooling package.

\section{Human users}\label{record-192-human-users}

\subsection{Primary human user}\label{record-192-primary-human-user}

A builder or localization maintainer who needs to:

\begin{itemize}
\tightlist
\item
  save exchange sheets to disk
\item
  read edited sheets back from disk
\item
  store and reload full catalog bundles
\item
  hand off or restore complete workbooks as a directory artifact
\end{itemize}

\subsection{Human hill}\label{record-192-human-hill}

A builder can persist workbook and bundle exchange artifacts through one small Node helper package, without hand-writing file I/O or inventing an ad hoc workbook directory format.

\section{Agent users}\label{record-192-agent-users}

\subsection{Primary agent user}\label{record-192-primary-agent-user}

An agent automating localization workflows.

It needs to:

\begin{itemize}
\tightlist
\item
  write sheets and bundles to disk
\item
  read them back deterministically
\item
  stage workbook directories for review workflows
\item
  reason about paths and formats explicitly instead of shelling out to one-off scripts
\end{itemize}

\subsection{Agent hill}\label{record-192-agent-hill}

An agent can automate localization exchange through explicit Node adapters instead of rebuilding CSV/TSV/JSON file orchestration in every workflow.

\section{Human playback}\label{record-192-human-playback}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A builder exports a workbook in memory.
\item
  They write it to a directory on disk in TSV or CSV form.
\item
  A tool or person edits the sheet files.
\item
  The builder reads the workbook directory back into memory.
\item
  They import the workbook rows and merge the updates.
\item
  They also save and restore full catalog bundles as JSON files.
\end{enumerate}

\section{Agent playback}\label{record-192-agent-playback}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  An agent exports a workbook.
\item
  It writes the workbook to a directory for review.
\item
  It later reads the workbook directory back.
\item
  It writes and reads catalog bundle files as deterministic JSON artifacts.
\end{enumerate}

\section{Invariants for this cycle}\label{record-192-invariants-for-this-cycle}

\begin{itemize}
\tightlist
\item
  filesystem concerns must stay out of the pure \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}i\allowbreak{}1\allowbreak{}8\allowbreak{}n\allowbreak{}-\allowbreak{}t\allowbreak{}o\allowbreak{}o\allowbreak{}l\allowbreak{}s} package
\item
  Node helpers must build on the existing workbook/bundle seam instead of replacing it
\item
  directory formats must be explicit and versioned
\item
  file helpers must be deterministic about sheet ordering and file names
\item
  richer spreadsheet providers remain out of scope
\end{itemize}

\section{Proposed API direction}\label{record-192-proposed-api-direction}

The first slice should be close to:

\begin{CodeBlock}
function writeExchangeSheetFile(path: string, sheet: ExchangeSheet, format?: DelimitedFormat): Promise<void>;
function readExchangeSheetFile(path: string, format?: DelimitedFormat): Promise<ExchangeSheet>;

function writeCatalogBundleFile(path: string, bundle: CatalogBundle): Promise<void>;
function readCatalogBundleFile(path: string): Promise<CatalogBundle>;

function writeExchangeWorkbookDirectory(
  path: string,
  workbook: ExchangeWorkbook,
  format: DelimitedFormat,
): Promise<void>;

function readExchangeWorkbookDirectory(path: string): Promise<ExchangeWorkbook>;
\end{CodeBlock}

Exact names can still move, but the responsibilities should not.

\item
  missing files fail clearly
\end{itemize}
