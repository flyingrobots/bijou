\section{Why this cycle exists}\label{record-172-why-this-cycle-exists}

DL-004 proved calmer drawer rhythm and structured notice rows in the shell notification center.

The next design-language proof should move into another likely future block candidate:

\begin{itemize}
\tightlist
\item
  guided flows
\item
  explainability walkthroughs
\item
  compact multi-section review surfaces with one obvious next action
\end{itemize}

Inspector panels are still part of the original idea, but they should not share a cycle with guided-flow proof if that forces us to invent two half-finished surfaces.

This cycle exists to prove the guided-flow side first by turning the \href{https://github.com/flyingrobots/bijou/blob/cbd70612140e7a450d764b3c7be1c6af878b99bc/docs/strategy/ai-explainability-standard.md}{AI Explainability Standard} into a canonical component instead of leaving it as doctrine only.

\section{Scope of this cycle}\label{record-172-scope-of-this-cycle}

This cycle intentionally covers:

\begin{itemize}
\tightlist
\item
  one canonical \texttt{e\allowbreak{}x\allowbreak{}p\allowbreak{}l\allowbreak{}a\allowbreak{}i\allowbreak{}n\allowbreak{}a\allowbreak{}b\allowbreak{}i\allowbreak{}l\allowbreak{}i\allowbreak{}t\allowbreak{}y\allowbreak{}(\allowbreak{})} component in \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u}
\item
  explicit \texttt{[\allowbreak{}A\allowbreak{}I\allowbreak{}]} labeling
\item
  separated rationale, evidence, next action, and governance sections
\item
  calm section rhythm for compact guided-flow review surfaces
\item
  graceful lowering into pipe and accessible modes
\end{itemize}

It does \textbf{not} include:

\begin{itemize}
\tightlist
\item
  a generalized guided-flow block runtime
\item
  inspector-panel implementation
\item
  shell integration or notification-center changes
\item
  service-backed AI integrations
\end{itemize}

\section{Human users}\label{record-172-human-users}

\subsection{Primary human user}\label{record-172-primary-human-user}

A builder or app user reviewing an AI-mediated recommendation.

They need:

\begin{itemize}
\tightlist
\item
  visible \texttt{[\allowbreak{}A\allowbreak{}I\allowbreak{}]} labeling
\item
  an explanation of why the recommendation exists
\item
  evidence separated from the recommendation itself
\item
  one clear next action
\item
  a calm surface instead of a decorative wall of text
\end{itemize}

\subsection{Human hill}\label{record-172-human-hill}

A user can read an AI-mediated recommendation and answer what it is, why it is here, what evidence supports it, and what they should do next without feeling like they are parsing marketing copy.

\section{Agent users}\label{record-172-agent-users}

\subsection{Primary agent user}\label{record-172-primary-agent-user}

An agent generating or auditing guided-flow and explainability surfaces in Bijou.

It needs:

\begin{itemize}
\tightlist
\item
  one canonical explainability component to target
\item
  explicit section structure rather than ad hoc copy blocks
\item
  proof that guided-flow rhythm follows the design language and AI doctrine
\end{itemize}

\subsection{Agent hill}\label{record-172-agent-hill}

An agent can point to one reusable explainability surface and show that Bijou's \texttt{[\allowbreak{}A\allowbreak{}I\allowbreak{}]}, rationale, evidence, and next-action doctrine is real code instead of only prose.

\section{Human playback}\label{record-172-human-playback}

\section{Invariants for this cycle}\label{record-172-invariants-for-this-cycle}

\begin{itemize}
\tightlist
\item
  AI-mediated explainability surfaces must mark themselves explicitly
\item
  evidence must not be merged into recommendation copy
\item
  the surface must present one obvious next action when that data exists
\item
  pipe and accessible modes must preserve the same meaning without relying on borders or color
\item
  this cycle must prove one canonical guided-flow surface before returning to inspector panels
\end{itemize}

\subsection{Drift from ideal}\label{record-172-drift-from-ideal}

Inspector-panel proof work did not land in this cycle.

That was intentional and correct.

Trying to prove guided-flow and inspector language in the same cycle would have forced two half-finished surfaces instead of one canonical explainability component.
