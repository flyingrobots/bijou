\section{Why this cycle exists}\label{record-170-why-this-cycle-exists}

DL-002 makes the pattern and block language explicit.

The next step should prove that those patterns are not just prose by applying them to more shared surfaces.

This cycle intentionally picks the smallest meaningful proving slice:

\begin{itemize}
\tightlist
\item
  shared collection rows outside preference lists
\item
  canonical full-row selection treatment
\item
  one-cell inset rhythm in rich TUI surfaces
\end{itemize}

The best first candidates are:

\begin{itemize}
\tightlist
\item
  \texttt{b\allowbreak{}r\allowbreak{}o\allowbreak{}w\allowbreak{}s\allowbreak{}a\allowbreak{}b\allowbreak{}l\allowbreak{}e\allowbreak{}L\allowbreak{}i\allowbreak{}s\allowbreak{}t\allowbreak{}S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}(\allowbreak{})}
\item
  \texttt{c\allowbreak{}o\allowbreak{}m\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}d\allowbreak{}P\allowbreak{}a\allowbreak{}l\allowbreak{}e\allowbreak{}t\allowbreak{}t\allowbreak{}e\allowbreak{}S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}(\allowbreak{})}
\end{itemize}

Both already represent canonical shared collection behavior. Both currently still lean too much on a glyph-only focus cue in the rich surface path.

\section{Scope of this cycle}\label{record-170-scope-of-this-cycle}

This cycle intentionally covers:

\begin{itemize}
\tightlist
\item
  proving canonical selected-row background treatment in shared TUI surfaces
\item
  proving one-cell inset rhythm in those same rich surfaces
\item
  doing that in \texttt{b\allowbreak{}r\allowbreak{}o\allowbreak{}w\allowbreak{}s\allowbreak{}a\allowbreak{}b\allowbreak{}l\allowbreak{}e\allowbreak{}L\allowbreak{}i\allowbreak{}s\allowbreak{}t\allowbreak{}S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}(\allowbreak{})} and \texttt{c\allowbreak{}o\allowbreak{}m\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}d\allowbreak{}P\allowbreak{}a\allowbreak{}l\allowbreak{}e\allowbreak{}t\allowbreak{}t\allowbreak{}e\allowbreak{}S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}(\allowbreak{})}
\end{itemize}

It does \textbf{not} include:

\begin{itemize}
\tightlist
\item
  notification-center polish
\item
  drawer rhythm and inspector surfaces
\item
  a general block runtime
\item
  changing the lowering-friendly string paths just to match rich TUI ornament
\end{itemize}

\section{Human users}\label{record-170-human-users}

\subsection{Primary human user}\label{record-170-primary-human-user}

A builder using Bijou collection surfaces in a rich TUI shell.

They need:

\begin{itemize}
\tightlist
\item
  focused rows to read as clearly selected
\item
  collection surfaces to feel consistent with the now-canonical settings language
\item
  more than a tiny leading glyph to understand current selection in dense shells
\end{itemize}

\subsection{Human hill}\label{record-170-human-hill}

A builder can place a browsable list or command palette in a shell and get canonical selected-row treatment without hand-adding shell-local styling.

\section{Agent users}\label{record-170-agent-users}

\subsection{Primary agent user}\label{record-170-primary-agent-user}

An agent reviewing or generating collection-style TUI surfaces.

It needs:

\begin{itemize}
\tightlist
\item
  explicit evidence that shared surfaces follow the documented selected-row treatment
\item
  a reliable distinction between selected rows and active regions
\item
  the ability to point at concrete shared-surface proof, not just doctrine prose
\end{itemize}

\subsection{Agent hill}\label{record-170-agent-hill}

An agent can verify that shared list-like surfaces now honor the design-language rules for selection and spacing instead of guessing from one-off shell examples.

\section{Human playback}\label{record-170-human-playback}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A builder renders a browsable list in a rich TUI.
\item
  The focused row reads as a full selected row, not just a glyph.
\item
  The same builder renders a command palette.
\item
  The palette uses the same selection logic and inset rhythm, so the shell feels related instead of custom per surface.
\end{enumerate}

\section{Invariants for this cycle}\label{record-170-invariants-for-this-cycle}

\begin{itemize}
\tightlist
\item
  selected rows in rich TUI surfaces should use background fill, not only a glyph
\item
  active-region treatment remains distinct from selected-row treatment
\item
  one-cell inset rhythm should improve readability without obscuring core content
\item
  lowering-friendly string paths should remain simpler unless the semantic contract requires more
\end{itemize}

\section{Risks}\label{record-170-risks}

\begin{itemize}
\tightlist
\item
  changing the lowering-friendly text path when only the surface path needs the richer treatment
\item
  conflating active-region styling with selected-row styling
\item
  introducing bespoke helper logic that is harder to reuse than the surfaces it is meant to unify
\end{itemize}
