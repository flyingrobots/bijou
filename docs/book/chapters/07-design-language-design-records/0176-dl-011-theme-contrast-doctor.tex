\section{Framing}\label{record-176-framing}

Bijou has explicit token doctrine, but no first-party tool that verifies whether a theme follows it. Poor contrast, invalid colors, and suspicious token reuse can survive until manual visual review.

DL-011 adds a pure theme doctor in core. It checks concrete \texttt{T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e} objects and returns a deterministic report that apps, docs, tests, and future CLI adapters can render however they want.

\section{Sponsored Users}\label{record-176-sponsored-users}

\begin{itemize}
\tightlist
\item
  Framework maintainers reviewing built-in and custom theme changes.
\item
  Third-party theme authors who need actionable feedback without opening a TUI.
\item
  Agent workflows that need stable reports for contrast and token hygiene.
\end{itemize}

\section{Hills}\label{record-176-hills}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A theme author can run a pure doctor against a \texttt{T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e} and get structured issues for invalid colors, low contrast, and overused color values.
\item
  A maintainer can pass explicit foreground/background token pairs and minimum ratios to enforce house rules.
\item
  A test can assert the doctor report without depending on terminal rendering.
\end{enumerate}

\section{Playback Questions}\label{record-176-playback-questions}

\begin{itemize}
\tightlist
\item
  Does the doctor flag invalid foreground or background hex strings?
\item
  Does the doctor calculate WCAG-style contrast ratios for token pairs?
\item
  Does the doctor flag weak explicit foreground/background token pairs?
\item
  Does the doctor detect suspicious color reuse when a reuse limit is supplied?
\item
  Does the report carry stable issue kinds, severities, paths, ratios, and messages?
\item
  Is the doctor exported from the core theme barrel and root package barrel?
\end{itemize}

\section{Drift Check}\label{record-176-drift-check}

\begin{itemize}
\tightlist
\item
  Scope stayed pure and adapter-free. The doctor returns structured reports; CLI/TUI rendering can build on that later.
\item
  Missing token families are only reported for explicit \texttt{c\allowbreak{}o\allowbreak{}n\allowbreak{}t\allowbreak{}r\allowbreak{}a\allowbreak{}s\allowbreak{}t\allowbreak{}P\allowbreak{}a\allowbreak{}i\allowbreak{}r\allowbreak{}s}. The concrete \texttt{T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e} type already makes built-in families present at compile time.
\item
  Mode-lowering risks remain follow-on work. The first slice focuses on color validity, contrast, and suspicious reuse.
\end{itemize}

\section{Retrospective}\label{record-176-retrospective}

\begin{itemize}
\tightlist
\item
  Keeping the doctor in \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u} rather than \texttt{b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}t\allowbreak{}u\allowbreak{}i} was the right ownership call. Themes are core objects and should be diagnosable without a runtime shell.
\item
  The first pass intentionally does not prescribe a universal contrast policy. Explicit pairs let teams encode house rules without making every decorative border token follow text contrast thresholds.
\end{itemize}
