\section{Date}\label{record-177-date}

2026-05-16

\section{Sponsor human}\label{record-177-sponsor-human}

A Bijou app author tuning a framed shell theme who needs focused pane chrome to be themed separately from scrollbars and local accent affordances.

\section{Sponsor agent}\label{record-177-sponsor-agent}

An agent auditing theme usage in DOGFOOD and first-party frame components that must explain why a pane gutter, scrollbar thumb, and local active item are not all the same semantic token.

\section{Hill}\label{record-177-hill}

Focused pane gutters use a dedicated built-in \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}f\allowbreak{}o\allowbreak{}c\allowbreak{}u\allowbreak{}s\allowbreak{}G\allowbreak{}u\allowbreak{}t\allowbreak{}t\allowbreak{}e\allowbreak{}r} token, while scrollbars stay on \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}s\allowbreak{}c\allowbreak{}r\allowbreak{}o\allowbreak{}l\allowbreak{}l\allowbreak{}T\allowbreak{}h\allowbreak{}u\allowbreak{}m\allowbreak{}b} / \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}s\allowbreak{}c\allowbreak{}r\allowbreak{}o\allowbreak{}l\allowbreak{}l\allowbreak{}T\allowbreak{}r\allowbreak{}a\allowbreak{}c\allowbreak{}k} and component-local active emphasis stays on \texttt{s\allowbreak{}e\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}c\allowbreak{}.\allowbreak{}a\allowbreak{}c\allowbreak{}c\allowbreak{}e\allowbreak{}n\allowbreak{}t}.

\section{Description}\label{record-177-description}

DOGFOOD exposed a vocabulary gap in the built-in theme contract. Focused pane gutters are reusable shell chrome, but they were still effectively treated as accent-colored geometry. Scrollbars already had named \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}s\allowbreak{}c\allowbreak{}r\allowbreak{}o\allowbreak{}l\allowbreak{}l\allowbreak{}T\allowbreak{}h\allowbreak{}u\allowbreak{}m\allowbreak{}b} and \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}s\allowbreak{}c\allowbreak{}r\allowbreak{}o\allowbreak{}l\allowbreak{}l\allowbreak{}T\allowbreak{}r\allowbreak{}a\allowbreak{}c\allowbreak{}k} tokens, so focus chrome and scroll chrome could drift together visually without any explicit semantic separation.

The fix belongs in the token system and first-party defaults, not in one-off app palette tweaks.

\section{Decision}\label{record-177-decision}

Add \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}f\allowbreak{}o\allowbreak{}c\allowbreak{}u\allowbreak{}s\allowbreak{}G\allowbreak{}u\allowbreak{}t\allowbreak{}t\allowbreak{}e\allowbreak{}r} to the built-in UI token vocabulary.

The first-party defaults are:

\begin{itemize}
\tightlist
\item
  focused pane gutter: \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}f\allowbreak{}o\allowbreak{}c\allowbreak{}u\allowbreak{}s\allowbreak{}G\allowbreak{}u\allowbreak{}t\allowbreak{}t\allowbreak{}e\allowbreak{}r}
\item
  unfocused pane gutter: \texttt{s\allowbreak{}e\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}c\allowbreak{}.\allowbreak{}m\allowbreak{}u\allowbreak{}t\allowbreak{}e\allowbreak{}d}
\item
  scrollbar thumb: \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}s\allowbreak{}c\allowbreak{}r\allowbreak{}o\allowbreak{}l\allowbreak{}l\allowbreak{}T\allowbreak{}h\allowbreak{}u\allowbreak{}m\allowbreak{}b}
\item
  scrollbar track: \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}s\allowbreak{}c\allowbreak{}r\allowbreak{}o\allowbreak{}l\allowbreak{}l\allowbreak{}T\allowbreak{}r\allowbreak{}a\allowbreak{}c\allowbreak{}k}
\item
  local active/focused affordance inside a component: \texttt{s\allowbreak{}e\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}c\allowbreak{}.\allowbreak{}a\allowbreak{}c\allowbreak{}c\allowbreak{}e\allowbreak{}n\allowbreak{}t}
\end{itemize}

\texttt{f\allowbreak{}o\allowbreak{}c\allowbreak{}u\allowbreak{}s\allowbreak{}e\allowbreak{}d\allowbreak{}G\allowbreak{}u\allowbreak{}t\allowbreak{}t\allowbreak{}e\allowbreak{}r\allowbreak{}T\allowbreak{}o\allowbreak{}k\allowbreak{}e\allowbreak{}n} remains a per-pane escape hatch for deliberate shell variants, but the stock focus-area and framed-app path should not require it for ordinary focused pane chrome.

\section{Accessibility / assistive reading posture}\label{record-177-accessibility-assistive-reading-posture}

No new accessible output is added. The change improves semantic clarity in the theme graph so future accessible inspectors can name focused shell chrome as shell chrome rather than generic accent usage.

\section{Localization / directionality posture}\label{record-177-localization-directionality-posture}

No localized text or directionality behavior changes. The token name is logical and does not imply left/right placement.

\section{Agent inspectability / explainability posture}\label{record-177-agent-inspectability-explainability-posture}

Theme inspectors and future Storybook-like tooling can now report \texttt{u\allowbreak{}i\allowbreak{}.\allowbreak{}f\allowbreak{}o\allowbreak{}c\allowbreak{}u\allowbreak{}s\allowbreak{}G\allowbreak{}u\allowbreak{}t\allowbreak{}t\allowbreak{}e\allowbreak{}r} as a first-class shell token. That makes pane focus chrome auditable without reverse-engineering whether a component happened to borrow \texttt{s\allowbreak{}e\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}c\allowbreak{}.\allowbreak{}a\allowbreak{}c\allowbreak{}c\allowbreak{}e\allowbreak{}n\allowbreak{}t}.

\item

\end{enumerate}
