\section{Decision Summary}\label{record-186-decision-summary}

DL-019 and DL-020 made theme rule provenance real, but DOGFOOD still has to make that truth visible. The Theme Inspector must not look like an unthemed debug drawer that merely lists colors. It should prove which active theme tokens are powering the docs shell and keep its own chrome readable in light and dark shells.

The runtime truth remains the existing DOGFOOD docs shell:

No external design-token integration is added. This is a narrow DOGFOOD usage pass over the inspector and its immediate theme proof surface.

\section{Sponsored Human}\label{record-186-sponsored-human}

A DOGFOOD reader comparing dark and light themes wants to see the active theme affect the app they are looking at, not just a detached list of hex values.

\section{Sponsored Agent}\label{record-186-sponsored-agent}

An agent auditing theme behavior wants deterministic rendered evidence that the inspector chrome, summary copy, usage rows, palette labels, and scroll chrome all come from active DOGFOOD theme tokens.

\section{Hill}\label{record-186-hill}

The Theme Inspector renders readable themed chrome in DOGFOOD dark and light shells, shows a live usage proof for DOGFOOD docs surfaces, and keeps the full palette as reference data rather than implying every reference color is already visible in the surrounding app.

\section{Playback Questions}\label{record-186-playback-questions}

\begin{itemize}
\tightlist
\item
  Does the inspector border, background, title, summary, and close hint use active docs theme tokens instead of fallback styling?
\item
  Does light mode preserve readable foreground/background contrast inside the inspector summary and usage proof?
\item
  Can the inspector show both the active shell palette and the specific DOGFOOD docs tokens currently used by the app?
\item
  Can tests fail if the inspector regresses to unstyled summary copy or loses the usage proof?
\end{itemize}

\section{Scope}\label{record-186-scope}

Included:

\begin{itemize}
\tightlist
\item
  theme the Theme Inspector drawer chrome through the active docs visual theme
\item
  add a compact DOGFOOD usage proof section before the reference palette
\item
  style inspector summary and palette chrome with explicit theme tokens
\item
  add focused DOGFOOD preview tests for light-mode readability and usage proof
\item
  update changelog and localization catalogs for new visible copy
\end{itemize}

Out of scope:

\begin{itemize}
\tightlist
\item
  replacing the theme engine
\item
  adding a design-book dependency
\item
  restyling every DOGFOOD docs pane in this slice
\item
  changing third-party theme presets
\item
  adding element-level provenance for every rendered cell
\end{itemize}

\section{Runtime Contract}\label{record-186-runtime-contract}

The usage proof is derived from the same active shell theme id that drives the docs page. It must not maintain an independent color table. If the active shell theme changes, the inspector summary, usage proof, reference palette labels, drawer border, surface, and scrollbar update from that same model state.

\section{Localization And Directionality Posture}\label{record-186-localization-and-directionality-posture}

All new visible DOGFOOD copy is catalog-backed and participates in the existing DOGFOOD i18n completeness, check, and debt gates.

\section{Tests To Write First}\label{record-186-tests-to-write-first}

\begin{itemize}
\tightlist
\item
  a light-theme inspector regression that proves the active summary and close hint are styled with readable foreground/background cells
\item
  a usage-proof regression that proves the inspector renders live DOGFOOD docs token rows instead of only the reference palette
\end{itemize}

\section{Closeout Notes}\label{record-186-closeout-notes}

Close this cycle when local DOGFOOD preview tests, DOGFOOD i18n gates, lint, and relevant Code Dojo checks are green, and the PR summary names the before/after behavior from the screenshots.
