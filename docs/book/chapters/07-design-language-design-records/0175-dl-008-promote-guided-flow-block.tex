\section{Why this cycle exists}\label{record-175-why-this-cycle-exists}

DL-005 proved the guided-flow side of the design language through \texttt{e\allowbreak{}x\allowbreak{}p\allowbreak{}l\allowbreak{}a\allowbreak{}i\allowbreak{}n\allowbreak{}a\allowbreak{}b\allowbreak{}i\allowbreak{}l\allowbreak{}i\allowbreak{}t\allowbreak{}y\allowbreak{}(\allowbreak{})}.

That gave Bijou one canonical component seam, but not yet a reusable block for calmer non-AI assistance surfaces.

The design-system block acceptance bar says a structure is ready to become a canonical block when:

\begin{itemize}
\tightlist
\item
  it recurs across more than one surface or product need
\item
  its interaction ownership is stable
\item
  its patterns are already canonical elsewhere
\item
  its lowering story is explicit
\end{itemize}

This cycle exists to clear that next bar by promoting guided-flow language into a reusable block helper instead of leaving explainability to carry every calm recommendation or setup surface by itself.

\section{Scope of this cycle}\label{record-175-scope-of-this-cycle}

This cycle intentionally covers:

\begin{itemize}
\tightlist
\item
  one reusable \texttt{g\allowbreak{}u\allowbreak{}i\allowbreak{}d\allowbreak{}e\allowbreak{}d\allowbreak{}F\allowbreak{}l\allowbreak{}o\allowbreak{}w\allowbreak{}(\allowbreak{})} block helper in \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u}
\item
  block-level section rhythm, multi-step assistance, and next-action treatment
\item
  reuse of the same block rhythm by \texttt{e\allowbreak{}x\allowbreak{}p\allowbreak{}l\allowbreak{}a\allowbreak{}i\allowbreak{}n\allowbreak{}a\allowbreak{}b\allowbreak{}i\allowbreak{}l\allowbreak{}i\allowbreak{}t\allowbreak{}y\allowbreak{}(\allowbreak{})}
\item
  proof of the block in DOGFOOD
\end{itemize}

It does \textbf{not} include:

\begin{itemize}
\tightlist
\item
  a wizard runtime or step-routing subsystem
\item
  shell-owned guided-flow overlays or drawer state
\item
  AI/service integrations beyond existing explainability work
\item
  layout and viewport formalization
\end{itemize}

\section{Human users}\label{record-175-human-users}

\subsection{Primary human user}\label{record-175-primary-human-user}

A builder composing one calm guided recommendation, setup brief, or review path without inventing a full wizard or hiding the action inside generic prose.

They need:

\begin{itemize}
\tightlist
\item
  one reusable block that separates summary, steps, supporting context, and next action
\item
  a calmer default than another titled box with ad hoc copy
\item
  a path that works for both AI and non-AI guided assistance
\item
  lowering that preserves the same meaning in pipe and accessible modes
\end{itemize}

\subsection{Human hill}\label{record-175-human-hill}

A builder can render one guided recommendation or setup path with a clear next action and calmer multi-step structure without hand-rolling the same section rhythm again.

\section{Agent users}\label{record-175-agent-users}

\subsection{Primary agent user}\label{record-175-primary-agent-user}

An agent generating or auditing guided-assistance surfaces in Bijou.

It needs:

\begin{itemize}
\tightlist
\item
  one block-level helper to target instead of reconstructing section rhythm from raw strings
\item
  proof that explainability is now one specialization of a broader guided-flow block language
\item
  explicit boundaries between content-block ownership and shell/workflow ownership
\end{itemize}

\subsection{Agent hill}\label{record-175-agent-hill}

An agent can point to one canonical \texttt{g\allowbreak{}u\allowbreak{}i\allowbreak{}d\allowbreak{}e\allowbreak{}d\allowbreak{}F\allowbreak{}l\allowbreak{}o\allowbreak{}w\allowbreak{}(\allowbreak{})} helper, show that \texttt{e\allowbreak{}x\allowbreak{}p\allowbreak{}l\allowbreak{}a\allowbreak{}i\allowbreak{}n\allowbreak{}a\allowbreak{}b\allowbreak{}i\allowbreak{}l\allowbreak{}i\allowbreak{}t\allowbreak{}y\allowbreak{}(\allowbreak{})} now rides the same block rhythm, and prove the block in DOGFOOD.

\section{Invariants for this cycle}\label{record-175-invariants-for-this-cycle}

\begin{itemize}
\tightlist
\item
  guided-flow promotion must not force shell ownership into a core block
\item
  \texttt{e\allowbreak{}x\allowbreak{}p\allowbreak{}l\allowbreak{}a\allowbreak{}i\allowbreak{}n\allowbreak{}a\allowbreak{}b\allowbreak{}i\allowbreak{}l\allowbreak{}i\allowbreak{}t\allowbreak{}y\allowbreak{}(\allowbreak{})} must remain AI-specific even while sharing block rhythm
\item
  one obvious next action must stay more visible than supporting prose
\item
  pipe and accessible modes must preserve summary, steps, sections, and next action without decorative chrome
\item
  the promoted block must be proven in at least one non-AI surface
\end{itemize}

\section{Risks}\label{record-175-risks}

\begin{itemize}
\tightlist
\item
  making the block so generic that it loses the rhythm it is meant to standardize
\item
  letting explainability collapse into generic guidance and lose AI specificity
\item
  overreaching into shell routing or wizard ownership before the block itself is stable
\end{itemize}

\section{Out of scope}\label{record-175-out-of-scope}

\begin{itemize}
\tightlist
\item
  generalized workflow state machines
\item
  shell-owned guided-flow overlays
\item
  editable step state
\item
  layout and viewport doctrine work
\end{itemize}

\subsection{Drift from ideal}\label{record-175-drift-from-ideal}

This cycle did not introduce a wizard runtime or shell-owned workflow surface.

That was intentional and correct.

The right promotion step was the calmer content block first, not a larger shell workflow subsystem.
