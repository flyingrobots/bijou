\section{Decision Summary}\label{record-180-decision-summary}

Theme contrast should be declared as a reusable design-system contract, not as one-off test loops.

Safe pairs name which foreground token paths are expected to be readable on which background token paths. The contract feeds \texttt{d\allowbreak{}o\allowbreak{}c\allowbreak{}t\allowbreak{}o\allowbreak{}r\allowbreak{}T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e\allowbreak{}(\allowbreak{})}, DOGFOOD theme tests, future Theme Inspector swatches, and lower-mode accessibility reports.

The first runtime shape is intentionally compact:

\begin{CodeBlock}
const pairs = defineThemeSafePairs()
  .readable('semantic.primary', 'surface.primary.bg')
  .status('status.error', 'surface.overlay.bg')
  .chrome('ui.cursor', 'surface.secondary.bg')
  .build();
\end{CodeBlock}

Safe-pair background paths may target a token foreground, such as \texttt{s\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}.\allowbreak{}p\allowbreak{}r\allowbreak{}i\allowbreak{}m\allowbreak{}a\allowbreak{}r\allowbreak{}y}, or a token background slot, such as \texttt{s\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}.\allowbreak{}p\allowbreak{}r\allowbreak{}i\allowbreak{}m\allowbreak{}a\allowbreak{}r\allowbreak{}y\allowbreak{}.\allowbreak{}b\allowbreak{}g}.

\section{Sponsored Human}\label{record-180-sponsored-human}

A designer-engineer wants DogFood and first-party themes to prove readable foreground/background combinations so that theme retuning is a design exercise instead of a screenshot guessing game.

\section{Sponsored Agent}\label{record-180-sponsored-agent}

An agent auditing a theme wants a stable matrix of safe token pairs so it can identify whether a low-contrast failure is a broken theme value, a missing token, or an unsupported pair that should not have been used by the component.

\section{Hill}\label{record-180-hill}

Bijou can declare safe token pairs once, run the same contrast contract through \texttt{d\allowbreak{}o\allowbreak{}c\allowbreak{}t\allowbreak{}o\allowbreak{}r\allowbreak{}T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e\allowbreak{}(\allowbreak{})}, and reuse the resulting pair matrix in DOGFOOD and future Theme Inspector UX.

\section{Playback Questions}\label{record-180-playback-questions}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item

\item

\item

\item
  Does DogFood publish its readable/status/chrome pair matrix from the theme module rather than hiding it in tests?
\item
  Can Theme Inspector later display the same pair facts without inventing a second contrast registry?
\end{enumerate}

\section{Non-Goals}\label{record-180-non-goals}

This slice does not implement the Theme Inspector drawer, retune the global default theme values, or replace the legacy single-mode \texttt{T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e} interface. Those are separate follow-on slices.

\section{Safe-Pair Vocabulary}\label{record-180-safe-pair-vocabulary}

\texttt{r\allowbreak{}e\allowbreak{}a\allowbreak{}d\allowbreak{}a\allowbreak{}b\allowbreak{}l\allowbreak{}e} pairs are ordinary text and component foregrounds that must stay legible on a surface.

\texttt{s\allowbreak{}t\allowbreak{}a\allowbreak{}t\allowbreak{}u\allowbreak{}s} pairs are process, health, timeline, or object-state foregrounds that must stay legible when rendered on a surface.

\texttt{c\allowbreak{}h\allowbreak{}r\allowbreak{}o\allowbreak{}m\allowbreak{}e} pairs are shell/runtime affordances such as cursor and focus chrome that must remain recognizable on app surfaces.

The kind is not decorative metadata. Future inspectors and reports can group failures by kind so a theme author can distinguish typography problems from status-color problems.

\section{Runtime Contract}\label{record-180-runtime-contract}

\texttt{d\allowbreak{}e\allowbreak{}f\allowbreak{}i\allowbreak{}n\allowbreak{}e\allowbreak{}T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e\allowbreak{}S\allowbreak{}a\allowbreak{}f\allowbreak{}e\allowbreak{}P\allowbreak{}a\allowbreak{}i\allowbreak{}r\allowbreak{}s\allowbreak{}(\allowbreak{})} returns a pure builder. Chained calls accumulate immutable pair declarations. \texttt{b\allowbreak{}u\allowbreak{}i\allowbreak{}l\allowbreak{}d\allowbreak{}(\allowbreak{})} returns a frozen array of frozen pair objects compatible with \texttt{T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e\allowbreak{}C\allowbreak{}o\allowbreak{}n\allowbreak{}t\allowbreak{}r\allowbreak{}a\allowbreak{}s\allowbreak{}t\allowbreak{}P\allowbreak{}a\allowbreak{}i\allowbreak{}r}.

Duplicate foreground/background pairs are rejected because duplicate pair rows make reports and inspectors ambiguous.

\texttt{d\allowbreak{}o\allowbreak{}c\allowbreak{}t\allowbreak{}o\allowbreak{}r\allowbreak{}T\allowbreak{}h\allowbreak{}e\allowbreak{}m\allowbreak{}e\allowbreak{}(\allowbreak{})} resolves contrast pair paths through concrete token color slots:

\begin{itemize}
\tightlist
\item
  \texttt{s\allowbreak{}e\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}t\allowbreak{}i\allowbreak{}c\allowbreak{}.\allowbreak{}p\allowbreak{}r\allowbreak{}i\allowbreak{}m\allowbreak{}a\allowbreak{}r\allowbreak{}y} resolves to the token foreground color.
\item
  \texttt{s\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}.\allowbreak{}p\allowbreak{}r\allowbreak{}i\allowbreak{}m\allowbreak{}a\allowbreak{}r\allowbreak{}y} resolves to the surface token foreground color.
\item
  \texttt{s\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}.\allowbreak{}p\allowbreak{}r\allowbreak{}i\allowbreak{}m\allowbreak{}a\allowbreak{}r\allowbreak{}y\allowbreak{}.\allowbreak{}b\allowbreak{}g} resolves to the surface token background color.
\end{itemize}

Missing paths remain errors. Invalid colors remain invalid-color issues from the normal token scan.

\section{DOGFOOD Matrix}\label{record-180-dogfood-matrix}

DogFood declares its safe-pair matrix beside its shell themes.

Readable foregrounds:

\begin{CodeBlock}
semantic.primary
semantic.muted
semantic.accent
semantic.info
semantic.success
semantic.warning
semantic.error
\end{CodeBlock}

Status foregrounds:

\begin{CodeBlock}
status.active
status.pending
\end{CodeBlock}

Chrome foregrounds:

\begin{CodeBlock}
ui.cursor
\end{CodeBlock}

Background slots:

\begin{CodeBlock}
surface.primary.bg
surface.secondary.bg
surface.elevated.bg
surface.overlay.bg
surface.muted.bg
\end{CodeBlock}

That matrix intentionally proves the dense docs shell before broader component retokenization. Additional first-party pairs should be added only when a component needs them as a real contract.

\section{Accessibility / Assistive Reading Posture}\label{record-180-accessibility-assistive-reading-posture}

Safe-pair checks do not make color sufficient as the only meaning carrier. They prove that color, when present, remains readable. The same components still need text, symbols, structure, or state labels that survive no-color, pipe, and accessible output modes.

\section{Agent Inspectability / Explainability Posture}\label{record-180-agent-inspectability-explainability-posture}

A future inspector can group safe-pair facts by pair kind:

\begin{CodeBlock}
readable semantic.primary on surface.primary.bg: pass 15.20
status status.pending on surface.overlay.bg: pass 8.40
chrome ui.cursor on surface.secondary.bg: pass 7.10
\end{CodeBlock}

If the renderer later preserves per-cell token provenance, an agent can compare the token pair actually used by a cell against the declared safe-pair matrix.

\section{Localization / Directionality Posture}\label{record-180-localization-directionality-posture}

No localized strings are introduced by this design. Token paths and pair kinds are stable developer identifiers and must not encode locale-specific prose or physical direction.

\section{Retrospective}\label{record-180-retrospective}

The important shape is the reusable contract. DogFood's earlier contrast proof was correct, but the pair list was trapped inside tests. This slice turns those pairs into design-system data so the next retuning pass can change colors with objective proof.
