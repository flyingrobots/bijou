\section{Sponsor Human}\label{record-111-sponsor-human}

DOGFOOD should increasingly feel like an app authored from semantic Blocks, not an app that has a Blocks documentation page on the side.

\section{Sponsor Agent}\label{record-111-sponsor-agent}

An agent should be able to inspect DOGFOOD's product surfaces and understand which Block owns each semantic region without executing provider lifecycle, hidden registries, or view mutation paths.

\section{Hill}\label{record-111-hill}

DOGFOOD uses Blocks for visible app semantics across shell, docs, preview, settings, and workbench surfaces while preserving the existing component layer as the leaf rendering vocabulary.

DF-071 is not a visual redesign. It is a product-boundary pass: more visible DOGFOOD surfaces should be described, rendered, and verified through Blocks where the Block boundary is already stable.

\section{Core Rule}\label{record-111-core-rule}

Blocks own product semantics.

Components own leaf rendering.

Runtime and provider systems own lifecycle.

Localization owns text lookup through a port.

DF-071 may connect these layers, but it must not collapse them.

\section{Adaptation Note}\label{record-111-adaptation-note}

The top navigation seam is owned by the generic \texttt{A\allowbreak{}p\allowbreak{}p\allowbreak{}F\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e} tab renderer. DF-071 therefore did not fork tab rendering inside DOGFOOD. Instead, it covered the frame-owned surfaces that already have stable semantic boundaries:

\begin{itemize}
\tightlist
\item
  footer hints
\item
  search title
\item
  notifications
\item
  performance HUD
\item
  keyboard help
\item
  command palette
\end{itemize}

The actual overlay renderers remain in \texttt{@\allowbreak{}f\allowbreak{}l\allowbreak{}y\allowbreak{}i\allowbreak{}n\allowbreak{}g\allowbreak{}r\allowbreak{}o\allowbreak{}b\allowbreak{}o\allowbreak{}t\allowbreak{}s\allowbreak{}/\allowbreak{}b\allowbreak{}i\allowbreak{}j\allowbreak{}o\allowbreak{}u\allowbreak{}-\allowbreak{}t\allowbreak{}u\allowbreak{}i}. DOGFOOD now publishes local block contracts for those surfaces so the app can be inspected as a block-authored product without duplicating frame runtime behavior.

\section{Non-Goals}\label{record-111-non-goals}

\begin{itemize}
\tightlist
\item
  no new provider lifecycle system
\item
  no command dispatch rewrite
\item
  no hidden global block registry
\item
  no localization runtime rewrite
\item
  no conversion of leaf components into Blocks
\item
  no broad visual redesign
\item
  no metadata-only tests standing in for rendered behavior
\end{itemize}

\section{Tests To Write First}\label{record-111-tests-to-write-first}

\begin{itemize}
\tightlist
\item
  behavior tests proving routed surfaces render the user-visible text they claim to own
\item
  behavior tests proving block registries expose the new semantic surfaces without discovery-time rendering
\item
  behavior tests proving routed surfaces still preserve lowered-mode behavior
\item
  behavior tests proving localization access stays behind the existing port
\end{itemize}
