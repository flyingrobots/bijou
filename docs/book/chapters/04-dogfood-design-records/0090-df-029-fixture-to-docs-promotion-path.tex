\section{Framing}\label{record-090-framing}

Good Bijou examples often start as regression fixtures. Good docs examples often become the clearest regression fixtures. Today the promotion path between those surfaces is mostly manual, which means provenance, story ids, component metadata, and capture outputs drift.

DF-029 adds a pure promotion record that links fixture, docs, story, example, or MCP artifacts. The first slice is not a file-writing CLI; it is the canonical record and text report that future commands can emit, review, and preserve.

\section{Sponsored Users}\label{record-090-sponsored-users}

\begin{itemize}
\tightlist
\item
  Maintainers promoting stable fixtures into docs and DOGFOOD stories.
\item
  Docs authors linking examples back to executable regression coverage.
\item
  MCP/tooling authors reusing example provenance in agent-facing payloads.
\item
  Agents proposing docs updates from failing or useful fixtures.
\end{itemize}

\section{Hills}\label{record-090-hills}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  A maintainer can record a fixture-to-docs promotion with source artifact, target artifact, component metadata, story matrix, tags, and notes.
\item
  A docs author can reverse that record when a docs story should become a regression fixture.
\item
  A reviewer can read a deterministic report that preserves provenance without inspecting multiple files.
\end{enumerate}

\section{Acceptance Criteria}\label{record-090-acceptance-criteria}

\begin{itemize}
\tightlist
\item
  RED tests fail before implementation and pass after.
\item
  Promotion records keep source, target, metadata, matrix, tags, and notes.
\item
  Reverse promotion swaps source/target and preserves provenance.
\item
  Report text is stable and suitable for docs, review comments, and agent output.
\item
  Docs and changelog describe the helper.
\end{itemize}

\section{Drift Check}\label{record-090-drift-check}

\begin{itemize}
\tightlist

\section{Retrospective}\label{record-090-retrospective}

\begin{itemize}
\tightlist
\item
  The promotion record is deliberately not a CLI. That keeps adapter concerns like path existence, markdown insertion, and baseline writing outside core.
\item
  Together with component metadata and story capture matrices, it gives future docs tooling a compact provenance spine instead of one-off comments.
\end{itemize}
