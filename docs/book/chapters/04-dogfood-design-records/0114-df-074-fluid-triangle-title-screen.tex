\section{Decision Summary}\label{record-114-decision-summary}

Bijou should design a future DOGFOOD title screen around a live fluid field moving around a triangular obstacle, rendered as terminal glyphs. The immediate Bijou work should define the title-scene contract, deterministic CPU fallback, theme-token policy, and cell-level proof. The high-end renderer should be Geordi-backed when the shared render pipeline is ready.

The goal is not to copy a browser demo into DOGFOOD. The goal is to turn the idea into a Bijou-native release-title system with deterministic witnesses and a future GPU render endpoint.

\section{Sponsored Human}\label{record-114-sponsored-human}

A Bijou maintainer wants a memorable title screen that feels alive, branded, and release-specific without making DOGFOOD startup flaky, slow, or impossible to test.

\section{Sponsored Agent}\label{record-114-sponsored-agent}

An agent wants a deterministic scene description, frame inputs, glyph outputs, and render receipts so it can explain title-screen pixels and terminal cells without depending on screenshots or manual terminal observation.

\section{Hill}\label{record-114-hill}

DOGFOOD can show a fluid triangle title screen where the fluid motion, glyph density, color tokens, and input behavior are deterministic under test, while the production renderer can later upgrade from a Bijou CPU path to a Geordi-backed GPU path without changing the title scene's product contract.

\section{Inspiration Boundary}\label{record-114-inspiration-boundary}

The reference project is useful because it combines:

\begin{itemize}
\tightlist
\item
  fluid-like motion
\item
  a triangular obstacle
\item
  ASCII rendering
\item
  per-column character sequences
\item
  a playful launch-screen posture
\end{itemize}

Bijou should borrow the interaction and rendering concept, not the browser runtime assumptions.

The reference README states that its simulation code comes from Ten Minute Physics and that the project is MIT licensed. If Bijou ports substantial code from the reference or from the underlying Ten Minute Physics simulation, the ported file must preserve the relevant MIT attribution and copyright notice. The preferred first implementation is an original Bijou renderer inspired by the concept.

\begin{itemize}

\section{Scene Model}\label{record-114-scene-model}

The title should be modeled as data before it is rendered.

\begin{CodeBlock}
type FluidTitleSceneSpec = {
  id: 'dogfood.fluid-triangle-title';
  version: 1;
  seed: number;
  cols: number;
  rows: number;
  quality: 'low' | 'medium' | 'high' | 'auto';
  themeMode: 'dark' | 'light';
  triangle: {
    centerX: number;
    centerY: number;
    radius: number;
    rotation: number;
  };
  glyphRamps: readonly string[];
  titleKey: 'dogfood.title.bijou';
  promptKey: 'dogfood.title.pressEnter';
};
\end{CodeBlock}

The scene spec owns intent. Renderers own lowering.

\section{Renderer Targets}\label{record-114-renderer-targets}

\subsection{Bijou CPU Renderer}\label{record-114-bijou-cpu-renderer}

The first implementation should be a deterministic Bijou CPU renderer. It does not need to be a full fluid solver. It needs to produce the right motion language, stay bounded, and be testable.

Acceptable first algorithms:

\begin{itemize}

  advected scalar density field
\item
  curl-noise-like deterministic flow
\item

\section{Theme And Color Policy}\label{record-114-theme-and-color-policy}

The renderer must use theme tokens rather than raw title-screen colors.

\section{Input Contract}\label{record-114-input-contract}

The title screen must keep the current input discipline:

\begin{itemize}
\tightlist
\item
  \texttt{E\allowbreak{}n\allowbreak{}t\allowbreak{}e\allowbreak{}r} proceeds to DOGFOOD.
\item
  Backtick toggles the normal shell perf HUD.
\item
  \texttt{q} opens the normal quit confirmation.
\item
  Theme or quality controls may remain title-owned only if documented.
\item
  No other ordinary key should accidentally skip the title.
\end{itemize}

Future optional interactions can perturb the field:

\begin{itemize}
\tightlist
\item
  mouse move nudges velocity
\item
  arrow keys shift the triangle
\item
  terminal resize reseeds layout while preserving deterministic frame facts
\end{itemize}

Those interactions are not required for the first slice.

\section{Localization And Directionality}\label{record-114-localization-and-directionality}

The visible title and prompt must be localization-backed strings. The fluid field itself is visual and does not require localization, but lower modes should expose the string keys.

RTL posture:

\begin{itemize}
\tightlist
\item
  The prompt should use the app's existing text direction rules.
\item
  The fluid field can remain spatially symmetric.
\item
  Per-column glyph ramps should not encode English-only words in default mode.
\end{itemize}

The reference project's per-column letter sequences are useful as a visual trick, but a Bijou default should not rely on hidden English text in the fluid field.

\section{Accessibility And Assistive Posture}\label{record-114-accessibility-and-assistive-posture}

The title screen must not be the only source of release information.

Required posture:

\begin{itemize}
\tightlist
\item
  prompt remains static enough to read
\item
  low-motion mode can freeze or heavily slow the field
\item
  status/lower-mode facts identify the release title
\item
  perf HUD remains accessible from the title screen
\item
  the screen does not flash at unsafe contrast/frequency patterns
\end{itemize}

\section{Agent Inspectability}\label{record-114-agent-inspectability}

Every deterministic render pass should be able to emit a receipt:

\begin{CodeBlock}
{
  "sceneId": "dogfood.fluid-triangle-title",
  "frame": 120,
  "seed": 700,
  "renderer": "bijou-cpu-density",
  "quality": "medium",
  "triangle": { "centerX": 80, "centerY": 18, "radius": 9 },
  "glyphRampHash": "fnv1a32:...",
  "surfaceHash": "fnv1a32:...",
  "tokenRefs": [
    "title.fluid.low",
    "title.fluid.mid",
    "title.fluid.high",
    "title.prompt.enter.fg"
  ]
}
\end{CodeBlock}

For Geordi output, the receipt should add endpoint facts:

\begin{CodeBlock}
{
  "renderer": "geordi-fluid-gpu",
  "endpoint": "packed-bijou-cells",
  "shaderHash": "sha256:...",
  "packedCellsHash": "fnv1a32:...",
  "witnessHash": "sha256:..."
}
\end{CodeBlock}

\section{Playback Questions}\label{record-114-playback-questions}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Does the first frame read as Bijou before animation is observed?
\item
  Does \texttt{E\allowbreak{}n\allowbreak{}t\allowbreak{}e\allowbreak{}r} remain the only key that proceeds to DOGFOOD?
\item
  Does the prompt stay legible at 80x24 and larger terminals?
\item
  Can the title run in low mode without Geordi?
\item
  Can a test prove the triangle collider leaves a stable void or edge?
\item
  Can a receipt explain the selected renderer, quality, seed, tokens, and output hash?
\item
  Can the Geordi endpoint later replace the high-quality renderer without changing title-screen input behavior?
\end{enumerate}

\section{Implementation Outline}\label{record-114-implementation-outline}

\begin{enumerate}

\item
  Add glyph-ramp and theme-token lowering into \texttt{S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e}.
\item
  Add title-screen integration behind a release-title switch.
\item
  Preserve existing perf HUD, quit, and Enter-only routing contracts.
\item
  Add a low-motion/frozen frame path.
\item
  Add tests for frame determinism, prompt visibility, key routing, and token use.
\item
  Add Geordi endpoint target profile once packed-cell or image witness support is ready.
\end{enumerate}

\section{Tests To Write First}\label{record-114-tests-to-write-first}

\begin{itemize}
\tightlist
\item
  Given the same spec, seed, size, and frame, the CPU renderer produces the same \texttt{s\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}H\allowbreak{}a\allowbreak{}s\allowbreak{}h}.
\item
  Given different frame indexes, at least one fluid-region cell changes while the prompt remains stable.
\item
  Given 80x24, the prompt and title are visible and not overwritten by fluid cells.
\item
  Given non-Enter printable key input, DOGFOOD remains on the title route.
\item
  Given \texttt{E\allowbreak{}n\allowbreak{}t\allowbreak{}e\allowbreak{}r}, DOGFOOD proceeds to the main docs route.
\item
  Given backtick, the normal perf HUD toggles while the title route remains active.
\item
  Given low-motion mode, repeated frames produce either identical output or a documented bounded change.
\item
  Given missing Geordi endpoint, \texttt{a\allowbreak{}u\allowbreak{}t\allowbreak{}o} selects a Bijou CPU renderer and emits a reason fact.
\end{itemize}

\section{Non-Goals}\label{record-114-non-goals}

\begin{itemize}
\tightlist
\item
  No browser canvas dependency in DOGFOOD startup.
\item
  No required GPU path for CI.
\item
  No direct code port from the reference project in the design slice.
\item
  No change to the public title-screen skip contract beyond preserving Enter-only proceed.
\item
  No claim that this implements shared UI scene IR.
\end{itemize}
