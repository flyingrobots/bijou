\section{Sponsor human}\label{record-083-sponsor-human}

A builder or maintainer who expects DOGFOOD to behave like a real docs site shell instead of only a component-family browser.

\section{Sponsor agent}\label{record-083-sponsor-agent}

An agent that must inspect DOGFOOD and answer:

\begin{itemize}
\tightlist
\item
  where the top-level docs sections live
\item
  whether DOGFOOD can read prose docs inside the app
\item
  whether the component explorer is still being mistaken for the whole docs product
\end{itemize}

\section{Hill}\label{record-083-hill}

DOGFOOD visibly behaves like a terminal-native docs shell with top-level section tabs and a real prose-doc reader, while keeping the component explorer as one important section rather than the whole app.

\section{Why this cycle exists}\label{record-083-why-this-cycle-exists}

\texttt{D\allowbreak{}F\allowbreak{}-\allowbreak{}0\allowbreak{}2\allowbreak{}1} reframed the release honestly: DOGFOOD had enough shell and component breadth to feel substantial, but it still behaved like a components-only product.

That meant \texttt{4\allowbreak{}.\allowbreak{}1\allowbreak{}.\allowbreak{}0} still lacked a visible docs-site shell:

\begin{itemize}
\tightlist
\item
  there was no top-level section navigation
\item
  there was no prose-doc reader inside the app
\item
  users could not tell where non-component docs were supposed to live
\end{itemize}

This cycle closes that shell-shape gap without pretending the full repo, package, release, doctrine, and architecture corpus has already landed.

\section{Playback questions}\label{record-083-playback-questions}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Does DOGFOOD now expose top-level docs navigation instead of a single component-only page?
\item
  Is the default docs route a prose-reader-oriented section rather than dropping directly into the component explorer?
\item
  Can a user visibly switch between \texttt{G\allowbreak{}u\allowbreak{}i\allowbreak{}d\allowbreak{}e\allowbreak{}s}, \texttt{C\allowbreak{}o\allowbreak{}m\allowbreak{}p\allowbreak{}o\allowbreak{}n\allowbreak{}e\allowbreak{}n\allowbreak{}t\allowbreak{}s}, \texttt{P\allowbreak{}a\allowbreak{}c\allowbreak{}k\allowbreak{}a\allowbreak{}g\allowbreak{}e\allowbreak{}s}, \texttt{P\allowbreak{}h\allowbreak{}i\allowbreak{}l\allowbreak{}o\allowbreak{}s\allowbreak{}o\allowbreak{}p\allowbreak{}h\allowbreak{}y}, and \texttt{R\allowbreak{}e\allowbreak{}l\allowbreak{}e\allowbreak{}a\allowbreak{}s\allowbreak{}e}?
\item
  Does the component browser still work as one section inside the docs shell?
\item
  Is the remaining \texttt{4\allowbreak{}.\allowbreak{}1\allowbreak{}.\allowbreak{}0} blocker work now clearly about publishing the real corpus rather than inventing the shell shape?
\end{enumerate}

\section{Accessibility / assistive reading posture}\label{record-083-accessibility-assistive-reading-posture}

The new reader must stay keyboard-first and text-legible. It cannot rely on screenshots, pointer-only interaction, or color alone to communicate the new section structure.

\section{Localization / directionality posture}\label{record-083-localization-directionality-posture}

Section titles and shell hints should stay localizable. This cycle does not block on translating the starter prose corpus, but the shell shape must not hard-code a components-only reading model.

\section{Agent inspectability / explainability posture}\label{record-083-agent-inspectability-explainability-posture}

The repo should make the new shell shape explicit in:

\begin{itemize}
\tightlist
\item
  this cycle doc
\item
  the DOGFOOD app implementation
\item
  the \texttt{v\allowbreak{}4\allowbreak{}.\allowbreak{}1\allowbreak{}.\allowbreak{}0} blocker lane
\item
  the release signposts and tests
\end{itemize}

An agent should be able to prove that \texttt{D\allowbreak{}F\allowbreak{}-\allowbreak{}0\allowbreak{}2\allowbreak{}2} closed and that the remaining blocker work is now corpus publication.

\section{Non-goals}\label{record-083-non-goals}

\begin{itemize}
\tightlist
\item
  importing the full repo docs corpus in this cycle
\item
  closing package, release, doctrine, or architecture content gaps
\item
  replacing every bespoke DOGFOOD surface
\item
  inventing a general animation or text-effects API as part of this work
\end{itemize}

\section{Decision}\label{record-083-decision}

For \texttt{4\allowbreak{}.\allowbreak{}1\allowbreak{}.\allowbreak{}0}, DOGFOOD should expose the full section map immediately:

\begin{itemize}
\tightlist
\item
  \texttt{G\allowbreak{}u\allowbreak{}i\allowbreak{}d\allowbreak{}e\allowbreak{}s}
\item
  \texttt{C\allowbreak{}o\allowbreak{}m\allowbreak{}p\allowbreak{}o\allowbreak{}n\allowbreak{}e\allowbreak{}n\allowbreak{}t\allowbreak{}s}
\item
  \texttt{P\allowbreak{}a\allowbreak{}c\allowbreak{}k\allowbreak{}a\allowbreak{}g\allowbreak{}e\allowbreak{}s}
\item
  \texttt{P\allowbreak{}h\allowbreak{}i\allowbreak{}l\allowbreak{}o\allowbreak{}s\allowbreak{}o\allowbreak{}p\allowbreak{}h\allowbreak{}y}
\item
  \texttt{R\allowbreak{}e\allowbreak{}l\allowbreak{}e\allowbreak{}a\allowbreak{}s\allowbreak{}e}
\end{itemize}

\texttt{G\allowbreak{}u\allowbreak{}i\allowbreak{}d\allowbreak{}e\allowbreak{}s} becomes the default docs route and carries the initial prose reader foundation. The other non-component sections get a visible home now, even if their deeper corpus still lands in follow-on blocker cycles.

\section{Implementation outline}\label{record-083-implementation-outline}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Promote DOGFOOD from a one-page framed app to a top-level tabbed docs shell.
\item
  Add a prose-reader page model with guide navigation and scrollable main-doc surfaces.
\item
  Keep the existing component explorer intact as the \texttt{C\allowbreak{}o\allowbreak{}m\allowbreak{}p\allowbreak{}o\allowbreak{}n\allowbreak{}e\allowbreak{}n\allowbreak{}t\allowbreak{}s} tab.
\item
  Seed DOGFOOD with starter markdown pages that explain the docs map and make the missing sections visible.
\item
  Reduce the remaining \texttt{4\allowbreak{}.\allowbreak{}1\allowbreak{}.\allowbreak{}0} blockers to real corpus publication: \texttt{D\allowbreak{}F\allowbreak{}-\allowbreak{}0\allowbreak{}2\allowbreak{}3} and \texttt{D\allowbreak{}F\allowbreak{}-\allowbreak{}0\allowbreak{}2\allowbreak{}4}.
\end{enumerate}

\section{Evidence}\label{record-083-evidence}

\begin{itemize}
\tightlist
\item
  the docs app now defaults to \texttt{G\allowbreak{}u\allowbreak{}i\allowbreak{}d\allowbreak{}e\allowbreak{}s}
\item
  the framed header exposes multiple top-level docs sections
\item
  \texttt{C\allowbreak{}o\allowbreak{}m\allowbreak{}p\allowbreak{}o\allowbreak{}n\allowbreak{}e\allowbreak{}n\allowbreak{}t\allowbreak{}s} still contains the family/story/variant explorer
\item
  DOGFOOD can render prose markdown pages from a starter corpus
\item
  the \texttt{v\allowbreak{}4\allowbreak{}.\allowbreak{}1\allowbreak{}.\allowbreak{}0} blocker lane now only carries the remaining corpus work
\end{itemize}

\section{Retrospective}\label{record-083-retrospective}

The important correction here is architectural, not decorative: DOGFOOD stops overclaiming that ``component docs'' equals ``the whole Bijou docs product.''

The remaining release blocker work is now narrower and more honest:

\begin{itemize}
\tightlist
\item
  \texttt{D\allowbreak{}F\allowbreak{}-\allowbreak{}0\allowbreak{}2\allowbreak{}3} should publish repo/package/release guidance into the visible shell
\item
  \texttt{D\allowbreak{}F\allowbreak{}-\allowbreak{}0\allowbreak{}2\allowbreak{}4} should publish philosophy/architecture/doctrine guidance into the visible shell
\end{itemize}
