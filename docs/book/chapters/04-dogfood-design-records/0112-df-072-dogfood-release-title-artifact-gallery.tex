\section{Framing}\label{record-112-framing}

Issue \#289 asks DOGFOOD to treat release title screens as first-class release artifacts instead of replacing the last title treatment in place. V7 shipped with \texttt{V\allowbreak{}7\allowbreak{} \allowbreak{}P\allowbreak{}r\allowbreak{}o\allowbreak{}d\allowbreak{}u\allowbreak{}c\allowbreak{}t\allowbreak{} \allowbreak{}T\allowbreak{}r\allowbreak{}u\allowbreak{}t\allowbreak{}h}; this follow-up adds a unique post-release treatment and keeps both artifacts visible through the Release page.

The design follows a Design Thinking loop: observe that release identity is valuable after the release lands, frame titles as reusable proof artifacts, prototype a gallery that keeps the newest treatment first, and prove every title through interactive, static, pipe, accessible, and localized output.

\section{Sponsor Human}\label{record-112-sponsor-human}

\begin{itemize}
\tightlist
\item
  A maintainer reviewing the release wants to see that v7 was published and that follow-up work is intentionally tracked instead of silently changing the historical title.
\item
  A DOGFOOD reader wants the Release page to open with the current title while still making the original release title discoverable.
\end{itemize}

\section{Sponsor Agent}\label{record-112-sponsor-agent}

\begin{itemize}
\tightlist
\item
  A review agent needs release-title metadata, lower-mode facts, and localization keys in one typed structure instead of scattered prose.
\end{itemize}

\section{Hill}\label{record-112-hill}

A DOGFOOD reader can open the Release guide and see a latest-first title gallery whose current item is a unique \texttt{V\allowbreak{}7\allowbreak{} \allowbreak{}L\allowbreak{}a\allowbreak{}u\allowbreak{}n\allowbreak{}c\allowbreak{}h\allowbreak{} \allowbreak{}W\allowbreak{}a\allowbreak{}k\allowbreak{}e} post-release title screen, while the original \texttt{V\allowbreak{}7\allowbreak{} \allowbreak{}P\allowbreak{}r\allowbreak{}o\allowbreak{}d\allowbreak{}u\allowbreak{}c\allowbreak{}t\allowbreak{} \allowbreak{}T\allowbreak{}r\allowbreak{}u\allowbreak{}t\allowbreak{}h} artifact remains available with its own lower-mode facts.

\section{Playback Questions}\label{record-112-playback-questions}

\begin{itemize}
\tightlist
\item
  Does the Release guide open with the current title treatment?
\item

\end{itemize}

\section{Lower Modes}\label{record-112-lower-modes}

Static mode keeps the title useful without border art:

\begin{CodeBlock}
Bijou DOGFOOD release title. Release V7 Launch Wake.
Proof lanes: published release, follow-up patch, title gallery, green main CI.
Motif: Wake lines, not fireworks: proof remains visible after ship.
\end{CodeBlock}

Pipe mode exposes facts for agents:

\begin{CodeBlock}
release_id  v7-launch
release_title   V7 Launch Wake
release_motif   Wake lines, not fireworks: proof remains visible after ship.
proof_lane  published release
proof_lane  follow-up patch
proof_lane  title gallery
proof_lane  green main CI
navigation_available    true
\end{CodeBlock}

Accessible mode names the same proof without depending on layout:

\begin{CodeBlock}
DOGFOOD title screen for V7 Launch Wake.
Current release proof lanes are published release, follow-up patch,
title gallery, green main CI.
Visual motif: Wake lines, not fireworks: proof remains visible after ship.
Navigation remains available after the title.
\end{CodeBlock}

\section{Runtime And API Contract}\label{record-112-runtime-and-api-contract}

\begin{itemize}
\tightlist
\item
  Release-title data is represented by typed \texttt{D\allowbreak{}o\allowbreak{}g\allowbreak{}f\allowbreak{}o\allowbreak{}o\allowbreak{}d\allowbreak{}R\allowbreak{}e\allowbreak{}l\allowbreak{}e\allowbreak{}a\allowbreak{}s\allowbreak{}e\allowbreak{}T\allowbreak{}i\allowbreak{}t\allowbreak{}l\allowbreak{}e} records.
\item
  \texttt{D\allowbreak{}O\allowbreak{}G\allowbreak{}F\allowbreak{}O\allowbreak{}O\allowbreak{}D\allowbreak{}\_\allowbreak{}R\allowbreak{}E\allowbreak{}L\allowbreak{}E\allowbreak{}A\allowbreak{}S\allowbreak{}E\allowbreak{}\_\allowbreak{}T\allowbreak{}I\allowbreak{}T\allowbreak{}L\allowbreak{}E\allowbreak{}\_\allowbreak{}G\allowbreak{}A\allowbreak{}L\allowbreak{}L\allowbreak{}E\allowbreak{}R\allowbreak{}Y} is latest-first.
\item
  \texttt{C\allowbreak{}U\allowbreak{}R\allowbreak{}R\allowbreak{}E\allowbreak{}N\allowbreak{}T\allowbreak{}\_\allowbreak{}D\allowbreak{}O\allowbreak{}G\allowbreak{}F\allowbreak{}O\allowbreak{}O\allowbreak{}D\allowbreak{}\_\allowbreak{}R\allowbreak{}E\allowbreak{}L\allowbreak{}E\allowbreak{}A\allowbreak{}S\allowbreak{}E\allowbreak{}\_\allowbreak{}T\allowbreak{}I\allowbreak{}T\allowbreak{}L\allowbreak{}E} points at the current title treatment.
\item
  Rendering defaults to the current title but accepts an explicit historical title for stable artifact playback.
\item
  DOGFOOD Release guides are generated from the gallery, not manually copied per title.
\end{itemize}

\section{Linked Invariants}\label{record-112-linked-invariants}

\begin{itemize}
\tightlist
\item
  New release-title UI strings must be represented in every supported DOGFOOD locale.
\item
  Lower modes must expose the same release id, title, motif, proof lanes, and navigation availability as the interactive title.
\item
  Release-title rendering must stay deterministic and width-bounded from its explicit inputs.
\end{itemize}

\section{Accessibility, Localization, And Inspectability}\label{record-112-accessibility-localization-and-inspectability}

\begin{itemize}
\tightlist
\item
  Every visible string added in this cycle has \texttt{e\allowbreak{}n}, \texttt{d\allowbreak{}e}, \texttt{e\allowbreak{}s}, and \texttt{f\allowbreak{}r} source rows and regenerated runtime catalogs.
\item
  The title's motif is exposed as text in interactive, static, pipe, and accessible modes.
\item
  The renderer remains deterministic and does not query GitHub, wall-clock time, or release APIs.
\item
  Interactive output must stay inside the requested width for compact terminals.
\end{itemize}
