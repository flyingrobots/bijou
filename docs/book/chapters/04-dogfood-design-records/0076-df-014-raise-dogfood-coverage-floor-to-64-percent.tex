\section{Why this cycle exists}\label{record-076-why-this-cycle-exists}

DF-013 proved that DOGFOOD could teach shell help and the notification system honestly.

The next promised step was to keep the ratchet moving by documenting the shell frame itself instead of only shell-adjacent surfaces:

\begin{itemize}
\tightlist
\item
  \texttt{c\allowbreak{}r\allowbreak{}e\allowbreak{}a\allowbreak{}t\allowbreak{}e\allowbreak{}F\allowbreak{}r\allowbreak{}a\allowbreak{}m\allowbreak{}e\allowbreak{}d\allowbreak{}A\allowbreak{}p\allowbreak{}p\allowbreak{}(\allowbreak{})} / \texttt{s\allowbreak{}t\allowbreak{}a\allowbreak{}t\allowbreak{}u\allowbreak{}s\allowbreak{}B\allowbreak{}a\allowbreak{}r\allowbreak{}S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}(\allowbreak{})} / \texttt{c\allowbreak{}o\allowbreak{}m\allowbreak{}m\allowbreak{}a\allowbreak{}n\allowbreak{}d\allowbreak{}P\allowbreak{}a\allowbreak{}l\allowbreak{}e\allowbreak{}t\allowbreak{}t\allowbreak{}e\allowbreak{}S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}(\allowbreak{})} for \textbf{App shell}
\item
  \texttt{s\allowbreak{}p\allowbreak{}l\allowbreak{}i\allowbreak{}t\allowbreak{}P\allowbreak{}a\allowbreak{}n\allowbreak{}e\allowbreak{}S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}(\allowbreak{})} / \texttt{g\allowbreak{}r\allowbreak{}i\allowbreak{}d\allowbreak{}S\allowbreak{}u\allowbreak{}r\allowbreak{}f\allowbreak{}a\allowbreak{}c\allowbreak{}e\allowbreak{}(\allowbreak{})} for \textbf{Workspace layout}
\end{itemize}

\section{Scope of this cycle}\label{record-076-scope-of-this-cycle}

This cycle intentionally covers:

\begin{itemize}
\tightlist
\item
  adding the app-shell family to DOGFOOD
\item
  adding the workspace-layout family to DOGFOOD
\item
  moving the field guide from \texttt{2\allowbreak{}3\allowbreak{}/\allowbreak{}3\allowbreak{}5} families to at least \texttt{2\allowbreak{}5\allowbreak{}/\allowbreak{}3\allowbreak{}5}
\item
  clearing the declared \texttt{6\allowbreak{}4\allowbreak{}\%} floor
\end{itemize}

It does \textbf{not} include:

\begin{itemize}
\tightlist
\item
  progressive disclosure or path/progress teaching
\item
  data-browsing families
\item
  final DOGFOOD completion
\end{itemize}

\section{Human users}\label{record-076-human-users}

\subsection{Primary human user}\label{record-076-primary-human-user}

A builder deciding whether Bijou can teach whole application framing and spatial composition, not only individual widgets.

\subsection{Human hill}\label{record-076-human-hill}

A user can open DOGFOOD and understand when to use shell chrome versus page content, and when split/grid layout is honest instead of decorative geometry.

\section{Agent users}\label{record-076-agent-users}

\subsection{Primary agent user}\label{record-076-primary-agent-user}

An agent continuing the coverage ratchet without padding the numerator with cosmetic stories.

\subsection{Agent hill}\label{record-076-agent-hill}

An agent can only satisfy DF-014 by adding real app-shell and workspace-layout stories and by proving the floor moved because those families are now actually present.
